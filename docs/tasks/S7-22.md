## Сделать
- `urfin_view::md` (§3.10): разбор pulldown-cmark с GFM (таблицы, задачи, зачёркнутый, сноски) через `into_offset_iter` → `MdDoc`: блоки со смещениями в исходнике, строчные отрезки, проекция текста с картой «проекция → блок → исходник», ссылки и картинки. Front matter — блок `yaml`.
- HTML-набор (§3.10, решение §13, вопрос 3): свой токенайзер тегов по событиям `Html` / `InlineHtml` (без html5ever) → `<br>` (перенос, `\n` в проекции), `<img src width height alt>` (картинка с размером, только локальные; сетевые — причина для плашки), `<details>` / `<summary>` (`BlockKind::Details { open }` + `Summary`, вложенный Markdown — дети с `depth + 1`; без `<summary>` — подпись по умолчанию в UI), `align="center|right"` у `<p>` / `<div>` (`Block::align`), `<kbd>`, `<sub>`, `<sup>` (стили run). Текст внутри HTML-блока — без разбора Markdown. Прочие, непарные и битые теги — `RawHtml` / run `code`; атрибуты кроме перечисленных игнорируются.
- HTML-комментарии `<!-- … -->` скрыты, как на GitHub (дополнение владельца 2026-10-30; в S7 §3.10 строку вносит полоса docs).
- Пути картинок и ссылок: относительно `.md`, `/` — от корня git-репозитория или тома, `%20`; только `Caps::LOCAL`. Сеть, нет файла, неподдержанный формат, больше `md_image_max_mb` → причина для плашки. `#якорь` → slug как у GitHub.
- Разбор на Interactive lane с отменой токеном; у файла > 1 МБ первые 256 КиБ отдаются первыми, остальное дописывается.
- Режим: `viewer.mode markup` у Markdown при `viewer.markdown = "document"` → документ; файл > 16 МБ — режим недоступен. Ключи `viewer.markdown`, `viewer.md_font_size`, `viewer.md_image_max_mb`.
- Позиция: смещение верхнего блока ↔ строка Текста, запись в историю. Alt+F8 и Hex-поиск в документе → Текст на той же позиции.
- F7 в документе (решение §13, вопрос 1): движок S7-09 по проекции (`ByteSource::Owned`), совпадение → (блок, отрезок); совпадение в свёрнутом `<details>` помечает блок к раскрытию; Hex недоступен.
- Бенч `md.rs`: разбор 1 и 16 МБ.

## Приёмка
- корпус CommonMark + GFM и README с HTML (`<p align="center"><img width>`, `<details>`, `<br>`, `<kbd>`, `<sub>` / `<sup>`, неизвестный тег, `<script>` — текстом): блоки и смещения верны; proptest — `src` блоков по порядку и внутри файла, проекция ↔ исходник обратимы на границах блоков;
- разбор 1 МБ ≤ 20 мс, 16 МБ ≤ 300 мс (release, warm), память ≤ 3× текста;
- сетевые ссылки на картинки не порождают ни одного обращения к сети (тест разрешения путей).

## Сделано
- `urfin_view::md`: `mod.rs` — модель (`MdDoc`, `Block`, `BlockKind`, `Run`, `RunStyle`, `ImageRef`/`ImageState`/`ImageIssue`, `LinkRef`/`LinkTarget`, `Anchor`, slug как у GitHub); `build.rs` — разбор pulldown-cmark (GFM + front matter `yaml`) через `into_offset_iter`; `html.rs` — токенайзер тегов; `resolve.rs` — пути; `job.rs` — задача `view.md` на Interactive lane, `MdMsg`, `ProjSource`, декодирование с картой в байты источника (BOM, 1251, UTF-16); `view.rs` — режим документа у `ViewerDoc`.
- Блоки — прямой обход: `src` (байты исходника), `text` (своя часть проекции), `runs` (отрезки без пропусков, у каждого — начало в исходнике; склейка — только при сплошном исходнике), `parent`, `depth`, `end` (за потомками), `align`. Пункт списка держит текст первого абзаца, дети — `depth + 1`; таблица → строки `Row` (ячейки через `\t`); абзац из одной картинки → `Image`. Проекция — блоки через `\n`, `<br>` и жёсткий перенос — `\n`. Карта: `block_at_src`, `block_at_text`, `text_to_src`, `src_to_text`.
- HTML-набор: `<br>`, `<img src width height alt>`, `<details [open]>` / `<summary>` (контейнер, закрывается `</details>` или концом родителя), `align` у `<p>` / `<div>` (действует и на Markdown внутри), `<kbd>`, `<sub>`, `<sup>`; комментарии скрыты; HTML-блок без тегов набора — `RawHtml`; прочие и непарные теги — run `CODE | RAW`.
- Пути: относительно `.md`, `/` — корень git (папка с `.git`) или тома, диск Windows — как есть, `%XX`, `file:///`; сеть (`http(s)`, `ftp`, `//`, UNC, `file://host`) — `Network` без обращений к ФС; `NotFound`, `Unsupported` (PNG, JPEG, GIF, WebP, BMP, SVG; `data:image/*` — да), `TooLarge`, `NotLocal` (архив, SFTP). Ссылки: якорь → блок, сноска → определение, `http(s)`/`mailto` — `External`, путь — `markdown` (открыть во вьювере) или нет (reveal), прочие схемы — `Other`.
- Разбор с отменой токеном (смена кодировки, закрытие); файл > 1 МБ — сначала первые 256 КиБ по пустой строке (`complete = false`), затем весь.
- Режим: «Разметка» у Markdown при `viewer.markdown = "document"` и ≤ 16 МБ — документ (`ViewerDoc::md_mode`, `md: Option<MdState>`); `"source"` — исходник. Ключи `viewer.markdown`, `viewer.md_font_size` (0 = 14), `viewer.md_image_max_mb` (20). `lang`: `.mdown`, `.mkd`.
- Позиция: `top` = начало верхнего блока; документ → Текст — со строки начала блока, обратно — блок по `top`; история пишет `top` и долю блока (`ViewMemo::frac`). Прокрутка `viewer.scroll` — блоками (свёрнутые `<details>` пропускаются). Alt+F8 и Hex-поиск → Текст на той же позиции. F7 — движок S7-09 по проекции (`SearchState::proj`), совпадение → `MdState::hit`/`sel`/`reveal`, свёрнутый `<details>` над ним раскрывается; счёт — по проекции. События UI: `InboxMsg::MdTop`, `MdToggle`, `MdSelect`.
- Тесты: модуль (токенайзер, сущности, slug, пути со счётчиком обращений к ФС, декодирование 1251/BOM, отмена, начало большого файла), корпус README с HTML и CommonMark + GFM — снимки блоков и смещений, proptest 256 случаев — порядок и вложенность `src`, покрытие текста отрезками, обратимость на границах блоков; через core — открытие, Текст ↔ документ, Alt+F8, Hex, F7 с `<details>`, inbox, история, файл > 1 МБ.
- Замер (release, warm, `tests/md_parse.rs`, `#[ignore]`): корпус README + GFM — 1 МБ 7,6 мс, 16 МБ 134 мс, память 2,47× текста, первый экран 16 МБ — 13,6 мс. Плотный худший случай (стиль каждые ~20 байт): 1 МБ 15 мс, 16 МБ 263 мс, память 4,2×.
