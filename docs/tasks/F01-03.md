## Сделать
- job `du` (dedicated, DeviceGate), `DuTree` на атомиках, `DONE`/«≥ X», тик 100 мс, крупные файлы, `TypeAgg`, отмена, заморозка в `DuSnapshot`.

## Приёмка
- 1M файлов (`gen_tree`): итог = эталон; отмена ≤ 100 мс; потоков после job 0;
- пик памяти ≤ 40 МБ (count-alloc);
- первый тик < 100 мс.

## Сделано (2026-10-30)
- `du::scan`: `scan()` (блокирующий, `walk_with` + листер по ФС) и `start()` — задача `du` на `spawn_dedicated`, события `ScanEvent::{Progress(Arc<DuTree>), Done(Arc<DuSnapshot>)}` в UI-поток; пауза/отмена через `JobHandle`.
- `DuTree`: сегменты по 4096 узлов на атомиках, `pending` → `DONE` вверх по цепочке, агрегаты одной прибавкой на каталог, `deny`, `LINK_SKIPPED`, крупные файлы (`top_files` во время скана), `TypeAgg`, заморозка `freeze()` в `DuSnapshot` (флаги `PARTIAL`, `APPROX`).
- Тик: первый через 30 мс, дальше 100 мс; `du.first_rows` в tracing.
- Тесты: `tests/du_scan.rs` (через core: итог = эталон, тики, `job.cancel` ≤ 100 мс → снимок `PARTIAL`, задача `Cancelled`); `tests/du_heavy.rs` (`#[ignore]`, release, считающий аллокатор); criterion `benches/du_scan.rs` (`du_scan_100k`, датасет `walk-100k`).
- Прогон `du_heavy` (ноутбук владельца, release, тёплый кэш, датасет `bench-scan-1m`: 985 059 файлов, 11 008 каталогов): итог = `dir /s /a` (75 979 482 Б); скан 282 мс (`dir /s /a` — 10,0 с); первый тик 33 мс; пик кучи 2,1 МиБ; отмена 1,2 мс; потоков до/после 5/5.

## Осталось
- Очередь устройства: скан ждёт слот в общей `DeviceGate` (core, решение 2026-10-30); `ops.priority`/`ops.run_now` для задачи `du` не действуют.
- Заголовок задачи — Fluent-ключ (EN+RU) в urfin-i18n (чужая полоса); `start()` берёт `title` у вызывающего (F01-05).
- `Patch` листинга по тикам и «≥ X» в UI — F01-05 (`DuVfs`).
- Замер C: на стенде (холодный/тёплый) в `docs/perf/runs/`; `du_scan_100k` не гонялся.
- Потоки `[du] threads = 0`: пока `volume::walk_threads` (SSD 4, HDD/сеть 1) — NVMe 8 после определения носителя (S5-02).
- Крупные файлы: общий список под мьютексом (сброс раз на каталог) вместо поточных min-heap — по памяти то же, топ — `top_files(n)`.
