## Сделать
- §3.3 «Live»: наблюдатель поддерева на время жизни вкладки, debounce, перелистывание затронутых, overflow → `CHANGED`.

## Приёмка
- создать/удалить 1 ГБ в поддереве → размеры предков обновились ≤ 1 с;
- простой: 0% CPU, после закрытия вкладки наблюдатель снят;
- 100k событий подряд не блокируют UI (кадр ≤ 2 мс).

## Сделано (2026-11-02, PR x/du-live)
- sys: `win_watch::watch_tree` — тот же `ReadDirectoryChanges(Ex)W` на порту завершения, `bWatchSubtree`; имена событий — пути от корня.
- vfs `du::fresh`: `Live` — поток `du-live` на анализ с открытой вкладкой (ждёт канал без таймаута — 0% CPU); пачка событий: debounce 250 мс, не дольше 700 мс от первого; события → ближайший каталог снимка; каталог перелистывается тем же листером, что скан (`Relister`: размер на диске, `FileId`), новые подкаталоги досчитываются сканом и прививаются; переполнение буфера / потеря корня → «●» (`CHANGED`) у всего снимка.
- Правка снимка (`dvfs_live`): свои файлы каталога = узел минус подкаталоги, разница — в каталог и предков; исчезнувшие подкаталоги вычитаются, новые прививаются (с «Сборками и кэшами»); крупные файлы — заново (группы дубликатов сбрасываются); `mtime`, «●» снимается; перелистывание идемпотентно и согласовано с вычитанием по перечитыванию (F01-06).
- handler: наблюдение у посчитанных анализов с вкладками; пересчёт или закрытие последней вкладки — снято, снимок — в кэш сразу; фикстура `--screens` (`DuRegistry::fix`) — без наблюдения.
- Тесты: `dvfs_live_tests` (добавление/удаление, прививка, исчезнувший каталог, повтор, «●», типы), `tests/du_live.rs` (Windows: файл в глубине → итог ≈ 0,26 с, новое поддерево, удаление, 3000+1000 событий, снятие наблюдения). Ручная проверка — `docs/manual-tests/F01-10.md`.

## Осталось
- Суммы по типам мелких файлов при перелистывании — приближённые (тип по именам из событий / пропорционально листингу); жёсткие ссылки при перелистывании не дедуплицируются — точно только полным сканом.
- Кадр ≤ 2 мс при 100k событий и 0% CPU в простое — на стенде (`win-manual`); работа вне UI-потока, в UI — одно сообщение на пачку.
