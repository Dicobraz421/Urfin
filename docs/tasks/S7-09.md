## Сделать
- §3.6: `compile`/`find` — memmem, meta regex по байтам, `hir_bytes::translate`, transcode-путь, hex с `??`; чанки с перекрытием, назад, перенос, прогресс, отмена, счётчик с лимитом, метки совпадений.

## Приёмка
- чанковый результат = результат по целому буферу (proptest);
- HIR-перевод 1251/866/KOI8 = поиск по декодированной строке;
- отмена ≤ 50 мс; ошибка regex → `SearchError` с позицией; criterion `search.rs`.

## Сделано
- `search/mod.rs`: `Pattern`, `SearchError` (позиция символа для regex и hex, пустое совпадение запрещено), `compile` → `Matcher` (`find`, `prepare` → `find_at`/`rfind`, `max_len`): UTF-8 литерал — memmem (`Finder`/`FinderRev`), без регистра и regex — `meta` по байтам; однобайтовые — `hir_bytes::translate`; UTF-16 и многобайтовые — перекодирование окна; hex — memmem, с `??` — байтовый HIR. «Слово» — проверка соседних символов по кодировке (кириллица в 1251/866/KOI8 — тоже слово).
- `hir_bytes.rs`: литералы и Unicode-классы → байтовые классы по таблице 256; непредставимые — пустой класс; границы слов — ASCII (ограничение в доке модуля).
- `transcode.rs`: UTF-16 — свой цикл и опорные точки через 256 байт; многобайтовые — `CharDecoder` и отрезки одинаковых символов; карта UTF-8 ↔ источник.
- `scan.rs`: окна 4 МБ с перекрытием `min(max_len, 64 КБ)` и контекстом 8 байт по краям, вперёд, назад (последнее совпадение до точки старта), перенос через конец, прогресс в атомике, отмена между окнами, счёт без перекрытий до предела (+ «есть ещё»); `Hay` — срез, mmap или `read_at` в буфер.
- `job.rs`: `SearchState` (прогресс, итог, перенос, счёт, метки, номер «3 из 120»), задачи `spawn_cpu` поиска и счёта, `SearchMsg`; новый образец отменяет поиск и счёт, смена кодировки — перекомпиляция.
- Команды: `viewer.search text= kind= case= word= back=` (без `text` — `UiEvent::Ext` для строки поиска), `search_next`/`search_prev`, `search_cancel`; совпадение → `sel`, `top` — к началу его строки, `reveal`.
- Тесты: proptest — окна любого размера = целый буфер (вперёд, назад, перенос, счёт; UTF-8, 1251, 866, KOI8-R, UTF-16 LE/BE; текст и regex, «Слово»); HIR-перевод 1251/866/KOI8 = поиск по декодированной строке; hex с `??`; ошибка regex с позицией; отмена; предел счёта.
- Замер (release, 512 МиБ в памяти, `tests/heavy.rs`): литерал 17,2 ГБ/с, без регистра 8,3, regex 17,2, 1251-regex 7,5, UTF-16 1,09, hex 20,1 ГБ/с; отмена — 0,1–0,3 мс (≤ 50 мс). Criterion — `benches/search.rs`.

## Осталось
- `benches/search.rs` запускается criterion только после записи `[[bench]] name = "search" harness = false` в `crates/view/Cargo.toml` (полоса deps).
- Строка поиска, полоса прогресса, подсветка совпадений на экране и риски меток — S7-10 / S7-07.
- Длина файла фиксируется на старте поиска (растущий Spool/follow — S7-12); совпадение regex длиннее 64 КБ обрезается перекрытием окон.
