## Приёмка
- фикстуры `scoop export` и `status`/`search` JSON (1 и N элементов — `ConvertTo-Json` отдаёт объект вместо массива) разбираются;
- мусор Write-Host до маркера игнорируется;
- работает с pwsh 7 и powershell 5.1 на стенде.

## Заметка
- Полосы `pkg` ещё нет в lanes.toml — добавить PR класса B.

## Сделано
- `scoop.rs`: скрипты `powershell -NoProfile -NonInteractive -ExecutionPolicy Bypass -EncodedCommand` (UTF-16LE base64; Bypass — как в шиме самого scoop): вывод в UTF-8, `Write-Host` заглушён (`6>$null`), данные — после маркера `<<URFIN>> <секция>`; всё до маркера (вывод `scoop update`, строки в конвейере) отбрасывается, маркер не в начале строки — не маркер. Значения в скрипте — `ps_quote` (одинарные кавычки, в т. ч. типографские, удваиваются).
- Установленные — `scoop export` (JSON `apps[]`, старый текст `name (v:x) [bucket]`); обновления — `scoop update` по `scoop_update_buckets`, затем `export` и `status --local` в одном скрипте (бакет — из export, «Held package» — пин); поиск — `scoop search` JSON. `ConvertTo-Json -InputObject @(…)` + разбор принимает объект, массив и обёртку 5.1 `{value, Count}`; не-объекты пропускаются.
- Id — `bucket/name` (бакет-URL/путь → только имя); `action_plan`: `install <bucket/name>`, `update|uninstall <name>`, вывод `*>&1` в поток, код — `$LASTEXITCODE`, без UAC.
- `ScoopAdapter` (Windows); PowerShell — переданный приложением (кэш S6), иначе `detect::find_powershell` (pwsh из PATH, иначе 5.1).
- Тесты: фикстуры `fixtures/scoop` (export JSON/текст, status/search 1 и N, сырой вывод с мусором) — insta; подставной `scoop.ps1` под всеми найденными PowerShell — сквозной прогон адаптера и действий; `#[ignore]` стенд только на чтение — прошёл на настоящем scoop 0.5.3 под 5.1.

## Осталось
- pwsh 7 на этой машине не установлен: сквозной тест на подставке и стенд прогнаны только под 5.1 (тест сам берёт pwsh, если он есть).
- Фикстуры `status`/`search` собраны по формату scoop вручную; настоящий вывод на стенде разобрался без ошибок.
