## Сделать
- Первым — проверка на стенде: `ReplaceFileW` при открытом нами handle (share `READ | DELETE`). Если отказ — запасной путь ADR-0023 §8 п. 4 (закрыть handle → `ReplaceFileW` с `lpBackupFileName` → открыть резервную копию тем же share, `FileDispositionInfo` на удаление); итог — строкой в ADR.
- Писатель (`edit/write.rs`): снимок → куски (исходник — `read_at` блоками 4 МиБ, не через `PageCache`; `Add` — из памяти/временного файла) → `.<имя>.urfin~`; та же кодировка — копия байт, другая — `Encoder` потоком + BOM, непредставимые — `EdAsk::Unmappable`. Память ≤ 8 МиБ буферов. Свободное место ≥ размера — иначе вопрос с цифрами.
- Дисковый слой S7-17 без изменений (`ReplaceFileW` → `MoveFileExW`, атрибуты, nlink, symlink); «на месте» — временный файл в `%TEMP%`, затем запись в исходный (снять свой запрет, записать, открыть заново), группы журнала на старых байтах — отбросить.
- После записи: новый файл открывается с запретом записи; корень не менялся — документ = один кусок нового файла, `saved_at`; правка во время записи разрешена (снимок). Вход — снимок дерева вместо `Snapshot { Rope }` (прежний путь — до S7-34).

## Приёмка
- сохранение без правок и с правками = собранный буфер (все кодировки V5, BOM, lossy);
- 1 ГБ с одной правкой ≤ 3 с NVMe, память + ≤ 8 МиБ; обрыв после temp (fault-injection) не портит исходник; ACL, атрибуты, hardlink — как S7-17;
- после сохранения отмена работает (старые куски читаются через handle старой версии), закрытие документа освобождает место старой версии.

## Заметка
- Класс B: `crates/view/src/sys/` (CODEOWNERS).

## Сделано (2026-11-01, x/view-22)
- Проверка на стенде (первой): `ReplaceFileW` без резервной копии при нашем handle (`GENERIC_READ`, share `READ | DELETE`) **проходит** — имя занимает новый файл, прежний handle читает старые байты; `MoveFileExW` при нашем handle — `ERROR_ACCESS_DENIED`. Handle не закрывается; запасной путь — `ReplaceFileW` с `lpBackupFileName` (`sys::replace_file_backup`) и сразу `DeleteFileW` копии (наш share `DELETE` — удаление при закрытии handle), затем `MoveFileExW`. Итог — строкой в ADR-0023 §8 п. 4; тест `replace_under_own_lock` (Windows).
- `edit/save.rs`: вход — `Body::Rope` (прежний путь, до S7-34) или `Body::Snap` (снимок движка); `save_full` → `Saved { outcome, reopened }`; `Outcome::NoSpace { need, free }`.
- `edit/stream.rs` (запись снимка): BOM + куски блоками 4 МБ (`write::blocks`, `read_at` источников); та же кодировка — байты как есть, другая — `Recode` потоком; непредставимые считаются по ходу записи временного файла, при вопросе цель не тронута и временного файла нет. Свободное место (`sys::free_space`, `GetDiskFreeSpaceExW`) ≥ размера — иначе вопрос движка `Ask::NoSpace` «Нет места: нужно X, свободно Y: [Сохранить всё равно] [Отмена]». Жёсткие ссылки / нет прав на каталог — временный файл во `%TEMP%\Urfin`, затем копия на место. Дисковый слой S7-17 (атрибуты, «только чтение», symlink, fault-injection) — общий.
- Записанный файл открывается заново (`Reopened`): ≤ 16 МБ — байты записи в памяти (без второго чтения), больше — `open_locked` (запрет записи другим); индекс строк — по ходу записи (готов, без фонового `Indexer`). Пик памяти записи большого файла — блок 4 МБ (копия в памяти — только если файл заведомо ≤ 16 МБ).
- Документ (`EditorDoc::on_engine_saved`): журнал помнит сохранённое состояние снимка (`Journal::checkpoint` / `mark_saved_at`: правка после снимка — новая группа, ● остаётся); текст не правили во время записи (`TextDoc::edits`) и кодировка та же — `TextDoc::rebase`: исходник — новый файл (один кусок `Original`), прежний — источник отмены `Rewrite(n)` (`Journal::rename_src`, `Tree::map_src`; его handle держит старые байты, место освобождается при закрытии документа), кэш исходника — `replace_source` (ответы прежних страниц не кладутся), индекс и счёт строк прежнего файла останавливаются. Правка во время записи разрешена (`EditorDoc::editable`: `Ready | Saving`).
- `request_snapshot` у документа на движке — снимок здесь же и запись (UI не нужен); полоса изменений (`Diff`) ему не нужна.
- Тесты (`stream_tests.rs`): без правок = те же байты, с правками = BOM + собранные куски (13 кодировок V5 × 4 EOL), индекс нового файла; lossy; перекодирование + BOM, непредставимые → вопрос (цель цела, временного нет) → «?»; обрыв после временного; жёсткая ссылка (на месте) и атрибуты; через core — документ на новом файле, отмена/повтор после сохранения и ●; правка во время записи; файл > 16 МБ — снова под запретом записи, отмена читает старую версию через свой handle, резервных копий нет. `tests/heavy.rs`: `engine_save_1gb_one_edit` (`#[ignore]`, release).
- Замеры (стенд, release, 2026-11-01; диск C: заполнен на 96–99 %, рядом шли чужие сборки): 1 ГБ с одной правкой — **31,4 с** при записи диска ≈ 50 МБ/с (тот же стенд: запись 1 ГБ с `Flush(true)` — 19,9 с, копия 1 ГБ — 11,3 с, чтение — 0,7 с); отмена — **31 мс** (≤ 100 мс), исходник цел, временный убран. Бюджет «≤ 3 с NVMe» на этом диске не проверить — гейт S7-36 (`URFIN_PERF_GATE=1`) на стенде со свободным местом. Открытие 10 ГБ (S7-29) — **0,86 мс** (≤ 50 мс).

## Осталось
- «На месте» (жёсткие ссылки, нет прав на каталог) для документа > 16 МБ под нашим запретом записи — ошибка «Сохранить как» (свой handle не даёт писать в файл); нужен переход документа на временную копию до записи — отдельной карточкой, если понадобится.
- Прежние версии в слотах `Rewrite(n)` держатся до закрытия документа, даже когда журнал на них уже не ссылается (≤ 16 МБ — в памяти): освобождать слот при обрезке журнала.
- Замер памяти записи (+ ≤ 8 МиБ) и 10 ГБ ≤ 30 с — S7-36 на стенде (по построению: буфер 4 МБ + выход `Recode`).
- Кадр UI во время записи — с экраном на движке (S7-33/S7-34).
