## Сделать
- раздел по `screen-settings-ssh`: вход, пароли, сеансы, запись, мультивыполнение, подсветка и правила-чипы;
- строки F-03 в «Политиках» (`password_cache`, `ssh.recording`, `ssh.multi_exec`) с источником TOML/GPO;

## Приёмка
- изменения применяются сразу;
- политики показаны замком с источником;
- выключение `password_cache` политикой удаляет записи `Urfin/ssh/*` при следующем запуске (если владелец выберет так, §7 №2).

## Сделано (2026-11-05, ветка x/ui-sshsettings)
- ui: раздел «SSH» (`gpui_shell/settings_ssh.rs`) по `screen-settings-ssh`: «Вход», «Пароли», «Сеансы», «Подсветка вывода»; в навигации «SSH» — пункт, «Подключения» — под ним. Переключатели — `ui.setting`, как в «Просмотре»/«Редакторе»; числа и команда пароля — поля `InputState`: значение уходит при выходе из поля (Enter, Tab, клик мимо), Esc возвращает прежнее, нечисло не пишется. «Добавить» — поле нового пути, `default_keys` пишется списком (`ui.setting list=`). «Открыть» у папки записей создаёт её задачей (`ui.settings open_dir=`). Статус — «N параметров заданы политикой».
- Менеджер и команда: пустой `password_cmd` — шаблон менеджера в поле; выбор менеджера снимает свою команду, своя команда — менеджер «Своя команда».
- Хвосты: чипы правил `[term.highlight]` (F03-10), флажок `multi_exec_confirm` (F03-11), сегменты `[ssh] recording` (F03-12).
- На лету: `urfin-net` на новый конфиг (`app.reload_config`, настройки, смена политики) берёт `[ssh]` — следующие подключения, каналы передачи, открытая группа; кэш паролей (`Vault::update`) видит флажок и политику сразу; смена импорта или агента перечитывает профили. Терминал берёт `[term.highlight]`; снапшот сетки и записи пересобирается и при смене правил (ключ кэша). Ctrl+Alt+H пишет `enabled` в конфиг: иначе перечитывание сбрасывало бы переключатель, а флажок настроек показывал бы не то.
- Агент для пояснения — по именам в `\.\pipe\` (`openssh-ssh-agent`, `pageant.*`), задачей `ssh.reload` при входе в раздел, к агенту не подключается.
- core: секция `[ssh]` (`SshCfg` и её типы) — в `urfin_core::net`, UI от `urfin-net` не зависит (решение «net-model-core»), `urfin_net` реэкспортирует; `NetModel.agent`. `PolicySet::setting` знает `ssh.password_cache`, `ssh.recording`, `ssh.multi_exec_confirm`: замка нет при `recording = "user"` и разрешающем `multi_exec`.
- Политика: замок и «Задано политикой организации · GPO/TOML», значение — действующее (`required` — «Всегда», `forbidden` — «Выкл»). Строки «Политик» уже были (F00-01), сверены с макетом.
- Приёмка «выключение `password_cache` удаляет записи при следующем запуске» — закрыта: решение [2026-11-01](../decisions/2026-11-01-password-cache-cleanup.md), `Vault::purge_if_forbidden` задачей на старте (F03-03/F03-05), тест `purge_deletes_only_urfin_entries`. На лету хранилище не трогается.
- Строки EN+RU. Сцена `screen-settings-ssh`; `screen-settings-ssh`, `screen-settings-policies` сверены с макетами.
- Тесты: unit полей (`settings_ssh`), политики (`ssh_settings_under_policy`), `Vault::update`, `NetState::apply`, агент по именам pipe, конфиг и Ctrl+Alt+H на настоящем `Core` (`highlight_follows_config_and_toggle_persists`).

## Осталось
- Ручные проверки — `docs/manual-tests/F03-14.md`.
- Чипа «Успех» (`rules.success`) на макете нет — только TOML; `recordings_dir`, `secret_ttl_min`, `transfer_channels` — только TOML (строк на макете нет), удаление ключа из `default_keys` — тоже.
- Keep-alive и переподключение действуют на следующие подключения: у идущего сеанса свой `ConnCfg`.
- Pageant старше 0.75 (только WM_COPYDATA) в пояснении не виден, вход через него работает.
- Список менеджера — клик по кругу, как у всех списков настроек (S7-01b, «мешочек» — общим компонентом).
