## Сделать
- формат §2.2, запись tmp+replace, чтение, проверка трейлера, LRU (`cache_keep`, `cache_max`), portable-путь.

## Приёмка
- roundtrip снимка 300k каталогов побайтно равен;
- загрузка ≤ 100 мс (release, стенд); битый файл → «нет кэша», файл удалён;
- лимиты LRU соблюдаются.

## Сделано (2026-11-01)
- `du::cache`: формат v1 §2.2 — заголовок (`URFDU\0`, `ver = 1`, `flags`, длина заголовка, длина meta, CRC32), meta (postcard: корень, `VolumeKey`, время, `usn`, `size_mode`, `track_min`, счётчики секций), `dirs`/`files` записями по 48 Б в раскладке `repr(C)`, арена имён, типы и `denied` (postcard), трейлер `xxh3_64` всего, что до него. Записи — поле за полем (без `unsafe`), чтение проверяет заголовок, версию, трейлер и ссылки (родитель раньше ребёнка, имена в арене, тип файла).
- `DuCache`: путь `state_dir\du\<serial:08x>-<xxh3 корня>.du` от `Paths` (portable — `<exe>\data\state\du\`); `load` — битый/чужой версии → `None` и файл удалён, отметка времени открытия (mtime) для LRU; `store` — `*.tmp` + rename, затем `trim`: свежие по времени открытия, пока ≤ `cache_keep` и ≤ `cache_max`; снимок, который один не влезает, не пишется (`CacheError::Limit`); брошенные `*.tmp` старше часа удаляются.
- `DuSnapshot`: `track_min` (порог списка `files`), `PartialEq`; `FsKind` — serde (индекс варианта: новые — в конец); `DuType::ALL`.
- Тесты: unit (roundtrip, порча любого байта и обрезка, чужая версия, битые ссылки при верном трейлере, ключ без регистра и хвостового `\`, portable-путь, LRU по числу и по объёму, битый файл удалён), proptest roundtrip; `tests/du_cache.rs` — 300k каталогов через файл побайтно равен; `load_budget` (`#[ignore]`, release); criterion `du_cache_load` (decode/load/encode 300k).
- Зависимости (`[workspace.dependencies]`, уже в графе через urfin-ops): postcard (meta, MIT/Apache-2.0), crc32fast (CRC заголовка, MIT/Apache-2.0), xxhash-rust `xxh3` (ключ и трейлер, BSL-1.0).

## Осталось
- Загрузка ≤ 100 мс — на стенде: `cargo nextest run -p urfin-vfs --release --run-ignored only -E 'test(load_budget)'` (Linux-песочница, release: 33 мс на 300k) и `du_cache_load` в `docs/perf/runs/`.
- Когда писать (после скана, после изменений не чаще 1/30 с, при закрытии вкладки; задача `Lane::Bulk`) и открытие из кэша — вызывающий: F01-05 (`du.open`), F01-10/11.
