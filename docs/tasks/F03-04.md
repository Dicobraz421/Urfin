## Приёмка
- `sftp://srv1/path` ↔ `Location` roundtrip;
- ввод `sftp://u@h:2222/x` находит профиль или создаёт разовый;
- первый батч листинга 10k файлов в `testsrv` — первый кадр ≤50 мс после ответа сервера;
- longname с юникодными именами владельцев разбирается, при мусоре — uid/gid;
- таб из сессии не подключается сам.

## Заметка

## Сделано (2026-11-01, ветка x/net-15)
- `uri.rs`: `SftpUri` ↔ `Location` (профиль — `Location.authority`, волна x/core-authority), показ `sftp://<профиль>/путь`, ввод `sftp://[user@]host[:port]/путь` (IPv6 в скобках), `resolve` — профиль по имени или `user/host/port`, иначе разовый `user@host[:port]` с источником `history` (`ProfileSource::History`, строки EN+RU).
- `sftp/`: `Session` — подсистема `sftp` на соединении пула, синхронные вызовы из потоков Runtime через рантайм крейта (UI-поток не ходит); `SftpFs: Vfs` — листинг (один `READDIR` = один батч), ссылки (`lstat` + `stat` цели батчем, цель — `stat(follow=false).link_target`), `stat`/`stat_entry`, `open_read` (`Read + Seek`), `space` (`statvfs@openssh.com`, иначе `Unsupported`), `watch` — без событий и без опроса; `open_write`, `mkdir`, `remove`, `rename`, `setstat`; `details` — права (`drwxr-xr-x`) и владелец из `longname` (юникод, `NT AUTHORITY\SYSTEM`; мусор — `uid/gid`); `rtt` — последний листинг, иначе keep-alive.
- Без канала профиля (`attach` не было) — `NotConnected`: таб из сессии сам не подключается.
- `rt.rs`: рантайм крейта с IO-драйвером (`enable_all`) — без него сокеты подключения не работали бы.
- `testsrv`: SFTP над каталогом (батчи по 100, `longname` с владельцем, ссылки из `Opts::links`, чтение/запись, операции).
- Тесты: unit (`uri`, `longname` — insta, права, записи), `tests/sftp.rs` — листинг и ссылки, владельцы, 10k файлов (первый батч ≤50 мс), чтение/запись/операции, «нет связи».

## Осталось

- Регистрация `SftpFs` в `VfsRegistry` app и `attach` после подключения (`sftp.open`), чип и пинг заголовка — F03-05 (UI подключения).
