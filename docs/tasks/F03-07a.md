## Сделано (2026-11-04, ветка x/vfs-write)
- vfs: методы записи `Vfs` — `open_write(p, from)` → `VfsWrite` (`finish`: `fsync` и закрытие), `mkdir`, `remove`, `rename(from, to, replace)`, `set_meta(mode, mtime)`, `link(at) -> Link`, `transfer_channels()`; по умолчанию `VfsError::NoWrite(scheme)`.
- ops: сторона `End::Remote(Arc<dyn Vfs>)` — backend из `Schemes` (виртуальные схемы и адреса в архиве — нет); `Caps::READ_ONLY` — отказ до задачи (F5/F6, F8, F7, Shift+F6); текст `ops-no-write` (EN+RU) и в отчёте задачи; `RemoteFs`, `RemoteWrite`, `Remotes`, `Link` из ops удалены.
- net: `SftpFs` реализует запись в `Vfs` (`SftpWriter: VfsWrite`, `profile_link`, `set_transfer_channels` из `[ssh] transfer_channels`); `SftpOps` удалён; `urfin-ops` — только dev-зависимость тестов `testsrv`.
- Тесты: `ops/tests/vfs_nowrite.rs` (копия в схему без записи — ошибка «запись не поддерживается» в отчёте; `READ_ONLY` — отказ без задачи), unit `remote::tests` (стороны из реестра, `NoWrite` всех методов), `sftp::tests::link_channels_and_seconds`.

## Осталось
- Локальная запись в ops — своя (быстрые пути); перевод на `Vfs` — отдельной волной, если понадобится.
- `VfsWriteTxn` для архивов — S8 (схема — CONTRACTS «VFS и операции»).
