## Сделать
- Строки документа: `line_of(off) -> LineGuess` и `offset_of_line(n)` по суммам дерева; внутри `Original` — метки `LineIndex` файла + досчёт ≤ 1024 строк (`count_seps`), внутри `Add` — `memchr`. Пока перед куском есть `Lf::Unknown` — `Approx` (средняя длина строки), как во вьювере.
- Фоновый `Indexer` вьювера идёт по файлу; по его продвижению куски `Original` получают `Lf::Known` (досчёт краёв разрезанных кусков), патч дерева — через `Msg`.
- Файл ≤ 16 МиБ — индекс на открытии (строки сразу точные).
- `LineChanges` по кускам, без diff текста: строка только из `Add` — добавлена, `Add` + `Original` — изменена, шов удаления — метка; для видимого диапазона — по запросу, счётчик шапки — фоном по списку кусков. Хэш-diff S7-15 (`diff.rs`) для нового пути не нужен.

## Приёмка
- proptest: `line_of`/`offset_of_line` = наивный счёт по модели на случайных правках (LF, CRLF, CR, UTF-16), в т. ч. до окончания индекса (`Approx` → `Exact` после);
- набрать и стереть в строке — строка снова не изменена; вставка строки — `added = 1`;
- 10 ГБ (V1): номер строки у курсора точный после индекса, до него — `Approx`, правка до окончания индекса не ломает счёт.

## Сделано (2026-11-01, x/view-21)
- `edit/lines.rs`: `TextDoc::line_of(off) -> LineGuess` и `offset_of_line(n) -> Option<LineGuess>` (`None` — строки точно нет) по суммам дерева (`Tree::prefix`, `Tree::find_line` — O(log n)); внутри `Original` — метка `LineIndex` файла + досчёт ≤ 1024 строк (`line_of_in`/`goto_line` по кэшу), внутри `Add` — `scan` по блоку; перед смещением есть `Lf::Unknown` или страниц нет — `Approx` (средняя длина строки по индексу файла). Номера строк исходника на краях кусков помнятся (`lines_at`, до 64 тыс.): досчёт края не ждёт страниц, ушедших из кэша.
- LF кусков `Original` — только по индексу (две метки и досчёт), не по всему куску; без индекса — `Unknown`. `TextDoc::new(.., index)`: куски, куда индекс дошёл, сразу `Known`; `index_now(src, sep)` — индекс файла ≤ 16 МБ на открытии.
- Продвижение индекса: `TextDoc::on_index(IndexDelta)`; фоновый `lf_patch(snap, index, cancel)` считает LF неизвестных кусков по снимку (исходник — где индекс дошёл, метки и досчёт краёв; правки — по байтам) и номера строк их краёв; `TextDoc::apply_lf` ставит `Known` кускам, которые с тех пор не менялись (`Tree::patch_lf`, `Tree::unknown` — обход только поддеревьев с неизвестными).
- `edit/changes.rs`: полоса изменений по кускам — строка только из правок (с переводом строки) — добавлена, правки + исходник — изменена, шов удаления (кусок исходника не продолжает предыдущий) в начале строки — `Deleted` перед ней, внутри — изменена; конец исходника не дошёл — `Deleted` в конце. `count(snap, orig, cancel)` — счётчик шапки фоном, O(кусков) (на кусок — LF из дерева и одна единица в конце); `visible(doc, range, orig)` — метки видимых строк по кэшам (номера от `range.start`). Хэш-diff (`diff.rs`) новому пути не нужен; типы `Change`/`LineChanges` — те же.
- «Enter» в конце строки (S7-26: вставка конца строки перед таким же сдвигается за него) — новая строка `Add`, полоса: `added = 1`, а не две изменённые.
- Тесты: proptest `line_of`/`offset_of_line` = счёт по модели на LF/CRLF/CR/UTF-16LE/BE после случайных правок; до окончания индекса — точные ответы верны, есть `Approx`, после дельты и патча — всё `Exact` (`approx_until_indexed`); > 1024 строк — метки; полоса: набрал и стёр — пусто, вставка строки (Home + строка, End + Enter + набор, пустая строка) — `added = 1`, удаление строки/первой/последней/всего, правка и склейка — изменена, новый файл, UTF-16; proptest — счётчик по снимку = метки целиком, метки диапазона строк = метки целиком в нём. Прогон с 1500 случаями — без падений.
- V1: файл генерируется на лету (`Synth`, страницы — только у курсора): `big_file_lines_64mb` в обычном прогоне, `big_file_lines_10gb` (`#[ignore]`, release): 10 ГБ — до индекса `Approx`, правки (удаление, вставка) до индекса, индекс до трети — всё ещё `Approx`, дочитывание (`Indexer::resume`) и патч — у курсора `Exact` = формуле; прогон 0,66 с (песочница, 4 потока).

## Осталось
- `Msg` патча (`IndexMsg` → `lf_patch` в фоне → `apply_lf`) и индекс на открытии — с документом на движке (S7-29); UI просит страницы `[метка, курсор)`, чтобы номер у курсора был точным (S7-33).
- Если кусков с `Unknown` между индексом и курсором много, `line_of` — оценка по средней длине (как вьювер).
