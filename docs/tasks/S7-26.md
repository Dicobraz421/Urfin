## Сделать
- `edit/piece/` (без I/O и без gpui): `Piece { src: Original | Add | Rewrite(n), start, len, lf: Known(u32) | Unknown }`; персистентное B+-дерево с `Arc`-узлами (лист ≤ 64 кусков, узел ≤ 16 детей), суммы — байты, известные LF, байты с `Unknown`; поиск куска по смещению и по строке — O(log n); `insert(at, pieces)`, `remove(range)` с копированием пути; слияние смежных непрерывных кусков одного источника; набор подряд дописывает последний `Add`.
- `TextSnap` (клон корня, `Send + Sync`), `TextView<'_>: ByteView` (chunk / chunk_before по кускам и кэшам страниц), `TextHay: Hay` (окно из кусков в буфер через `read_at`).
- Буфер `Add`: блоки 64 КиБ `Arc<[u8]>`, только дописывание; в памяти ≤ 16 МиБ, сверх — временный файл `%TEMP%\Urfin\edit-<pid>-<doc>.add` (`FILE_ATTRIBUTE_TEMPORARY`, `DELETE_ON_CLOSE`) как ещё один `ByteSource` для `PageCache`; кусок может ссылаться на диапазон, уже занятый другим куском (замена без групп).
- Счёт LF для `Add` при вставке — `index::scan` с `Sep` документа.

## Приёмка
- proptest: случайные вставки/удаления = модель `Vec<u8>` (содержимое, суммы байт и LF, `ByteView` и `Hay` дают те же байты, что модель), в т. ч. UTF-16 (`Sep` двухбайтовый);
- criterion: вставка и удаление в случайном месте при 1 млн кусков ≤ 50 мкс, клон снимка O(1);
- выгрузка `Add` за 16 МиБ: память в пределах, чтение выгруженного через кэш верно.

## Заметка
- Прежний путь (Rope, `EditorState`) не трогается — переключение в S7-34.

## Сделано (2026-11-01, x/view-21)
- `edit/piece/` (без gpui, без I/O на UI-потоке): `Piece { src, start, len, lf }` (`Src::{Original, Add, Rewrite(u16)}`, `Lf::{Known(u32), Unknown}`; 32 Б — у ADR «≈ 24 Б»), `split` (счёт LF меньшей части) и `join` (смежные непрерывные одного источника; `Add` — в пределах блока; длина ≤ `PIECE_MAX` = 2 ГБ, поэтому `Known(u32)` не переполняется).
- `Tree` (`tree.rs`): B+-дерево с `Arc`-узлами (лист ≤ 64, узел ≤ 16), суммы детей `Sums { bytes, lf, unknown, pieces }`; `find`/`prefix`/`iter_from` — O(log n); `insert`/`remove` — `Arc::make_mut` по пути (узлы, которые держит снимок, копируются); родитель чинит детей (`fix`: пустые прочь, переполненные делятся, полупустые сливаются, на шве листьев куски сливаются); `seam` сливает непрерывные куски из разных листьев; `patch_lf` — обход только поддеревьев с `unknown > 0` (для S7-27); `check` — инварианты в тестах.
- `AddBuf` (`add.rs`): блоки 64 КБ `Arc<Vec<u8>>` (хвост дописывается на месте, пока его не держит снимок), в памяти ≤ 16 МБ, сверх — префикс полных блоков в `%TEMP%\Urfin\edit-<pid>-<doc>.add` через `sys::open_spool` (`FILE_ATTRIBUTE_TEMPORARY`, `DELETE_ON_CLOSE`), `SpillSource: ByteSource` + свой `PageCache` 2 МБ; `AddSnap` читает выгруженное `read_at`.
- `TextDoc` (`text.rs`): дерево + источники + кэши (`Original` — 16 МБ, если не в памяти; `Rewrite(n)` — `push_rewrite`); `replace`/`insert`/`remove` → `Splice { at, removed, inserted }`, `splice` для журнала, `set_tree`/`set_sep` для `Op::Root`; LF кусков `Add` — `index::scan` по вставленным байтам; вставка конца строки перед таким же концом строки сдвигается за него (байты те же; «Enter в конце строки» — строка `Add`, полоса изменений точнее). `want(range)` — страницы источников под диапазон документа.
- `TextView: ByteView` (куски + кэши, `Missing` — в страницах документа), `TextSnap` (`Clone` O(1), `Send + Sync`, `read_at` по кускам), `TextHay: Hay` (окно в буфер через `read_at` источников).
- Тесты (`piece/tests.rs`): proptest — случайные вставки/удаления/замены = модель `Vec<u8>` на LF/CRLF/CR/UTF-16LE/BE (содержимое через `chunk` и `chunk_before`, суммы байт и LF, LF каждого куска, снимки по ходу не меняются, окна `TextHay`); глубокое дерево (≥ 2 уровней) и удаление всего; набор и стирание — снова один кусок; `Add` не пересекает блоки; `count` S7-09 по `TextHay` = по срезу; выгрузка `Add` за порог (память ≤ порога, `Missing` до подкачки, после — те же байты, снимок читает файл).
- Замер `bench_edit_1m` (`#[ignore]`, release, песочница Linux): 1 млн кусков (глубина 5) — вставка p50 1,8 мкс / p99 6,0 мкс, удаление p50 1,8 / p99 5,0 мкс (бюджет ≤ 50 мкс); клон снимка 50 нс и на 1 куске, и на 1 млн (O(1)).
