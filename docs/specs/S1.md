## 0. Ключевые решения

- **Решение:** состоянием владеет один объект `Core`, и живёт он в UI-потоке. Handlers работают как редьюсеры (`&mut AppState`), UI в кадре читает `&AppState` напрямую. Никаких `Arc<RwLock>`, снапшотов и копий.
  **Почему:** кадр обходится без блокировок и копирования, ввод применяется в том же кадре (латентность ≤1 кадр). Модель проще и тестируется детерминированно. Отдельный core-поток с ArcSwap-снапшотами дал бы +1 кадр задержки и копирование 100k строк.
- **Решение:** handlers не делают I/O и не блокируются. Всё тяжёлое уходит в `Runtime::spawn*`, результат возвращается сообщением `Msg`, которое применяется в `Core::pump`.
  **Почему:** только так UI-поток может владеть состоянием без риска фризов. Правило проверяется `tracing::warn!`, если handler выполняется дольше 1 мс (debug-сборки).
- **Решение:** большие данные хранятся как `Arc<Vec<Entry>>` и `Arc<Vec<u32>>` (order). Воркеры получают клон `Arc` (O(1)), чанк добавляется через `Arc::make_mut`.
  **Почему:** сортировка 100k на cpu-pool не требует копировать данные и не мешает UI. Копирование (~1 мс) случается только при гонке «чанк во время сортировки».
- **Решение:** команда на проводе одна: `Command { id: CommandId(строка), args }`. Handlers регистрируются по namespace (часть id до первой точки). Core разбирает свои команды в типизированный `CoreCmd`.
  **Почему:** keymap, палитра, cmdline и будущие макросы работают с одним сериализуемым видом. S4–S8 добавляют команды без правки enum в core. Сравнение строк при частоте ввода ничего не стоит.
- **Решение:** каналы воркеры→core ограничены (1024 `Msg`), блокирующий send с проверкой отмены каждые 15 мс. Прогресс идёт не событиями, а через атомики, UI читает их напрямую. Пока есть активные задачи, UI перерисовывается не чаще 30 раз в секунду (`request_repaint_after(33ms)`).
  **Почему:** естественный бэкпрешер без потери данных, ограниченная память, 0% CPU в простое.
- **Решение:** I/O-пулы делятся на две полосы: `Interactive` (4 потока: листинг, stat, превью) и `Bulk` (2 потока: операции). CPU-работу выполняет глобальный пул rayon на N−1 потоков. Долгоживущие потоки (PTY, watcher) создаются через `spawn_dedicated`.
  **Почему:** листинг не стоит в очереди за копированием 50 ГБ. Глобальный rayon позволяет S4 вызывать `par_sort` без `install`.
- **Решение:** устаревшие результаты отбрасываются по `Gen` (u64 на таб, растёт при каждой навигации). Предыдущая загрузка отменяется `CancelToken`.
  **Почему:** быстрая навигация не даёт гонок и мерцания.
- **Решение:** конфиг лежит в `config.toml`. Пользователь его хозяин, app только читает. Секции других крейтов хранятся как `toml::Table` (`#[serde(flatten)]`) и разбираются лениво. Миграции выполняются цепочкой `fn(&mut toml::Table)` до типизированного разбора. Сессия хранится отдельно в `session.toml` (state-dir) и пишется атомарно (tmp+rename) на bulk-полосе с debounce 2 с.
  **Почему:** один формат, ошибка в конфиге не блокирует старт, секции других сессий не ломают core.
- **Решение:** `..` — виртуальная строка 0. Её нет в `entries`, и её нельзя выделить.
  **Почему:** выделение и сортировка остаются чистыми, а курсор живёт в едином пространстве строк.
- **Решение:** паники в задачах перехватываются (`catch_unwind`), поток пула живёт дальше, job переходит в `Failed`. Паника в UI-потоке пишет crash-лог, а при следующем старте показывается inline-баннер. Профиль release: `panic = "unwind"`. Отчёты о падениях никуда не отправляются, только локальный файл.
  **Почему:** баг в одной операции не роняет приложение. Офлайн-политика.
- **Решение:** eframe с `default-features = false` и фичами `glow`, `default_fonts`, `x11`, `wayland`. Фичи `persistence` и `accesskit` выключены. Геометрию окна храним сами в сессии.
  **Почему:** меньше бинарь, быстрее старт, нет wgpu.
- **Решение:** в CI clippy запускается с `-D warnings` при уровне pedantic = warn. Шумные pedantic-линты отключены на уровне workspace.
  **Почему:** код чистый с первого дня, дешевле, чем чистить потом.

## 1. Модель потоков

```
                 ┌──────────────────── UI thread (eframe/glow) ─────────────────────┐
 ввод ─► keymap ─┤ Command ─► Core::dispatch ─► Handler(ns) ─► &mut AppState        │
                 │                                   │ cx.spawn(lane, task)         │
                 │ ui.show(&AppState) ◄─ Core::pump(≤4мс) ◄─ cmd_rx ◄─ CommandSender │◄─ term / watcher / ipc
                 │                         ▲                                         │
                 └─────────────────────────┼─────────────────────────────────────────┘
                                           │ msg_rx (bounded 1024, Box<dyn Msg>)
     io-interactive[4] ── листинг, stat ───┤
     io-bulk[2] ───────── ops, запись сессии ┤   MsgSink::send → WakeFlag(false→true) → Waker::wake()
     rayon cpu[N-1] ───── sort, hash, поиск ─┤                                 = ctx.request_repaint()
     dedicated ────────── PTY-reader, watcher ┘
     Progress (атомики): пишут воркеры ─► UI читает напрямую в кадре
```

Кадр:
1. `core.pump(4ms)`: обработка входящих команд, затем `Msg` до исчерпания бюджета. Остаток → `ctx.request_repaint()`.
2. `let ev = core.take_ui_events()`.
3. `ui.show(ctx, core.state(), &ev, &mut out)`, только чтение.
4. `for c in out { core.dispatch(c) }`. Изменения видны в следующем кадре. После dispatch вызывается `ctx.request_repaint()`, если `state.rev` изменился.
5. Если `jobs.any_active()`, вызывается `request_repaint_after(33ms)`.

Пробуждение коалесцируется: `WakeFlag: AtomicBool` сбрасывается в начале `pump`, `wake()` вызывается только при переходе false→true. В простое все потоки спят на `recv`, CPU 0%.

UI-поток никогда не вызывает `MsgSink::send` (иначе возможен deadlock на полном канале), это проверяет `debug_assert!` по thread-id. Изнутри handler используются `cx.dispatch` и `cx.ui`.

Завершение: `Core::shutdown(200ms)` отменяет все токены, закрывает каналы (заблокированные send просыпаются с `Closed`), ждёт join не дольше таймаута, затем потоки отпускаются (detach).

### 2.5 Шина и Runtime

```rust
pub struct Core { /* state, rt, handlers, registry, services, cmd_rx, msg_rx, session_saver */ }
impl Core {
    pub fn new(boot: Boot, services: Services, waker: Arc<dyn Waker>) -> Self;
    pub fn register(&mut self, h: Box<dyn Handler>);          // паника при дубле namespace
    pub fn state(&self) -> &AppState;
    pub fn registry(&self) -> &CommandRegistry;
    pub fn sender(&self) -> CommandSender;
    pub fn dispatch(&mut self, cmd: Command);                  // синхронно; ошибка → Toast
    pub fn pump(&mut self, budget: Duration) -> Pump;          // команды, затем Msg
    pub fn take_ui_events(&mut self) -> Vec<UiEvent>;

    pub fn shutdown(self, timeout: Duration) -> Session;       // + финальная запись сессии
}
pub struct Boot { pub paths: Paths, pub config: Config, pub warnings: Vec<ConfigWarning>, pub session: Option<Session>, pub crashed_last_time: Option<PathBuf> }
#[derive(Copy, Clone, Debug)] pub struct Pump { pub more: bool, pub changed: bool }

pub struct Cx<'a> { pub state: &'a mut AppState, pub rt: &'a Runtime, pub services: &'a Services, /* queue */ }
impl Cx<'_> {
    pub fn dispatch(&mut self, c: Command);   // в конец очереди текущего pump
    pub fn ui(&mut self, e: UiEvent);
    pub fn toast(&mut self, l: Level, t: impl Into<String>);
}

pub trait Waker: Send + Sync + 'static {
    fn wake(&self);
    fn wake_after(&self, d: Duration);
}

/// Результат фоновой работы, применяется в UI-потоке.
pub trait Msg: Send + 'static {
    fn name(&self) -> &'static str;                  // для tracing
    fn apply(self: Box<Self>, cx: &mut Cx<'_>);
}
pub fn msg(name: &'static str, f: impl FnOnce(&mut Cx<'_>) + Send + 'static) -> Box<dyn Msg>;

#[derive(Clone)]
pub struct MsgSink { /* Sender<Box<dyn Msg>>, WakeFlag */ }
impl MsgSink {
    /// Блокирует при полном канале (бэкпрешер), проверяя cancel каждые 15 мс.
    pub fn send(&self, m: Box<dyn Msg>, cancel: &CancelToken) -> Result<(), SendError>;
    pub fn try_send(&self, m: Box<dyn Msg>) -> Result<(), TrySendError>;
}
pub enum SendError { Cancelled, Closed }

pub struct TaskCx { pub cancel: CancelToken, pub sink: MsgSink }

#[derive(Copy, Clone, Debug, PartialEq, Eq)] pub enum Lane { Interactive, Bulk }

#[derive(Clone, Debug, Serialize, Deserialize)]
#[serde(default)]
pub struct RuntimeConfig {
    pub interactive_threads: u8,   // 4
    pub bulk_threads: u8,          // 2
    pub cpu_threads: u8,           // 0 = num_cpus-1 (min 1)
    pub msg_capacity: u32,         // 1024
}
pub struct Runtime { /* lanes, sink, waker */ }
impl Runtime {
    pub fn spawn(&self, lane: Lane, name: &'static str, cancel: CancelToken, f: impl FnOnce(TaskCx) + Send + 'static);
    pub fn spawn_cpu(&self, name: &'static str, cancel: CancelToken, f: impl FnOnce(TaskCx) + Send + 'static); // rayon::spawn
    pub fn spawn_dedicated(&self, name: String, cancel: CancelToken, f: impl FnOnce(TaskCx) + Send + 'static) -> std::thread::JoinHandle<()>;
    pub fn sink(&self) -> MsgSink;
}
```

Пул: N потоков на полосу (`io-i-N`, `io-b-N`) с общей `crossbeam_channel::unbounded<Task>`. Каждая задача выполняется в `catch_unwind`, паника идёт в `tracing::error` и в `Msg` с `Toast`. Rayon настраивается через `ThreadPoolBuilder::build_global` с именами `cpu-N`.

### 2.6 Сервисы, которые внедряют другие крейты

```rust
pub struct Services { pub listing: Arc<dyn ListingService> }
impl Services { pub fn null() -> Self; }          // для тестов и smoke

/// Реализует S4. Методы не блокируют: только spawn в rt.
pub trait ListingService: Send + Sync + 'static {
    fn load(&self, req: LoadReq, rt: &Runtime);
    fn arrange(&self, req: ArrangeReq, rt: &Runtime);
}
pub struct LoadReq { pub tab: TabId, pub gen: Gen, pub loc: Location, pub cancel: CancelToken, pub view: ArrangeSpec }
pub struct ArrangeReq { pub tab: TabId, pub gen: Gen, pub entries: Arc<Vec<Entry>>, pub cancel: CancelToken, pub view: ArrangeSpec }
#[derive(Clone, Debug)]
pub struct ArrangeSpec { pub sort: SortSpec, pub filter: Option<Mask>, pub show_hidden: bool }

pub enum ListingUpdate {
    Chunk(Vec<Entry>),                                   // append; core обновляет stats
    Order { order: Arc<Vec<u32>>, for_len: u32 },        // отбрасывается, если entries.len() != for_len
    Done,
    Failed(Arc<str>),
}
/// Готовый Msg: core сам проверит gen, применит, восстановит курсор и выделение.
pub fn listing_msg(tab: TabId, gen: Gen, u: ListingUpdate) -> Box<dyn Msg>;
```

Политика core:
- Навигация: gen+1, отмена старого токена, листинг стримится сразу.
- `refresh`: стримится в `incoming`. Swap происходит на `Done` или через 150 мс, если загрузка долгая. Курсор и выделение восстанавливаются по именам.
- Восстановленный из сессии таб с `Failed` поднимается к ближайшему существующему родителю (до 32 шагов).

### 2.9 Ошибки и логирование (в app)

- `urfin_app::boot::init_tracing(&Paths, &LogCfg) -> Option<WorkerGuard>`. ## 4. Контракты для других сессий

**S2 (UI)**
- Читает `&AppState` в кадре: `Tab::rows()` и `row(r)` для виртуализированного списка, `rev` у `AppState` и `Tab` как ключи кэша.
- Получает `UiEvent` через `take_ui_events()`, пишет `Command` в `&mut Vec<Command>`.
- Рисует `Prompts::active()` как inline-оверлей у `Anchor`, `JobRegistry::iter()` и `Progress::snapshot()` в job-баре, `Banner`.
- Сообщает размер области через `panel.viewport`. Сплиттер панелей лежит в `WindowGeom.split`.
- `CommandRegistry` служит для палитры. Конфиг читает через `config.section::<UiCfg>("ui")`.
- Сигнатура фронтенда (крейт ui): `Ui::show(&mut self, ctx: &egui::Context, s: &AppState, ev: &[UiEvent], out: &mut Vec<Command>)`.

**S3 (keymap)**
- Маппит ввод egui в `Command` с `Origin::Key`. Сериализация `Command` в TOML (`"id"` или `{cmd=…, args…}`) уже есть.
- Список и валидация команд — `CommandRegistry::iter/validate`, `CommandMeta::repeatable`.
- Контекст для `when` — `AppState::focus`.
- Секция конфига `[keymap]`, пресеты — свои файлы S3 в `config_dir/keymaps/`.

**S4 (vfs)**
- Реализует `ListingService` (`load`, `arrange`) и возвращает результаты только через `listing_msg(tab, gen, ListingUpdate)`.
- Типы `Location`, `Entry`, `EntryKind`, `Attrs`, `SortSpec`, `ArrangeSpec`, `Mask`, `CancelToken`.
- Полосы: `Lane::Interactive` для I/O, `spawn_cpu`/rayon для сортировки, `spawn_dedicated` для watcher.
- Watcher шлёт `panel.refresh {tab}` через `CommandSender`. Чанки ≥2048 записей или раз в 8 мс, первый чанк сразу (цель <16 мс).

**S5 (ops)**
- Handler namespace `ops` и `file`.
- `Tab::targets()` даёт источник, `passive_tab().loc` — назначение.
- `JobRegistry::start` → `JobHandle` (`checkpoint`, `ask`, `finish`, атомики `Progress`), `Lane::Bulk`, `PromptSpec`/`Reply` для конфликтов (`allow_all` = «для всех»).
- После операции шлёт `panel.refresh` для затронутых табов.

**S6 (term)**
- Handler namespace `cmdline` и `term`. `Runtime::spawn_dedicated` для PTY-reader, `MsgSink` для вывода.
- `CommandSender` для `cd` → `panel.go`. `Focus::Cmdline`/`Terminal`. `active_tab().loc` — cwd.
- История пишется в `Paths::state_dir`. Секция `[term]`.

**Общее:** новые варианты в `Focus`, `SortKey`, `UiEvent` и `Attrs` добавляются только через S0. `UiEvent::Ext` и `Command` с собственным namespace не требуют S0.

## 6. Решения для владельца

1. **Где хранить настройки.** Влияет на переносимость (флешка, несколько машин) и привычки пользователей Far/DN.
   - Варианты:
     - (а) только профиль пользователя (`%APPDATA%`);
     - (б) только portable рядом с exe;
     - (в) профиль по умолчанию, portable при наличии файла-маркера `urfin.portable`.
   - Рекомендация: **(в)**, заложено в спецификацию.
2. **Восстановление сессии при запуске.** Открывать ли прошлые табы и пути или стартовать «с чистого листа».
   - Варианты:
     - (а) всегда восстанавливать;
     - (б) опция, по умолчанию вкл;
     - (в) опция, по умолчанию выкл.
   - Рекомендация: **(б)** (`general.restore_session = true`).
3. **Один экземпляр или несколько.** Single-instance (второй запуск открывает таб в уже открытом окне) требует IPC. С несколькими окнами сессию сохраняет последнее закрытое.
   - Варианты:
     - (а) несколько экземпляров;
     - (б) single-instance сразу;
     - (в) (а) сейчас, single-instance опцией к M6.
   - Рекомендация: **(в)**.
4. **Язык интерфейса.** Определяет, закладывать ли i18n сейчас (заголовки команд, тосты, подсказки). Потом это дорого переделывать.
   - Варианты:
     - (а) только EN;
     - (б) только RU;
     - (в) EN+RU с первого дня (ключи `cmd.<id>`, таблицы строк, `general.language = auto`).
   - Рекомендация: **(в)**, стоимость сейчас ≈1 задача в S2.
5. **Доступность (скринридеры, AccessKit).** Включение даёт поддержку NVDA и VoiceOver, но увеличивает бинарь и немного нагружает каждый кадр.
   - Варианты:
     - (а) выкл, за feature-флагом `a11y`;
     - (б) вкл по умолчанию.
   - Рекомендация: **(а)** на M0–M5, пересмотреть к M6 (релиз).
