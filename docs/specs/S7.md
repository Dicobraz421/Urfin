## 0. Ключевые решения

- **Решение:** F3 и быстрый просмотр (Ctrl+Q) — одна подсистема `ViewerDoc`. Отличаются размещением (`Placement::Window | Panel(Side)`) и бюджетами: быстрый просмотр не запускает индекс и поиск, пока не получит фокус.
  **Почему:** один код рендера, кодировок и источников. Быстрый просмотр получает hex, кодировки, подсветку и большие файлы без доработок.
- **Решение:** UI-поток никогда не читает файл, даже через mmap. Он рисует только из `PageCache`: страницы по 64 КиБ, LRU, 8 МиБ на документ (быстрый просмотр — 1 МиБ). Страницы подгружает `Loader` на `Lane::Interactive` и прогревает соседние экраны. Страница mmap отдаётся без копии (`Page::Mapped`), но только после того, как loader её «потрогал».
  **Почему:** «UI не делает I/O». Page fault на HDD или сети — 10–1000 мс, бюджет кадра — p50 ≤ 3 мс / p99 ≤ 6 мс (решение 2026-10-29). Пока страница не пришла, на месте строки рисуется скелетон; у локального файла данные приходят в следующем кадре.
- **Решение:** источники за `trait ByteSource`:
  - `Owned` — файл ≤ 4 МиБ, читается целиком;
  - `Mapped` (memmap2) — локальный том SSD/HDD/NVMe, файл ≥ 64 МиБ, mtime старше 60 с, не follow;
  - `File` (`FileExt::seek_read`) — остальные локальные случаи, включая сеть, USB и follow;
  - `Seek` — не-локальный VFS с `Caps::SEEK`;
  - `Spool` — поток без seek (архивы S8): фоновая копия во временный файл, который растёт.

  **Почему:** на Windows отображённый файл нельзя усечь (`ERROR_USER_MAPPED_FILE`) — падения нет; фильтр mtime не блокирует активные логи. На сети и USB ошибка страницы mmap — `EXCEPTION_IN_PAGE_ERROR`, то есть abort, поэтому там только `seek_read` (медленнее mmap из кэша на 10–30 %).
- **Решение:** файлы > 4 ГБ открываются мгновенно. Позиция — байтовое смещение (`top: u64`), скроллбар в Text/Wrap тоже байтовый. Начало строки ищется назад не дальше `max_line`. Номер строки — из фонового разреженного индекса `(offset, line)` с шагом 1024 строки; пока индекс не дошёл, показывается «стр. ≈N».
  **Почему:** так работает Far. Открытие — O(1): stat + 64 КиБ + детект. Индекс 4 ГБ / 50 М строк — ≈ 0,8 МБ.
- **Решение (2026-11-01, ADR-0023):** F4 — **встроенный редактор, основной и по умолчанию** (№35) на **своём движке для файлов любого размера**: исходный файл читается страницами (`PageCache`) и не меняется до сохранения, правки — piece table на персистентном дереве, текст правок — в кодировке документа, отмена — журнал операций, сохранение — потоком. Документ живёт во `view` (handler `editor`), UI рисует видимые строки на canvas (как вьювер) и шлёт ввод; IME — `EntityInputHandler` своего элемента. Свои же: кодировки, BOM и EOL «как были», атомарное сохранение, поиск и замена движком S7-09, полоса изменений, мини-карта, строки поиска/замены/перехода по макетам. Блочное выделение (Alt+Shift+стрелки, как в Far) — в M4, мультикурсор — после M4 (решение владельца 2026-11-01, §14). Alt+Shift+F4 — внешний редактор (`[editor] external` → `$VISUAL`/`$EDITOR` → программа Windows). `editor.default` меняет F4 и Alt+Shift+F4 местами.
  **Почему:** F4 из файлового менеджера — правка конфига или лога «на секунду», в том числе лога на гигабайты; внешний редактор стартует 0,5–3 с. `EditorState` gpui-kit держит весь текст в памяти (≈ 9 МБ на МБ) и замирает UI ≈ 15 мс на МБ (спайк S7-16) — лимит 16 МБ; вьювер на своих частях открывает 100 ГБ за ≈ 1 мс. Отвергнутые варианты — в ADR-0023.
- **Решение:** подсветка — tree-sitter (№53, заменяет syntect №46), разбор — напрямую по документу (ADR-0023 §7), не через `SyntaxHighlighter` gpui-kit. Грамматики вшиты; набор и вес — §5.7, на решение владельца (§11 B2). Размер: языки с лексером или трекером — любого размера (§5.7), без него — ≤ 16 МБ. Подсветка работает в редакторе, во вьювере (режим «Разметка») и в быстром просмотре.
- **Решение:** поиск во вьювере — фоновая задача на `spawn_cpu` с прогрессом в строке состояния, без job-бара. Типы поиска:
  - литерал — `memchr::memmem`;
  - без учёта регистра и regex — `regex-automata::meta` по байтам;
  - однобайтовые кодировки (1251/866/KOI8) — HIR-перевод Unicode-классов в байтовые через таблицу на 256 значений, без перекодирования;
  - UTF-16 и прочие многобайтовые — перекодирование чанка в UTF-8 с картой смещений;
  - regex — чанки 4 МиБ с перекрытием 64 КиБ;
  - hex — с маской `??`.

  **Почему:** в UTF-8 и однобайтовых кодировках (99 % файлов) сканирование идёт со скоростью памяти. Job-бар — для файловых операций, поиск — локальное действие вьювера.
- **Решение (2026-10-30):** «Разметка» у Markdown — настоящий документ (§3.10): пропорциональный шрифт, заголовки, списки и задачи, таблицы, код на подложке, локальные картинки, сетевые — плашкой. Разбор — свой, pulldown-cmark, не tree-sitter. В редакторе — панель инструментов под шапкой (§5.8), у `.md` — Markdown-кнопки и предпросмотр рядом (§5.9).
  **Почему:** README и CHANGELOG читают как документ; документ нужен в M4, не дожидаясь грамматик S7-21a. Панель — для тех, кто не помнит клавиш Far. Отвергнутые варианты — в решении.

## 2. Модель и API (`urfin-view`)

```rust

pub struct ViewerDoc {
    pub id: DocId, pub loc: Location, pub placement: Placement, pub quick: bool,
    pub src: Arc<dyn ByteSource>, pub len: u64, pub len_final: bool,
    pub enc: Enc, pub eol: Eol, pub mode: Mode, pub wrap: Option<WrapKind>, pub lang: Option<CompactString>,
```

### Редактор

Ревизия 2026-11-01 ([ADR-0023](../adr/0023-editor-engine.md); контракт — предложение ADR-0023 §9, строка CONTRACTS меняется в S7-29). Текст, курсор, выделение и отмена живут в `urfin-view` (handler `editor`), как документ вьювера; UI рисует видимые строки из `TextView` и шлёт ввод. До S7-34 в коде ещё прежний путь (Rope в `EditorState` UI, `Adopted`/`Edited`/`Snapshot`).

## 3. Вьювер (F3)

### 3.1 Открытие
1. `viewer.open {path?, alt?, internal?, placement?}`. На каталоге → `vfs.dir_size`. `alt` → внешний просмотрщик `[viewer] external` (пусто — программа Windows для типа файла, `file.open`; шаблон `"{path}"` — через `term.open`). Без `internal` действуют маски `[[viewer.assoc]]` (по умолчанию пусто).
2. Handler создаёт `ViewerDoc` в состоянии `Opening`, кладёт его в `screens`, ставит `Focus::Viewer`. Экран рисуется сразу: вкладка, шапка, пустое поле.
3. Interactive lane: `open_source` → первые 64 КиБ → `detect` → `lang` (§5.7) → Msg `Opened {src, len, detected}`. Если в истории есть запись (позиция, кодировка, режим, перенос) и `pos < len` — она восстанавливается.
4. `binary` → Hex; иначе язык известен и доступен (§5.7) → Разметка (у Markdown при `viewer.markdown = "document"` — документ, §3.10); иначе Text. Индексатор стартует, если `!quick` и режим текстовый.

Бюджет: первый экран ≤ 50 мс (warm) / ≤ 150 мс (cold SSD) при любом размере файла, включая 100 ГБ. Известное отступление на файлах от 50 МБ — [решение 2026-11-06](../decisions/2026-11-06-perf-tails.md).

### 3.2 Детект кодировки и EOL (`detect.rs`)
1. BOM: UTF-8 / UTF-16LE / UTF-16BE (UTF-32 → hex + тост «не поддерживается»).
2. UTF-16 без BOM: ≥ 30 % нулей на одной чётности и < 5 % на другой при выборке ≥ 512 байт.
3. Бинарный файл: NUL в выборке (не UTF-16) или > 10 % управляющих байтов, кроме `\t\n\r\f\x1b`.
4. Валидный UTF-8 (обрезанный хвост выборки допустим) → UTF-8. Чистый ASCII → UTF-8.
5. Иначе `chardetng::EncodingDetector::guess(tld, false)`. `tld` — из языка интерфейса: ru/uk/be/kk → `b"ru"`. KOI8-U показывается как KOI8-R, если в выборке нет байтов украинских букв `A4 A6 A7 AD B4 B6 B7 BD`.
6. EOL: есть LF → `Lf`/`CrLf` (CR перед LF не рисуется). Нет LF, но есть CR → `Cr`. Смесь → `Mixed` (разделитель LF, одиночный CR рисуется `␍`).

Ручная смена: F8 — кольцо `viewer.codepage_ring` (по умолчанию `auto → UTF-8 → windows-1251 → IBM866`); Shift+F8 или клик по чипу кодировки — «мешочек» от чипа (`screen-viewerenc.png`): «Авто — определять по содержимому» сверху, группы Юникод (UTF-8, UTF-16 LE/BE), кириллица (Windows-1251, CP866, KOI8-R, KOI8-U, ISO-8859-5, Mac Cyrillic), западная (Windows-1252…), остальные кодировки encoding_rs ниже; текущая — ✓ и метка «авто», если выбрана детектом. Клавиши — ↑↓, Enter, F8 по кругу, Esc. Смена сбрасывает индекс только для UTF-16 ↔ байтовых (разделитель другой).

### 3.3 Индекс строк (`index.rs`)
- Разделитель: `\n` (или `\r` для `Cr`). UTF-16 — пара `0A 00` / `00 0A` на чётном смещении: `memchr` + проверка чётности.
- `Mapped` и `File` на SSD/NVMe: параллельно (`rayon`) по диапазонам 64 МиБ; диапазон отдаёт `(count, метки каждые 1024 строки)`, при слиянии — префиксная сумма. HDD, сеть, `Spool` — последовательно, буфер 4 МиБ, отдельный handle с `FILE_FLAG_SEQUENTIAL_SCAN`.
- Публикация: Msg с дельтой меток не чаще 10 раз в секунду. Отмена — токеном документа. Для follow/Spool индексатор дочитывает прирост.
- `viewer.goto` на строку N: если `upto` её покрывает — loader сканирует от метки ≤ 1024 строк; если нет — «ждём индекс» с прогрессом в строке состояния, Esc отменяет.
- Бюджет: ≥ 2 ГБ/с (warm, NVMe, 8 потоков), ≥ 1 ГБ/с в один поток. RAM — 16 Б на 1024 строки.

### 3.4 Раскладка и режимы (`layout.rs`)
Переключатель режимов — сегменты «Текст | Разметка | Hex» справа в шапке (Shift+F4 — меню режимов «мешочком» от этих сегментов, F4 — Hex ↔ прошлый текстовый). В быстром просмотре сегментов нет — источник меню режимов там чип «Разметка ▾» (§4).
- **Текст:** логическая строка — до разделителя. Строки длиннее `max_line` (64 КиБ) режутся на сегменты, в конце сегмента — маркер `↩` цветом `text.tertiary`. Табы раскрываются до `tab_size` (8). Управляющие символы — `·` цветом `text.tertiary`. Недекодируемые байты — U+FFFD цветом `critical.fg`. Горизонтальная прокрутка по колонкам: строится только видимое окно `hscroll..hscroll+cols`.
- **Разметка:** раскладка Текста + подсветка tree-sitter (§5.7) для документов с известным языком: языки с лексером или трекером — любого размера (§5.7), без него — ≤ 16 МБ; иначе режим недоступен (сегмент `text.disabled`). У Markdown «Разметка» — документ (§3.10, `screen-viewer-md.png`); исходник с подсветкой — при `viewer.markdown = "source"`. «Чистый Markdown» моноширинно снят (решение 2026-10-30).
- **Перенос** (F2, оба текстовых режима): визуальные строки считаются только для видимой области. `Chars` — по ширине в колонках (unicode-width, CJK = 2); `Words` — по границам UAX#29, слово длиннее строки рвётся. Прокрутка вверх: `line_start_before` → разбить строку → последняя подстрока перед `top`.
- **Hex:** строка = `hex_cols` байт (`auto`: 32 при ширине ≥ 150 колонок, 16 при ≥ 76, иначе 8). Линейка `00 … 1F` над данными, столбец курсора — `accent`. Колонки:
  - смещение — 8 hex-цифр (12 при len > 4 ГиБ) на подложке `header`;
  - байты группами по 8, `text.secondary` только у нулей, остальные, и непечатаемые тоже, — `text`;
  - текст в текущей кодировке: однобайтовая — символ на байт; UTF-8 — символ на первом байте, продолжения `·`; UTF-16 — на чётных байтах.
  
  Курсор — фон `fill.cursor` + рамка `accent` одновременно в hex и тексте; в статусе — «Смещение 0x0000004E · 54h = 84 · «T»». Индекс не нужен, скроллбар точный.
- Межрежимная позиция сохраняется: Text→Hex — `top` вниз до `hex_cols`, Hex→Text — до начала строки.
- Режим Far «dump» (без переносов на ширину окна) — бэклог, в макетах его нет.

### 3.5 Переход (`viewer.goto`, Alt+F8)
Строка внизу экрана (`OverlayKind::Find`), как `screen-editgoto.png`: «Перейти к строке» (в Hex — «Перейти к смещению»), поле, подсказка «из N · строка», кнопки Перейти (Enter) / Отмена (Esc). Синтаксис:
- `123` — строка в Текст/Разметка, смещение в Hex;
- `0x1F00`, `1F00h`, `$1F00` — смещение;
- `50%` — доля файла;
- `+N` / `-N` — относительно текущей позиции (строки или байты по режиму).

Перед переходом текущая позиция кладётся в `back` (Alt+Backspace — `viewer.back`). Закладки: Ctrl+Shift+0..9 ставят, Ctrl+0..9 переходят.

### 3.6 Поиск (`viewer.search`, F7)
- Строка поиска — внизу экрана, над строкой состояния (`OverlayKind::Find`, IME вкл), как ряд «Найти» в `screen-editreplace.png`: поле, «3 из 120» / «12 из 1 000+», флажки Регистр (Alt+C), Слово (Alt+W), Регулярное (Alt+R), Hex (Alt+H). Клавиши — подписями на кнопках, keybar показывает только дополнительные (№61).
  Enter — вперёд, Shift+Enter — назад, Esc — закрыть (идущий поиск отменяется). Фокус после Enter остаётся в строке. Shift+F7 / Alt+F7 работают и после закрытия.
- Фоновая задача (`spawn_cpu`, токен на поиск): от `sel.end` (или `top`) вперёд чанками по 4 МиБ. `Mapped` — прямо по срезу, иначе `read_at` в буфер. Regex-чанки перекрываются на `min(max_len, 64 КиБ)`. На конце файла — перенос на начало (`viewer.search_wrap`) и тост «Продолжено с начала». Назад — чанки в обратном порядке, в чанке берётся последнее совпадение до точки старта; memmem — `FinderRev`.
- Прогресс: `scanned` в атомике; полоса 2 px `accent.fill` под шапкой и «Поиск… 41 %» в статусе. Обновление ≤ 30/с, перерисовка таймером 33 мс, пока поиск идёт.
- Совпадение становится выделением (`sel`); `top` ставится так, чтобы строка оказалась на трети экрана. Совпадения в видимой области подсвечиваются при отрисовке (matcher по видимым байтам, ≤ 64 КиБ): `highlight`, текущее — заливка `accent.fill` и текст `accent.on`.
- Метки: позиции совпадений (до `count_limit`) — риски на полосе прокрутки (как на `screen-editreplace.png`), в середине статуса — «5 отметок «Исправлено»».
- Подсветка, метки и итог в статусе — только при открытой строке «Найти», как в редакторе: закрыли строку — сняты, исключения для вьювера нет (решения [2026-11-04](../decisions/2026-11-04-mockup-editor-search.md), [2026-11-06](../decisions/2026-11-06-mockups-d07.md)).
- Счётчик: после первого совпадения задача досчитывает до `viewer.count_limit` (10 000) или до конца файла на низком приоритете; новый поиск её отменяет.
- Компиляция по кодировке:
  - **UTF-8 / ASCII:** литерал с учётом регистра → `memmem::Finder`; иначе → `meta::Regex` (unicode on, `utf8(false)`, `(?i)`, `\b` по опции «Слово»).
  - **Однобайтовая (1251, 866, KOI8, 1252…):** `regex-syntax` → HIR (Unicode) → `hir_bytes::translate`: литералы и классы — через таблицу `byte → char` на 256 значений, непредставимые → пустой класс; `\b` → ASCII-граница (ограничение задокументировано); затем `meta::Builder::build_from_hir`. Без перекодирования.
  - **UTF-16 и многобайтовые (Shift_JIS, GBK, EUC-*):** чанк перекодируется в UTF-8 (`Decoder`) с картой «байт UTF-8 → смещение в источнике», поиск по UTF-8.
  - **Hex:** `DE AD ?? EF` / `DEAD??EF`. Без `??` — memmem, иначе `(?s-u)\xDE\xAD.\xEF`.
- Бюджеты (warm): литерал ≥ 3 ГБ/с; без учёта регистра и простой regex ≥ 0,8 ГБ/с; 1251-regex ≥ 0,8 ГБ/с; UTF-16 ≥ 250 МБ/с; hex ≥ 3 ГБ/с.

### 3.7 Выделение и копирование
- Мышь: drag выделяет байтовый диапазон (hit-test — `ShapedLine::index_for_x` + `RowText.map`), Shift+клик расширяет, двойной клик — слово. В Hex выделение по байтам в обеих колонках.
- `viewer.select_all` (Ctrl+A) и `viewer.copy` (Ctrl+C, Ctrl+Ins) декодируют выделение в текущей кодировке на Interactive lane и кладут текст в буфер обмена (`cx.write_to_clipboard` в фиче по `UiEvent::Ext`). Выделение в Hex копируется hex-строкой (`DE AD BE EF`). Лимит `viewer.copy_limit_mb` = 64, сверх — тост.
- Кнопка мыши «Назад» = `viewer.back`. Колесо — 3 строки; Ctrl+колесо — размер моно-шрифта вьювера (`viewer.font_size`, не общий масштаб).

### 3.8 Follow (tail -f) — `viewer.follow` (Shift+F)
- Источник всегда `File` (не `Mapped`). Handle открыт с `FILE_SHARE_READ|WRITE|DELETE`: писатель пишет, усекает и ротирует файл свободно.
- Поток `spawn_dedicated("view.follow")` раз в `follow_interval_ms` (250) делает `refresh_len()`, без watcher S4 (сеть, точность):
  - прирост → Msg `Grew(len)`: индекс дочитывает, `top` прилипает к концу, если пользователь был внизу;
  - `len < old` → «файл усечён»: индекс сбрасывается, позиция — в конец;
  - ротация (по пути новый `file_id`) → переоткрыть по пути (`viewer.follow_reopen`), тост.
- Чип «Слежение» в шапке справа (`success.fg`). Прокрутка вверх приостанавливает прилипание, End возобновляет. Поток живёт, пока документ открыт. Простой ≈ 0 % CPU (4 stat/с).

### 3.9 Навигация между файлами и экраны
- `viewer.next_file` / `prev_file` (Gray+/Gray−): следующий файл в `order` таба-источника, каталоги пропускаются; документ переоткрывается на месте, режим и перенос сохраняются, кодировка — `auto`.
- `viewer.reveal` (Ctrl+F10): курсор таба-источника на файл (`panel.cursor.to`), фокус — в панель, вьювер остаётся экраном.
- `viewer.to_editor` (F6): редактор на той же позиции (строка и колонка); вьювер закрывается.
- Экраны (Far F12): каждый документ с `Placement::Window` — экран. Пока экран активен, полоса вкладок окна показывает вкладки экранов (`ViewState.screens`: имя файла, ● у изменённого, ×; «+» после них нет), слева — кнопка «две панели» (возврат к панелям, путь — в подсказке; DESIGN «Таб панелей вне панелей»). Esc закрывает документ; возврат к панелям его не закрывает.
- `ui.screens` (F12; DN — Alt+0) — список панелей и экранов «мешочком» от кнопки «Экраны» в заголовке окна справа, перед кнопками окна (решение 2026-11-01, `screen-screens.png`): кнопка видна и на панелях, и на экране, пока открыт хоть один экран; клик и клавиша открывают одну фигуру у этой кнопки. Строка 0 — «Панели», дальше экраны по `ViewState.screens`: цифра 0–9 выбирает сразу, значок вида, имя (● у изменённого), папка, «просмотр»/«правка», ✓ у текущего. Экранов нет — кнопка скрыта; F12 показывает её открытой с одной строкой «Панели».
- `viewer.history` (Alt+F11; DN — Alt+PageDown / Alt+PageUp с `kind`): MRU просмотров и правок «мешочком» от кнопки «История» (часы) первой слева в шапке вьювера и редактора (решение 2026-11-01, `screen-viewerhistory.png`): поле «Найти файл», строки — вид, имя, папка, позиция, когда; Enter — открыть как было, F3/F4 — просмотр/правка. На панелях (Far: Alt+F11 и там) — раздел «Файлы» мешочка от кнопки «История» у пути активной панели; раздел «Папки» — Alt+F12 (`screen-history-files.png`, `screen-history.png`; решение 2026-11-01, «Панели»; S2 §2.1). Хранение: `state_dir/view-history.json`. Запись `{uri, kind, pos, enc, mode, wrap, ts}`, cap 500, запись с debounce 2 с на Bulk lane. Выключатель — `viewer.remember_pos` (№36).

### 3.10 Markdown-документ (`md/`, решение 2026-10-30)
Режим «Разметка» у Markdown (`lang` = Markdown: `.md`, `.markdown`, `.mdown`, `.mkd`) при `viewer.markdown = "document"` (по умолчанию) показывает документ — `screen-viewer-md.png`, стили — DESIGN «Markdown-документ». `"source"` — исходник с подсветкой S7-21. Файл > 16 МБ — режим недоступен (сегмент `text.disabled`), открывается Текст. Для других языков «Разметка» — подсветка §5.7.

- **Разбор** (`urfin_view::md`, Interactive lane, отмена — токеном документа): текст декодируется целиком в текущей кодировке, `pulldown_cmark::Parser::new_ext(…).into_offset_iter()` с расширениями GFM: таблицы, задачи, зачёркнутый, сноски. Итог — `MdDoc`:
  ```rust
  pub struct MdDoc { pub blocks: Vec<Block>, pub text: String /* проекция */, pub images: Vec<ImageRef>, pub links: Vec<LinkRef> }
  pub struct Block { pub kind: BlockKind, pub src: Range<u64> /* байты исходника */, pub runs: Range<u32> /* в проекции */, pub depth: u8, pub align: Align /* left | center | right — align= у <p>/<div> */ }
  pub enum BlockKind { Heading(u8), Para, Item { mark: Mark /* • | N. | [ ] | [x] */ }, Quote, Table { align: SmallVec<[Align; 8]> }, Code { lang: Option<CompactString> }, Rule, Image(u32), FootnoteDef, Details { open: bool }, Summary, RawHtml }
  pub struct Run { pub text: Range<u32>, pub style: RunStyle /* bold | italic | strike | code | link(u32) | image(u32) | kbd | sub | sup */ }
  ```
  Смена кодировки или правка (предпросмотр §5.9) → новый разбор.
- **Поддержано:** CommonMark + GFM — заголовки ATX и Setext, абзацы, жёсткий перенос, жирный, курсив, зачёркнутый, код в строке, ссылки (inline, reference, autolink), картинки, списки маркированные и нумерованные (вложенные, `start`), задачи, цитаты (вложенные), таблицы с выравниванием, блоки кода (fenced и с отступом), черта, сноски (метка и список внизу). Блок кода с известным языком — подсветка S7-21, когда она есть; до неё — `text`. Front matter (`---` в первой строке) — блок кода `yaml`.
- **Сырой HTML — небольшой набор** (решение владельца 2026-10-30, §13, вопрос 3): `<br>` — жёсткий перенос; `<img src width height alt>` — картинка по правилам ниже (только локальные, сетевые — плашка), `width`/`height` в px задают размер (задано одно — пропорции сохраняются), не шире колонки; `<details>` + `<summary>` — раскрываемый блок (`Details`: по умолчанию свёрнут, с атрибутом `open` — раскрыт; первый `<summary>` — его подпись, без него — «Подробнее»), внутри — обычный Markdown; `align="center"` / `"right"` у `<p>` и `<div>` — выравнивание блока (`Block::align`); `<kbd>` — клавиша; `<sub>` / `<sup>` — нижний и верхний индекс. Теги разбирает свой маленький токенайзер по событиям `Html` / `InlineHtml` pulldown-cmark (без html5ever): имя и атрибуты без учёта регистра, значения в кавычках или без. Текст внутри HTML-блока — как есть, Markdown в нём не разбирается (как на GitHub), разрешённые теги работают. Прочие теги, непарные и битые — текстом, моноширинно, `secondary` (`RawHtml`, `InlineHtml` — run `code`), как раньше. Скриптов, стилей и сети нет: `style`, `class`, обработчики и прочие атрибуты игнорируются.
- **Проекция** — видимый текст документа одной UTF-8 строкой (абзацы и `<br>` через `\n`, ячейки таблицы через `\t`) с картой «проекция → блок → исходник». Нужна для поиска F7 (§13, вопрос 1), выделения и копирования. Текст свёрнутого `<details>` в проекции есть: совпадение внутри раскрывает блок.
- **Картинки:** путь разрешается относительно папки `.md` (`%20` декодируется; `/путь` — от корня git-репозитория, если `.md` в нём, иначе от корня тома; абсолютный путь Windows — как есть). Только локальные файлы (`Caps::LOCAL`, не архив и не SFTP) до `viewer.md_image_max_mb` (20); форматы — что декодирует GPUI (PNG, JPEG, GIF, WebP, BMP, SVG), `data:` — тоже (без сети). Грузит и декодирует GPUI в фоне (`gpui::img` с путём), UI-поток файл не читает. Размер — свой, но не шире колонки; до загрузки — скелетон 24. Сетевые (`http(s)://`, `//`), отсутствующие, неподдержанные и слишком большие — плашка: значок, alt-текст, причина («из сети не загружается», «файл не найден», «формат не поддерживается», «больше 20 МБ»). Число непоказанных — в середине статуса.
- **Ссылки:** цвет `accent`; при наведении — подчёркивание и подсказка с целью. Клик: `#якорь` — прокрутка к заголовку (slug как у GitHub); относительный путь к `.md` — открыть в этом же вьювере (назад — `viewer.back`, Alt+Backspace); другой локальный файл или папка — курсор панели на него (`viewer.reveal`). Внешние (`http(s)`, `mailto`; решение владельца 2026-10-30, §13, вопрос 2) — Ctrl+клик открывает программой Windows (браузер, почта): `ShellExecuteExW` с verb по умолчанию на коротком потоке, как Enter по файлу (S6 §7), UI не ждёт; сам Урфин в сеть не ходит. Простой клик — только подсказка «Ctrl+клик — открыть в браузере». Другие схемы не открываются, цель видна в подсказке.
- **Раскладка (UI, S7-22a):** колонка 820 по центру, поля 32 (в предпросмотре и быстром просмотре — вся ширина, поля 28), Segoe UI Variable 14/22; `viewer.md_font_size` (0 = 14), Ctrl+колесо меняет его. Блок — элемент `gpui::list` (переменная высота, меряется лениво); таблица и блок кода длиннее 64 строк режутся на элементы. Перенос по словам — всегда (F2 в документе не действует). Широкая таблица и блок кода прокручиваются по горизонтали внутри блока.
- **Позиция:** верх экрана — смещение начала верхнего блока + доля его высоты; оно же пишется в историю (`pos`). Документ ↔ Текст сохраняет место: Текст открывается со строки начала блока, обратно — блок, содержащий `top`. Статус слева — «Стр A–B из N · P %» по исходнику видимых блоков; в середине — итог поиска или «N картинок не показано»; справа — размер и EOL.
- **Поиск и смещения — через Текст** (решение): Alt+F8 (переход к строке или смещению) и поиск Hex переключают в Текст на той же позиции и открывают свою строку. F7 — поиск по проекции (решение владельца 2026-10-30, §13, вопрос 1): движок S7-09 по проекции, совпадения подсвечиваются в документе, «N из M», Регистр / Слово / Регулярное; флажок Hex — `disabled`. Выделение мышью — по проекции; Ctrl+C копирует видимый текст без разметки, Ctrl+A — весь документ; исходник копируется из Текста.
- **Бюджеты** (release, warm): разбор 1 МБ ≤ 20 мс, 16 МБ ≤ 300 мс; при файле > 1 МБ первый экран строится из первых 256 КиБ разбора, остальное дописывается; кадр — p50 ≤ 3 мс, p99 ≤ 6 мс (решение 2026-10-29); память — ≤ 3× размера текста.

## 4. Быстрый просмотр (Ctrl+Q)

- `panel.mode {qview}` (core) ставит `Tab.mode = qview` пассивной панели. Её область рисует `gpui_shell/view/quick.rs` (`screen-quickview.png`): вкладка и шапка панели «Быстрый просмотр», справа в шапке — тип («TOML»); поле номеров 40, моно-текст, подсветка (Разметка), если язык известен; в середине статуса — «стр 1–26 из 41». Временный предпросмотр S2-18 (`crates/ui/src/views.rs`: `PreviewState`, `classify`, задача `ui.preview`) снимается.
- Следит за курсором активной панели. Debounce в фиче (UI-локальное): через 50 мс без движения уходит `viewer.quick {side, path}`. Handler переоткрывает тот же `DocId` и отменяет прошлое открытие; в очереди — не больше 1 чтения.
- Ограничения: кэш 1 МиБ, индекс и поиск не стартуют. Бинарный файл → Hex. Каталог → краткая сводка (`vfs.dir_size` по команде). Файлы облака (`Attrs::OFFLINE`) не читаются: «Файл в облаке — F3 для загрузки» (не будим скачивание OneDrive).

- Кодировка и режим (решение 2026-11-01): справа в шапке области, после типа — чипы «UTF-8 авто ▾» и «Разметка ▾» (`screen-quickview.png`). Shift+F8 / Shift+F4 и клик по чипу открывают «мешочек» от своего чипа (`screen-quickview-enc.png`; пункты — как во вьювере); клик по чипу переводит фокус в быстрый просмотр. Плашки у края области больше нет.
- Markdown в быстром просмотре — документ (§3.10) для файлов ≤ 4 МиБ (источник `Owned`), шириной в панель; больше — Текст. Картинки грузятся только для видимых блоков.
- `viewer.dock` переключает F3-вьювер между окном и пассивной панелью (как быстрый просмотр, без следования за курсором). По умолчанию `viewer.placement = "window"` (№34).

## 5. Редактор (F4)

Движок — [ADR-0023](../adr/0023-editor-engine.md) (решение владельца 2026-11-01): любой размер файла, память на документ ≤ 64 МиБ. Ниже — поведение; устройство (дерево кусков, кодировка, журнал, защита исходника) — в ADR.

### 5.1 Открытие
- `editor.open {path?, alt?, internal?, line?, col?}`: `alt` или `editor.default = "external"` → внешний редактор (§5.6); `editor.new` (Shift+F4) → черновик имени `ui.draft` → пустой документ, файл создаётся при первом сохранении.
- **Лимита размера нет** (`editor.max_size_mb` снят). Открытие = открытие вьювера (Interactive lane): stat → первые 64 КиБ → детект (§3.2) → документ из одного куска `Original`. Экран и ввод доступны сразу; номера строк точные, когда фоновый индекс дошёл (до того поле номеров пустое, статус «Стр ≈N», как во вьювере).
- Файл ≤ 16 МиБ читается в память целиком и индексируется на открытии. Больше — источник `File` (`seek_read`, не mmap), страницы через `PageCache` документа (16 МиБ), индекс — фоновый `Indexer` вьювера.
- Файл > 16 МиБ на время правки **закрыт для записи другим программам** (handle без `FILE_SHARE_WRITE`; чтение, переименование и удаление разрешены). Если его уже пишет другая программа — документ открывается без запрета, первая правка спрашивает строкой внизу: «Файл пишет другая программа — правка без запрета записи может испортить текст: [Править копию] [Открыть в просмотре] [Отмена]» (ADR-0023 §8).
- `lossy` → inline-строка `caution` внизу: «Есть байты, недопустимые в {enc}: они показаны «�» и сохранятся как были, если их не править. [Сменить кодировку F8]».
- Read-only (атрибут или нет прав) → чип «только чтение» в шапке (как во вьювере), правка не принимается. Сохранение предлагает снять атрибут (`EdAsk::ReadOnly`).

### 5.2 Правка
- Документ, курсор, выделение и отмена — во `view`; UI шлёт ввод (§2). Клавиши — команды `editor.*` (§7), переназначаются в keymap:
  - движения: стрелки, Home/End, Ctrl+←/→ по словам (`unicode-segmentation` по окну строки), PgUp/PgDn, Ctrl+Home/End; Shift — расширение выделения; вверх/вниз — по визуальным рядам с памятью колонки (перенос учитывается). Движение, упёршееся в незагруженные страницы, завершается по их приходу;
  - мышь: клик, drag с автопрокруткой, двойной — слово, тройной — строка (`InboxMsg::Caret`);
  - **блочное выделение** (S7-40, решение 2026-11-01): Alt+Shift+стрелки/Home/End/PgUp/PgDn и Alt+drag — прямоугольник «строки × экранные колонки»; копирование — строки через `eol_new` + формат `MSDEVColumnSelect`; вырезание и Del/Backspace — колонки в каждой строке; ввод — удалить блок и печатать у курсора; вставка блочного буфера — колонкой от курсора; одна группа отмены; блок выше 64 тыс. строк — фоновой задачей. Мультикурсора нет (после M4);
  - Backspace/Del (Ctrl — по словам), Enter с автоотступом, Tab/Shift+Tab (с выделением — блок, `editor.block.shift_*`), `editor.delete_line` (Ctrl+Y), Ins — режим замены (статус «Вставка»/«Замена»);
  - буфер обмена (Ctrl+C/X/V, Ctrl+Ins / Shift+Ins / Shift+Del): вставка читается вне UI-потока и потоком кодируется в буфер правок, EOL → `eol_new`, одна группа отмены; копирование и вырезание — до `viewer.copy_limit_mb` (64), больше — тост с размером;
  - пробелы вместо табов (`expand_tabs`), `tab_size`; мягкий перенос (`editor.wrap`); свёртка (§5.7, после S7-21); номера строк.
- Текст правок кодируется в кодировку документа. Символа нет в ней → строка внизу: «В {enc} нет символа «X»: [Перевести документ в UTF-8] [Вставить «?»] [Отмена]»; перевод — с отменой (≤ 16 МиБ мгновенно, больше — задача с прогрессом).
- IME — `EntityInputHandler` элемента правки: composition рисуется поверх строки с подчёркиванием, в документ попадает commit; UTF-16-координаты — окно строки курсора (ADR-0023 §7).
- Отмена/повтор (`editor.undo`/`redo`, клавиши — по пресету): группы — пауза ≥ 1 с, переход курсора, смена вида правки, любая команда правки; восстанавливается выделение. Память журнала ≤ 16 МиБ (старые группы отбрасываются). История переживает сохранение; ● снимается, когда отмена вернула сохранённое состояние.
- `editor.eol {lf|crlf|cr}` (палитра, «LF ▾») — весь документ одной группой (на больших файлах — фоновая замена по кускам, как «Заменить все»); новые строки получают `eol_new`.
- `editor.goto` (Alt+F8): строка внизу (`screen-editgoto.png`): «Перейти к строке», поле `строка[:колонка]`, «из 41 · строка:колонка», Перейти (Enter) / Отмена (Esc). Пока индекс не дошёл до строки — переход по ближайшей метке и досчёт, «из ≈N».
- `editor.search` / `editor.replace` (F7 / Ctrl+F7): строка внизу в один или два ряда (`screen-editreplace.png`): Найти + «N из M», Регистр / Слово / Регулярное (Alt+C/W/R); Заменить на + Заменить (Enter) / Заменить все (Ctrl+Alt+Enter) + подсказка «$1, $2 — группы из «Найти»». Tab — между полями, Shift+Enter — предыдущее. Движок — S7-09 по кускам документа (снимок, фон): литерал, regex по байтам, однобайтовые — HIR-перевод, UTF-16 — transcode; `^`/`$` по строкам с CRLF. Совпадения — подсветкой в строках (текущее — заливка `accent.fill`, текст `accent.on`), метки — на мини-карте и полосе прокрутки; закрыли строку — подсветка и метки сняты. Счётчик до `count_limit`. «Заменить все» — фоновая задача с прогрессом в статусе и отменой (Esc), документ на это время только для чтения, итог — одна группа отмены (> 64 тыс. совпадений — результат потоком во временный файл, ADR-0023 §5).
- `editor.codepage` (F8 / Shift+F8 — тот же «мешочек» кодировок, от кнопки «UTF-8 ▾» панели инструментов; панель выключена — вверх от ячейки кодировки в статусе): документ не изменён → переинтерпретация (перечитать байты с диска в новой кодировке); изменён → кодировка меняется только для сохранения (перекодирование потоком при записи), с подтверждением одной строкой.

### 5.3 Экран редактора
По `screen-editor.png` и DESIGN: вкладка — имя файла, ● у изменённого. Шапка 36: значок `</>`, путь к папке; справа — счётчик правок «+2 добавлено · 1 изменена» (`LineChanges`). Поле слева: полоса изменений 3 px (`accent` — изменено, `type.exec` — добавлено; по кускам документа, без diff текста: строка только из правок — добавлена, правка + исходник — изменена, метка — шов удаления), номера 40, свёртка 14. Строки 20 px — свой `canvas` (§6), шрифт `editor.font` (по умолчанию моно окна, Cascadia Mono 13), текущая строка подсвечена. Мини-карта 88 справа с рамкой видимой части: окно строк вокруг видимой части из кэша страниц (на длинном документе окно едет пропорционально), линии строк цветами подсветки, метки поиска. `editor.gutter = false` прячет номера, свёртку и мини-карту. Под шапкой — панель инструментов 36 (§5.8, `editor.toolbar`). Строка состояния: слева «Стр 6, Кол 18» (до индекса — «Стр ≈N»; колонка в строке, начало которой дальше 1 МиБ, — «Кол ≈N»), в середине «41 строка», справа «TOML · Пробелы: 4 · Вставка»; кодировка и конец строки — кнопками на панели, а при выключенной панели — в статусе: «TOML · Пробелы: 4 · UTF-8 · LF · Вставка» (№61). Задачи документа («Замена 12 %», «Перевод в UTF-8 7 %») — в статусе справа, сохранение больших файлов — в job-баре. Курсор мигает 500 мс, только при фокусе в редакторе.

### 5.4 Сохранение (`editor.save` F2, `save_as` Shift+F2, `save_close` Shift+F10)
- Handler берёт снимок документа (O(1)) и пишет **потоком**: куски по очереди (исходник — блоками 4 МиБ, правки — из буфера) во временный файл; память постоянная. Та же кодировка — байты кусков копируются как есть (сохранение без правок даёт те же байты); другая (F8 с правками) — перекодирование потоком `Encoder` + BOM, непредставимые → `EdAsk::Unmappable`: «N символов нельзя записать в {enc}: [Сохранить в UTF-8] [Заменить на ?] [Отмена]».
- Атомарно: `.<name>.urfin~` в том же каталоге → `sync_all` → `ReplaceFileW` (сохраняет ACL, атрибуты, время создания и ADS); при ошибке — `MoveFileExW(REPLACE_EXISTING)`. Исключения: `nlink > 1` или нет прав на каталог → временный файл в `%TEMP%`, затем запись на месте (история отмены, ссылающаяся на старые байты, отбрасывается); symlink → пишется в цель. Перед записью — свободное место ≥ размера документа, иначе вопрос с цифрами.
- После записи документ перестраивается на новый файл (один кусок), если его не правили во время сохранения; правка во время сохранения разрешена (снимок), тогда ● остаётся.
- Внешнее изменение: перед сохранением и при возврате на экран сравнивается `DiskStamp`. Если файл изменён (или путь указывает на другой файл) → inline-строка внизу «Файл изменён на диске: [Перезагрузить] [Сохранить поверх]» (inline-подтверждение, не тост — №51). Данные документа при этом целы (≤ 16 МиБ — в памяти, больше — под запретом записи, §5.1).
- Документ > 8 МиБ сохраняется как Job (`JobSpec{kind:"editor.save", owner_ns:"editor", lane: Bulk}`) с прогрессом в job-баре и отменой.
- Не-локальные (S8) файлы: только «Сохранить как» в локальный путь, пока S8 не даст запись (удалённые SFTP — F03-08).
- `Handler::on_quit` → `Veto(PromptSpec)`, если есть несохранённые: «Не сохранено: N [Сохранить все] [Не сохранять] [Отмена]». `editor.close` изменённого документа — подтверждение одной строкой.
- Автосохранение `editor.autosave` (макет «Выключено» по умолчанию): `off | focus` (при уходе с экрана или из окна) `| delay` (через 1 с после правки); пишет только локальные файлы без конфликта `DiskStamp`.

### 5.5 Бюджеты
Стенд, release; гейты — S7-36, таблица — `docs/perf/s7.md`.
- Открытие любого размера (10 ГБ, V1) до первого экрана ≤ 50 мс тёплый / ≤ 150 мс холодный SSD, править — сразу; 10 МБ ≤ 50 мс.
- Нажатие (правка + кадр) на любом размере, включая 10 ГБ: p50 ≤ 3 мс, p99 ≤ 6 мс; файл в одну строку (V2, строка 50 МБ) — p50 ≤ 3,5 мс, p99 ≤ 7 мс ([решение 2026-11-06](../decisions/2026-11-06-perf-tails.md)); прокрутка и прыжок — как вьювер.
- Память документа (кэш страниц + правки + дерево + журнал + индекс) ≤ 64 МиБ на любом размере; процесс с документом 10 ГБ — private ≤ 200 МБ.
- Сохранение 1 ГБ с одной правкой ≤ 3 с на NVMe, память + ≤ 8 МиБ; 10 ГБ ≤ 30 с; кадр UI во время записи в бюджете.
- Вставка 100 МБ — без замирания UI, готово ≤ 1 с. Поиск литерала ≥ 3 ГБ/с. «Заменить все»: 100 тыс. совпадений в 50 МБ ≤ 1 с, одна отмена.

### 5.6 Внешний редактор (Alt+Shift+F4)
Порядок: `[editor] external` (шаблон `"code -w {path}"`, `{line}` — текущая строка, если открыт из вьювера) → `$VISUAL` → `$EDITOR` → программа Windows для типа файла (`file.open`). Запуск:
- консольный редактор (`external_console = "auto"`: vim, nvim, nano, micro, hx, `emacs -nw`, kak; или `console = true` в шаблоне) → сеанс терминала S6 (`SessionKind::External`), фокус в Terminal;
- GUI-редактор → отсоединённый процесс (`term.open`).

Панели обновит watcher S4.

### 5.7 Подсветка (tree-sitter, №53)
- Грамматики (S7-21a, решение 2026-10-30): в exe — JSON, TOML, YAML, INI, XML, Markdown (крейты `tree-sitter-*` у `urfin-view`, рантайм tree-sitter 0.26), запросы — свои, `assets/syntax/<язык>/highlights.scm` (вшиты); прочие языки — **пакеты** `grammars\<язык>.dll` рядом с `urfin.exe` (`assets/syntax/pack`, экспорт `urfin_grammar_abi`/`urfin_grammar`/`urfin_highlights`, запросы — из крейта грамматики), грузятся по требованию в фоне (`LoadLibraryExW` по абсолютному пути, `view::sys`), только папка установки, без сети. Разбор — `tree_sitter::Parser::parse_with_options` напрямую по тексту документа (ADR-0023 §7), общий для вьювера и редактора; `SyntaxHighlighter` gpui-kit не используется (ему нужен Rope всего текста). Вьювер: не-UTF-8 кодировки (UTF-16, однобайтовые) — перекодирование в UTF-8 с картой смещений (как у Markdown-документа), отрезки — по байтам источника; редактору (S7-35) — `InputEncoding::UTF16` и ASCII-заглушка по снимку. Язык — `urfin_view::lang`: имя файла (`Makefile`, `CMakeLists.txt`, `.gitignore`…), расширение, shebang; неизвестный — без подсветки.
- Цвета: захваты tree-sitter → роли `[syntax]` темы Урфина (`keyword`, `string`, `number`, `comment` + при необходимости `type`, `function`, `tag`, `heading` — правка `docs/THEMES.md` и всех встроенных тем), light/dark из темы (№59), не тема gpui-kit.
- **Любой размер — видимое окно** ([ADR-0024](../adr/0024-windowed-highlight.md), решение 2026-11-02): фоновый проход по файлу хранит контрольные точки состояния (каждые 64 КиБ); окно (видимое ± 64 КиБ) красится от ближайшей точки. JSON, TOML, INI, XML, HTML — свои лексеры `syntax/lex` (равенство tree-sitter + `highlights.scm` — дифференциальные тесты), окном при любом размере; YAML и Markdown — tree-sitter по отрезку от безопасной строки. Пакетные языки, PowerShell среди них, — трекер и tree-sitter по кускам (ADR-0024 §8), окном при любом размере; Bash до 16 МиБ (`MARKUP_MAX`) разбирается полностью, дальше — окном (`Lang::win_ok`). `editor.highlight = false` выключает подсветку в редакторе, во вьювере — режим Разметка (кроме Markdown-документа §3.10: он от tree-sitter не зависит).
- Вьювер и быстрый просмотр (Разметка): окно по видимой части; пока проход по файлу не дошёл до окна — без цвета. Стили — по байтовым диапазонам, при отрисовке накладываются на строки.
- Редактор: правка → точки после неё пересчитываются до совпадения состояния (обычно один кусок), окно — от точки перед правкой; до нового окна на экране только доказуемо верные цвета (ADR-0024 §4). Свёртка — из событий структуры лексера/трекера (скобки, таблицы TOML, элементы XML, отступы YAML, разделы и код Markdown), у пакетных — по узлам дерева; свёрнутое — слой отображения (раскладка пропускает диапазон), не правка.
- **Набор и вес** (оценка ≈ 3× сжатого крейта на crates.io; точный прирост `urfin.exe` меряет S7-21a по `ci/size.py`). Сейчас `urfin.exe` 27,31 МиБ при гейте 30 (CI main 2026-10-30).

Строка 36 под шапкой редактора (`screen-editor.png`, `screen-editor-md.png`; правила — DESIGN «Панель инструментов редактора»). Каждая кнопка — команда (через Command bus, как клавиша): подсказка — название и клавиша из активного keymap, состояние (disabled, active) — из документа.

- Disabled: Сохранить — документ не изменён и не новый; Отменить/Вернуть — нечего отменить / вернуть (журнал документа, ADR-0023 §4); Предпросмотр — файл > 16 МБ (подсказка «Файл больше 16 МБ»); всё, что правит текст, — read-only. ### 5.9 Markdown-команды и предпросмотр рядом (`md_edit.rs`)
Команды выполняет handler `editor` над кусками документа (ADR-0023), одной группой отмены, только для языка Markdown (в других файлах — не в палитре, клавиши не действуют).
- `editor.md.bold` / `italic` — обернуть выделение в `**…**` / `*…*`; уже обёрнуто — снять; без выделения — слово под курсором; не на слове — вставить пару, курсор между.
- `editor.md.heading {level?:Int}` — префикс строки `#`×N + пробел вместо прежнего; тот же уровень — снять; без `level` — меню H1–H3 и «Обычный текст» (0).
- `editor.md.list` / `numbered` / `task` — префикс `- ` / `N. ` (номера подряд от первого) / `- [ ] ` у каждой строки выделения; есть у всех — снять; другой тип списка — заменить.
- `editor.md.link` — выделение → `[выделение](|)`, курсор в скобках; выделение похоже на URL или путь → `[|](выделение)`; без выделения — `[](|)`.
- `editor.md.code` — выделение в одной строке → `` `…` ``; несколько строк → блок ```` ``` ```` вокруг них, курсор после открывающих кавычек (язык).
- `editor.md.table` — шаблон 3×2 (`| Столбец 1 | Столбец 2 | Столбец 3 |`, строка `|---|---|---|`, пустая строка), курсор в первой ячейке.
- **Предпросмотр рядом** (`editor.preview`, Ctrl+Shift+V): тело редактора делится пополам вертикальной чертой 1 `border` (перетаскивается, каждая часть ≥ 280; доля — `editor.preview_split`), справа — тот же рендер, что во вьювере (§3.10, S7-22a), поля 28. Мини-карта при предпросмотре скрыта. Разбор — после паузы 150 мс в правке, на Interactive lane по снимку документа (O(1); текст снимка ≤ 16 МБ собирается в строку для pulldown-cmark); прежний разбор отменяется. Прокрутка синхронная по смещениям блоков: верхняя строка текста → блок, содержащий её, наверх предпросмотра; прокрутка предпросмотра двигает текст так же; ведёт та сторона, которую прокрутил пользователь последней (без эха). Клик по флажку задачи в предпросмотре меняет `[ ]` ↔ `[x]` в тексте (одна undo-группа). Картинки — как во вьювере, относительно папки файла. Последнее состояние — `editor.preview` в настройках, применяется к следующему `.md`.

## 6. Рендер в GPUI (`gpui_shell/view`)

- Фичи окна по ADR-0022: `Viewer` и `Editor` (`impl ShellFeature`, по строке в `Features::new`). Экран документа — `Main::Replace` (как вкладка настроек): занимает область панелей, cmdline скрыт (`chrome::cmdline_hidden`), полоса вкладок показывает экраны (§3.9) — хук вкладок фичи по образцу `chrome::settings_tab`. Keybar остаётся, набор клавиш — по макету и контексту `viewer`/`editor` (Fluent `keybar-<id>`). Быстрый просмотр и `Placement::Panel` — тело пассивной панели (`quick.rs`). Слои — CONTRACTS «Терминал»: терминал → панели → cmdline → вьювер/редактор → оверлеи.
- Каркас вьювера (`screen-viewer.png`): шапка 36 — значок файла, путь к папке, чип «только чтение», справа чип кодировки «UTF-8 авто ▾» и сегменты «Текст | Разметка | Hex», чип «Слежение» при follow; имя файла — только во вкладке, размер, EOL и тип — в статусе (№61). Поле номеров 52 на `header` (номер — когда строка известна точно по индексу, иначе поле пустое). Строки 22 px. Полоса прокрутки 14 с бегунком, метки совпадений — при открытой строке «Найти» (§3.6). Строка состояния: слева «Стр 1–27 из 212 · 13 %» (или «стр ≈N», «индексация 41 %», «поиск 63 %»; в Hex — диапазон смещений), в середине — итог поиска при открытой строке «Найти», справа «9,4 КБ · CRLF».
- Строки — один `canvas` на видимую область (как сетка терминала `term_view.rs`). Каждый кадр — `rows_down` от `(top, top_sub)` по кэшу страниц; на `Missing` — скелетоны `fill.subtle.hover` и `pages.want()` → Loader. Прокрутка своя, без `overflow_scroll`; позиция бегунка = `top/len`.
- `rows.rs`: кэш `ShapedLine` (`window.text_system().shape_line`) на 2 экрана; ключ `(row.start, row.end, hscroll, spec_hash, style_epoch, hl_hash)`; подсветка (поиск, выделение, синтаксис) — `TextRun` в задании; прокрутка на строку переиспользует N−1 строк. Hit-test — `ShapedLine::index_for_x` + `RowText.map`, поэтому ширина запасных глифов не ломает выделение.
- Шрифт — моно окна (Cascadia Mono → Consolas, `ui.font_mono`, `type.mono` 13; CONTRACTS «Крейты»); запасные системные шрифты GPUI — для CJK и символов. Колонки — unicode-width.
- Бюджеты кадра (решение 2026-10-29, release, стенд): p50 ≤ 3 мс, p99 ≤ 6 мс на полный экран, кэш тёплый; прыжок (холодный экран) — p99 ≤ 6 мс; ввод ≤ 1 кадр. В простое кадров нет (кроме мигания курсора редактора при фокусе); follow, поиск и индекс будят UI не чаще 30 раз в секунду.
- Редактор (ADR-0023 §7): свой элемент правки `edit_view.rs` между полосой изменений и мини-картой — тот же `canvas` строк, что у вьювера: `rows_down` по `TextView` документа, кэш `ShapedLine` `rows.rs` (правка перестраивает только свои строки), hit-test, скелетоны на `Missing`; поверх — выделение, курсор, совпадения поиска, composition IME. Прокрутку и вывод курсора в видимую часть ведёт handler по `InboxMsg::Viewport` (как вьювер). Ввод — `EntityInputHandler` элемента (`InboxMsg::Input`), мышь — `InboxMsg::Caret`. Над ним — панель инструментов (`toolbar.rs`, §5.8); при предпросмотре вместо мини-карты — документ (`doc.rs`, §5.9).
- Меню и списки — «мешочки» от видимых источников (решение 2026-11-01, DESIGN «Общие правила»): экраны — от кнопки «Экраны» заголовка окна (хук заголовка фичи `Viewer`, как вкладки экранов), история — от кнопки «История» шапки вьювера/редактора или от пути активной панели, кодировка и режим быстрого просмотра — от чипов шапки области (`quick.rs`). Клавиша открывает ту же фигуру у той же кнопки; положение корешка берётся из раскладки кнопки (как `Measure` шапки вьювера), не из констант. Плашка без корешка по центру сверху (`lists.rs`) и плашка у края области (`menu_in_area`) снимаются — S7-25.
- Markdown-документ (`doc.rs`, §3.10): не `canvas` строк, а `gpui::list` блоков (div-дерево с `StyledText` и `TextRun` по стилям роли темы; картинки — `img`); тот же элемент — во вьювере, в быстром просмотре и в предпросмотре редактора. Подсветка поиска и выделение — `TextRun` поверх стилей.

   - (б) оставить как есть: S7-07 сверяет с `screen-viewer.png` только каркас, а S7-01b добавляет строки настроек по образцу соседних переключателей.
   **Рекомендация: (а)** — макеты — истина, и сверка снимков в D-07 иначе упрётся в расхождения.

## 14. Движок редактора — решено владельцем 2026-11-01

**Решено владельцем 2026-11-01** ([ADR-0023](../adr/0023-editor-engine.md) «Решено владельцем», [решение](../decisions/2026-11-01-editor-engine.md)); контракт ADR-0023 §9 одобрен:
1. Кодировка внутри — как в файле (§5.2, ADR-0023 §3).
2. Файл > 16 МиБ закрывается для записи другим программам сразу при открытии (§5.1).
3. История отмены держится всегда, и после сохранения (§5.2).
4. Подсветка — окном при любом размере, без лексера или трекера — ≤ 16 МБ (§5.7, ADR-0024).
5. Блочное выделение — в M4 (§5.2, S7-40/S7-40a); мультикурсор — после M4.
