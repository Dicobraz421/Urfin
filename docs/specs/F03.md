## 0. Ключевые решения

- **Решение:** два транспорта.
  - Файлы (`sftp://`) — свой клиент в `urfin-net` на `russh` + `russh-sftp` (S8 §5).
  - Терминал — системный `ssh.exe` (OpenSSH for Windows) в ConPTY как сеанс S6 (№85).

  **Почему:** SFTP нужен в процессе — для VFS, очередей и докачки. Терминал через `ssh.exe` даёт привычное поведение OpenSSH: `~/.ssh/config`, `ControlPersist` не нужен, agent forwarding, escape-последовательности. Свой PTY-канал не нужен.
- **Решение:** одна точка входа для секретов. Пароли, фразы-пароли, коды 2FA и ключи из менеджера паролей получает Урфин:
  - строкой `screen-sshpass`;
  - или командой менеджера паролей.

  Оба транспорта берут секреты из одной памяти сеанса:
  - SFTP — напрямую;
  - `ssh.exe` — через `SSH_ASKPASS` (`urfin.exe --askpass`, §2.7) и через агент Урфина на именованном pipe (`IdentityAgent`, §2.7).

  **Почему:** пароль вводится один раз на подключение. Ключ из менеджера не попадает на диск.
- **Решение:** доверие ключам серверов — общий `~/.ssh/known_hosts`, тот же, что у `ssh.exe`.
  - Неизвестный ключ — строка `screen-sshhostkey`.
  - Изменившийся ключ — строка `screen-sshhostchanged`: по умолчанию «Отмена», замена — только с вводом имени хоста.
  - «Только в этот раз» — временный файл сеанса, `ssh.exe` получает его вторым `UserKnownHostsFile`.

  **Почему:** одно решение пользователя действует для обоих транспортов и для внешнего `ssh`.
- **Решение:** сеть — только по явному действию пользователя:
  - «Подключить»;
  - Enter на профиле;
  - открытие сохранённого таба `sftp://` после Enter.

  При старте Урфин не подключается. Таб `sftp://` из сессии показывает «не подключено — Enter» (№85).
- **Решение:** адрес везде `sftp://<профиль>/путь` (№87). Полный `user@host:port` — в подсказке пути и в статусе. Ввод `sftp://user@host:port/путь` в адресную строку создаёт разовый профиль.
- **Решение:** подсветка вывода, мультивыполнение и запись показываются чипами в ближайшей свободной шапке над выводом (№91):
  - в терминале на весь экран — в пустом заголовке окна;
  - в паре — в шапке терминала;
  - в просмотре записи — справа в шапке, по образцу F3.

  Вывод не сдвигается. Сочетания экрана — в keybar (№88).
- **Решение:** политики (ADR-0020, №86, №89) применяются на лету:
  - `password_cache = false` — Урфин ничего не пишет в Диспетчер учётных данных и не читает из него, флажок «Запомнить» показан с замком;
  - `ssh.recording = required | forbidden | user`;
  - `ssh.multi_exec = false` — группа ввода недоступна.

## 1. Состав

**Входит (v1):**
- **Профили.**
  - `%APPDATA%\Urfin\connections.toml`.
  - Импорт `~/.ssh/config` и сеансов PuTTY — только чтение, живьём.
  - Меню дисков «SSH».
  - Новое подключение строкой.
  - Раздел настроек «Подключения».
- **Аутентификация:**
  - ключи Ed25519/ECDSA/RSA (OpenSSH-формат);
  - пароль;
  - keyboard-interactive (2FA);
  - агент OpenSSH (pipe `openssh-ssh-agent`) и Pageant — через них работают KeePassXC, 1Password, Bitwarden.
- **Прочее подключение:** jump-host (`ProxyJump`, цепочка до 3), keep-alive, переподключение.
- **Пароли:**
  - кэш в Диспетчере учётных данных — опция, выключается полностью; политика `password_cache`;
  - команда получения пароля с подстановками `{host}`, `{user}`, `{id}` и шаблоны: BearPass, Пассворк, 1Password, Bitwarden, KeePassXC;
  - ключ из записи менеджера — только в память.
- **Файлы `sftp://`:**
  - панель с колонками «Права» и «Владелец»;
  - F5/F6 с очередью и докачкой;
  - F7, F8, Shift+F6, ссылки (показ);
  - F3/F4 удалённых: скачать → открыть → закачать по F2;
  - сравнение и синхронизация локальная ↔ удалённая;
  - обрыв связи без потери панели.
- **Терминал:**
  - `ssh.exe` в ConPTY;
  - пара «панель + терминал» к одному профилю, папка по OSC 7, Ctrl+Tab;
  - подсветка вывода (Ctrl+Alt+H) для любого терминала и уровни в логах F3;
  - мультивыполнение (Ctrl+Alt+G);
  - запись asciicast v2 (Ctrl+Alt+R) и просмотр записи по F3.
- **Настройки:** «SSH», «Подключения»; строки F-03 в «Политиках».

**v2 (не в этом пакете):**
- перенаправление портов и SOCKS;
- «держать удалённую папку в актуальном состоянии» по явной команде;
- запись `.ppk` (чтение — через Pageant).

**Не делаем:**
- X11, RDP/VNC-туннели;
- Kerberos/GSSAPI;
- монтирование SFTP как диска Windows;
- обфускацию;
- динамические плагины (№85);
- автоматическую синхронизацию папки панель → терминал (§3.2).

## 2. Подключения и SFTP

### 2.1 Крейт `urfin-net`, фаза 3

Без `unsafe`: именованные pipe — через `tokio::net::windows::named_pipe`, Credential Manager — через `keyring`. Зависимости — запрос №4.

```
crates/net/src/
  lib.rs          — NetHandler (ns ssh, sftp), NetState (AppState.ext), register
  config.rs       — [ssh] (§2.9), connections.toml (§2.2)
  profile.rs      — Profile, ProfileSource, слияние config/PuTTY/свои
  import/         — ssh_config.rs (подмножество), putty.rs (реестр)
  conn/           — pool.rs, session.rs (russh client), jump.rs, keepalive.rs, reconnect.rs
  auth/           — agent.rs (OpenSSH pipe, Pageant), keys.rs, secrets.rs (память, zeroize),
                    vault.rs (keyring), pwcmd.rs (команда менеджера), kbi.rs (2FA)
  hostkey.rs      — known_hosts: проверка, добавление, замена, временный файл сеанса
  bridge/         — askpass.rs (pipe-сервер для --askpass), agent_srv.rs (агент Урфина для ssh.exe)
  sftp/           — vfs.rs (Vfs), list.rs, io.rs (open_read/open_write), longname.rs, ext.rs
  uri.rs          — sftp://<профиль>/путь ↔ Location; разбор user@host:port
crates/net/tests/ — testsrv: russh server + russh-sftp server в процессе (без сети вне 127.0.0.1)
```

Рантайм: один tokio current-thread на крейт (`spawn_dedicated`, S8 §5). Наружу — синхронный фасад `Vfs` и `MsgSink` в `NetState`. UI-поток в сокеты не ходит.

### 2.2 Профили и `connections.toml`

```toml
# %APPDATA%\Urfin\connections.toml — пароли и ключи сюда не пишутся
version = 1

[[profile]]
name = "web-prod-01"              # = authority в sftp://web-prod-01/…
host = "10.20.1.11"
port = 22
user = "deploy"
auth = "key"                      # agent | key | password | command
key = "~/.ssh/deploy_ed25519"
via = "bastion"                   # ProxyJump: имя профиля или user@host:port
start_dir = "/var/www/portal"
bookmarks = ["/var/log/nginx", "/etc/nginx"]
password_cmd = ""                 # пусто — из [ssh].password_cmd
password_id = ""                  # подстановка {id}
last_used = 2026-10-23T09:14:00Z

[[override]]                      # правки поверх импортированных (config/PuTTY)
name = "siem-collector"
auth = "command"
password_id = "srv-siem01"
```

**Источники:**
- **`config`** — `~/.ssh/config` и его `Include`. Читаются `Host` (без шаблонов `*?` и без `!`), `HostName`, `User`, `Port`, `IdentityFile`, `ProxyJump`, `ServerAliveInterval`. `Match` и прочие директивы игнорируются; в свойствах профиля — «не поддерживается: Match (строка N)».
- **`putty`** — `HKCU\Software\SimonTatham\PuTTY\Sessions\*`: `HostName`, `PortNumber`, `UserName`, `PublicKeyFile` (`.ppk` — подпись «ключ через Pageant»).
- **`urfin`** — свои профили.

**Правила:**
- Импорт — только чтение: файлы пользователя не меняются. Перечитывается при открытии меню дисков и раздела «Подключения» (mtime).
- При совпадении имён: `urfin` > `config` > `putty`. Конфликт показан в статусе раздела.
- Запись файла — атомарно (temp + rename), формат v1 фиксирован (запрос №7).

**История хостов** — `state/ssh/history.toml`: хост, пользователь, время. Это источник автодополнения поля «Хост» наряду с `config` и `known_hosts` (№70, `screen-sshnew`).

### 2.3 Подключение (`conn/`)

**Пул:** соединение на профиль, в нём каналы SFTP (S8 §5):
- листинг — 1 канал;
- передачи — до `[ssh].transfer_channels = 4`.

**Ход подключения (фазы в статусе `screen-sshhostkey`, «2 из 3»):**
1. TCP. Если задан `via` — канал `direct-tcpip` через уже поднятое соединение jump-хоста, рекурсивно, глубина ≤3.
2. Ключ сервера (§2.4).
3. Аутентификация (§2.5).

**Таймауты:** TCP — 10 с, аутентификация — 60 с (ожидание пользователя не считается).

**Keep-alive:** `keepalive@openssh.com` каждые `[ssh].keepalive_s = 30` (0 — выкл). Профиль из config берёт `ServerAliveInterval`. Пинг заголовка панели — RTT последнего keep-alive или листинга.

**Обрыв:** EOF, ошибка канала или 2 пропущенных keep-alive. Тогда:
- панель приглушена, листинг не стирается (`screen-sftplost`);
- строка `warning_bg` «Связь с srv1 потеряна · переподключение через N с (попытка k из M)» с кнопками «Переподключить сейчас» и «Отключиться»;
- попытки — `[ssh].reconnect = { tries = 5, interval_s = 3 }`;
- job S5 этого профиля переходят в «ждёт связи», после переподключения продолжаются с докачкой (§4.2);
- после исчерпания попыток — «Отключено» и «Переподключить».

Секреты из памяти сеанса используются повторно. Если их нет (2FA), снова показывается строка ввода.

Терминал и панель — разные соединения (№94): второе открывается только по требованию (открыли терминал к серверу, где уже есть панель, — или наоборот). При 2FA код спрашивается на каждое соединение; v2 — флажок профиля «Один вход».

### 2.4 Ключи серверов (`hostkey.rs`)

**Файлы:** `~/.ssh/known_hosts` и `~/.ssh/known_hosts2`. Хэшированные имена (`|1|`) поддерживаются. Записи `@cert-authority` и `@revoked` учитываются, остальные маркеры игнорируются.

**Сопоставление:** `[host]:port`, если порт ≠22, иначе `host`. Для jump — ключ каждого узла цепочки отдельно.

**Неизвестный ключ** (`screen-sshhostkey`, `warning_bg`): тип и `SHA256:` отпечаток.
- «Доверять и подключить» — добавить строку в конец `~/.ssh/known_hosts` (append, другие строки не трогаются).
- «Только в этот раз» — `state/ssh/run/<nonce>/known_hosts`, файл удаляется при отключении.
- «Отмена».

**Изменившийся ключ** (`screen-sshhostchanged`, `danger_bg`):
- показаны «было» (`known_hosts:N`) и «сейчас»;
- фокус на «Отмена»;
- «Заменить ключ и подключиться…» требует ввести имя хоста. Тогда меняется только строка N; файл переписывается атомарно, копия — `known_hosts.urfin-bak`.

`ssh.exe` получает `-o UserKnownHostsFile="<~/.ssh/known_hosts> <файл сеанса>" -o StrictHostKeyChecking=yes`. Тем самым ключ проверяет Урфин до запуска терминала, и `ssh.exe` вопросов не задаёт.

### 2.5 Аутентификация (`auth/`)

Порядок — по `auth` профиля. При `agent` — агент, затем ключи по умолчанию.

- **Агент:**
  - `[ssh].agent = auto | openssh | pageant`;
  - auto: сначала `\\.\pipe\openssh-ssh-agent`, затем Pageant (pipe Pageant ≥0.75, иначе WM_COPYDATA через функцию `russh` для Pageant);
  - в настройках — «найден OpenSSH · KeePassXC, 1Password, Bitwarden — через агент».
- **Ключ:** файл OpenSSH (Ed25519, ECDSA, RSA с `rsa-sha2-256/512`). Фраза-пароль — строкой `screen-sshpass`. `.ppk` не читается: подпись «загрузите ключ в Pageant».
- **Пароль и keyboard-interactive:**
  - каждый запрос сервера — строка `screen-sshpass` с текстом запроса (`Verification code:`);
  - для пароля есть «Из менеджера паролей ▾»;
  - «Запомнить» — только при `password_cache = true`.
- **Команда** (`pwcmd.rs`):
  - argv разбирается `shell-words`, подстановки `{host}`, `{user}`, `{id}` — отдельными значениями, без shell;
  - запуск — `term::proc::spawn_piped` (v6 №15), `CREATE_NO_WINDOW`, таймаут 30 с;
  - первая строка stdout — пароль; stdout целиком в PEM-формате — закрытый ключ;
  - код ≠0 — строка ошибки с хвостом stderr (≤200 символов, без stdout).
  - Шаблоны в «мешочке» (`screen-sshpass`):

    | Менеджер | Команда |
    |---|---|
    | BearPass | `bearpass get {id} --field=password` |
    | Пассворк | `passwork-cli get --password-id {id}` |
    | 1Password | `op read "op://Servers/{host}/password"` |
    | Bitwarden | `bw get password "{host}"` |
    | KeePassXC | `keepassxc-cli show -s -a Password db.kdbx {host}` |

    Синтаксис CLI BearPass и Пассворка сверяется на стенде в F03-03. Если CLI нет — шаблон показан, запуск даёт «команда не найдена».
- **Секреты в памяти** (`secrets.rs`):
  - `Zeroizing<String>` и `Zeroizing<Vec<u8>>`;
  - живут, пока открыт сеанс профиля, или `[ssh].secret_ttl_min = 0` (0 — до отключения);
  - в логи и трассировку не попадают;
  - паника в этом модуле не печатает значения.
- **Кэш** (`vault.rs`):
  - `keyring` → Windows Credential Manager, цель `Urfin/ssh/<user>@<host>:<port>`;
  - только при `password_cache` (политика) и флажке профиля;
  - выключение политики удаляет записи Урфина при следующем запуске (по префиксу `Urfin/ssh/`) — решение владельца №2 (§7).

### 2.6 Схема `sftp` (`uri.rs`, `sftp/vfs.rs`)

- `Location { backend: "sftp", authority: "<профиль>", path: "/abs/path" }` (запрос №1).
  - URI для показа и ввода: `sftp://<профиль>/путь` (№87).
  - Ввод `sftp://user@host:port/путь` ищет профиль с тем же `user/host/port`; если его нет — создаётся разовый профиль `user@host` с источником `history`.
- `caps`: `READ | WRITE | RENAME | SYMLINK_READ`. Без `WATCH`: обновление — по Ctrl+R и после своих операций (S4 кэш без watch).
- **Листинг:**
  - `READDIR` батчами (~100 записей), первый батч — первый кадр;
  - `longname` (SFTP v3) разбирается для имён владельца и группы; при неудаче — `uid/gid` числом;
  - права — `mode` в виде `drwxr-xr-x` (моно);
  - симлинки: `lstat` + `stat` цели, цель — в подсказке.
- **Колонки:** Имя · Размер · Изменён · Права · Владелец (`screen-sftppanel`) — через колонки схемы (v6 №1, распространение на не-виртуальные схемы — запрос №2). Данные — `Entry.ext`.
- **Заголовок панели** (`screen-sftppanel`):
  - чип «SSH» и путь `sftp://srv1/…`;
  - справа «N объектов · ping»;
  - в статусе одной группой (№92): «admin@srv1.corp.local · ssh-ed25519 · ключ из агента (Pageant)».
- Сессия сохраняет таб `sftp://` без подключения.

### 2.7 Мост к `ssh.exe` (`bridge/`)

- **`--askpass`.** Новый флаг app: ранний выход из `boot.rs`, без GPUI (запрос №5, как `--pkg-check`).
  1. `ssh.exe` запускается с `SSH_ASKPASS=<urfin.exe>`, `SSH_ASKPASS_REQUIRE=force`, `URFIN_ASKPASS=\\.\pipe\urfin-askpass-<nonce>`.
  2. Помощник подключается к pipe (DACL — текущий пользователь), передаёт текст запроса и печатает ответ в stdout.
  3. Урфин отвечает из памяти сеанса или показывает строку `screen-sshpass` над терминалом.
  4. Отказ — пустой ответ и код 1.
- **Агент Урфина.** Для ключей из менеджера (§2.5) Урфин поднимает pipe `\\.\pipe\urfin-agent-<nonce>` (протокол ssh-agent, сервер из `russh::keys::agent`, только эти ключи, только подпись). `ssh.exe` получает `-o IdentityAgent=<pipe>`. Pipe живёт, пока жив сеанс.
- `ssh.exe` ищется как `%SystemRoot%\System32\OpenSSH\ssh.exe`, затем в PATH. Версия — `ssh -V` (лениво, кэш `state/ssh/ssh_exe.toml`). Нужна ≥8.9 (`SSH_ASKPASS_REQUIRE`). Если ниже — подпись «обновите OpenSSH», терминал работает без моста (пароль вводится в самом терминале).

### 2.8 Меню дисков, новое подключение, настройки «Подключения»

- **Меню дисков** (Alt+F1/F2, `screen-sshdrives`) — группа «SSH».
  - Строки: профили (имя, `user@host`, «12 мин назад» или «не подключались»).
  - Действия:
    - Enter — подключить (`sftp.open`);
    - Ins — «Новое подключение…» (`ssh.new`);
    - F4 — изменить профиль;
    - Del — отключить.
- **Новое подключение** (`screen-sshnew`) — строка снизу, как F7.
  - Поля:
    - «Хост» — общий компонент поля с автодополнением (№70): `config`, история, `known_hosts`; общая часть `highlight`, источник справа; Alt+↓ — история хостов;
    - «Пользователь», «Порт», «Через»;
    - «Вход»: Агент / Ключ / Пароль / Команда;
    - флажок «Сохранить профиль».
  - Enter — подключить.
- **Настройки «Подключения»** (`screen-settings-conn`):
  - поиск и кнопки Добавить (Ins) / Изменить (F4) / Удалить (Del) / Импорт…;
  - таблица: Источник (метка `config`/`PuTTY` одной ширины) · Имя · Хост · Пользователь · Вход · Через · Последнее;
  - «Свойства» выбранного;
  - статус: `%APPDATA%\Urfin\connections.toml · N профилей · K из ~/.ssh/config · M из PuTTY`, «Пароли в файл не пишутся»;
  - Enter — подключиться, Shift+Enter — терминал.

### 2.9 Конфиг `[ssh]` (дефолты)

```toml
[ssh]
agent = "auto"                  # auto | openssh | pageant
```

## 3. Терминал

### 3.1 Сеанс `ssh.exe` (S6)

- Новый вид сеанса `SessionKind::External { argv, env, title }` (запрос №3). Интеграции 633 нет, фаза сразу `NoIntegration`: ввод raw (S6 §0, №88), строки ввода Урфина нет.
- OSC 7 и 1337 CurrentDir принимаются (S6 §1.3: «ssh» — сеанс без нашей интеграции).
- **argv:**
  - для профиля из config — `ssh.exe <Host>`;
  - для своих — `ssh.exe -p <port> [-i <key>] [-J <via-цепочка>] <user>@<host>`;
  - всегда: `-o UserKnownHostsFile=… -o StrictHostKeyChecking=yes`, плюс `-o IdentityAgent=…` при агенте Урфина;
  - env: §2.7.
- **Шапка терминала** (пара): кнопка «ssh srv1 ▾» — меню сеансов профиля и «Новый сеанс». В терминале на весь экран (Ctrl+O) шапка та же, заголовок окна отдан под чипы (№91).
- Выход `ssh.exe` (код ≠0) — строка `[соединение закрыто, код N]` и «Enter — переподключить».

### 3.2 Пара «панель + терминал» (`screen-sshpair`)

- `ssh.terminal {profile}` (Shift+Enter в «Подключениях», «Терминал» в контекстном меню панели `sftp://`): во второй половине окна сверху панель `sftp://`, под ней терминал того же профиля. Высота — сплиттер, по умолчанию 45/55.
- **Ctrl+Tab** (контекст `in_sshpair`, №88) — фокус панель ↔ терминал.
- **Папка терминал → панель:** OSC 7 от удалённой оболочки (`file://host/path`). Хост сверяется с профилем, путь нормализуется.
  - Если сервер OSC 7 не шлёт, в статусе «папка: сервер не сообщает». В справке — однострочник для bash/zsh.
- **Папка панель → терминал:** только явной командой `ssh.cd_here` («Перейти в терминале сюда», F9 и контекстное меню). Она шлёт `Ctrl+U` и `cd -- '<путь>'\r`. Автоматической синхронизации нет: ввод сырой, тихого cd нет (§7 №4).
- Статус пары одной группой: «ssh.exe · ключ ed25519 из агента | папка: /var/www/app ↔ панель | UTF-8 · 79×18».

### 3.3 Подсветка вывода (`screen-termhl`, `screen-sshpair`)

- Работает для любого терминала: SSH, pwsh, cmd, WSL. Переключатель — `term.highlight.toggle`, **Ctrl+Alt+H** (№88). Режим — нейтральный чип в шапке (№91), в статусе не дублируется.
- **Красится только неокрашенный текст:** ячейки с fg/bg по умолчанию и без SGR-цвета. Цвета программы (cargo, git, ls) не трогаются. Приглашение, уже окрашенное оболочкой, не трогается. В alt-screen (TUI) подсветка выключена.

| Правило | Пример | Роль |
|---|---|---|
| errors | `error`, `ERROR`, `FAILED`, `failed`, `fatal`, `panicked`, `Exception` | `danger` (t.k) |
| warnings | `warn`, `WARN`, `warning` | `context_remote` (t.rem) |
| success | `active (running)`, `ok`, `PASSED`, `succeeded` | `added` (t.ex) |
| paths | `/abs/x`, `~/x`, `C:\x`, `\\srv\x` | подчёркнуты `accent` |
| urls | `https?://…` | подчёркнуты `accent` |
| ip | IPv4/IPv6 с портом | подчёркнуты `accent` |
| dates | ISO 8601, `Oct 23 13:58:40`, `2026/10/23 14:02:31` | `secondary` |
| hashes | hex 7–64 символов на границе слова | `secondary` (выкл. по умолчанию) |

- **Исполнение:**
  - правила — один `RegexSet` по строке снапшота (S6 §1.5) только для повреждённых строк;
  - кэш по хэшу строки;
  - бюджет ≤0,3 мс на кадр при 50 изменённых строках;
  - результат — оверлей стилей поверх ячеек, `Term` не меняется.
- **Уровни в логах F3:** те же правила errors/warnings/dates во вьювере для файлов `*.log` и `.cast` (S7, режим «Текст»), переключатель — тот же Ctrl+Alt+H в контексте вьювера.

### 3.4 Мультивыполнение (`screen-sshmulti`)

- Только для SSH-сеансов. Недоступно при политике `ssh.multi_exec = false`: команды выключены, в keybar их нет (№88).
- **Ctrl+Alt+G** (`ssh.group.edit`) открывает терминал на весь экран с колонкой «Сеансы · группа ввода» шириной 200:
  - флажки сеансов, Пробел — в группу или из группы (`ssh.group.toggle`);
  - группа из ≥2 сеансов включает режим группы.
- **Вывод.** Справа стопка блоков по сеансам группы. Каждый блок:
  - заголовок: имя, IP, «код N», если сервер прислал OSC 133/633;D (не 0 — `danger`), иначе без кода;
  - снапшот последних строк его `Term`;
  - высота делится поровну, минимум 6 строк.
- **Ввод:**
  - каждый символ уходит во все PTY группы (`TermApi::broadcast`, запрос №3);
  - первый Enter после включения группы задерживается: над вводом строка «Отправить в 3 сеанса: `<набранное>`? Enter — да, Esc — нет» (`[ssh].multi_exec_confirm`); Esc шлёт `Ctrl+U` во все сеансы;
  - после подтверждения Enter идёт без вопросов, пока группа не изменится.
- **Esc** (`ssh.group.leave`) выходит из группы (вне строки подтверждения).
- **Чип** в заголовке окна (№91): «⚠ Ввод в N сеанса: srv1, srv2, srv3 | Выйти Esc».
- **Статус** одной группой: «Группа: 3 сеанса из 4 · первая команда подтверждена в 14:05».

### 3.5 Запись (`screen-sshrec`)

- **Ctrl+Alt+R** (`term.record.toggle`) — старт и стоп для текущего сеанса (SSH и локального).
  - Политика `ssh.recording` действует только на SSH-сеансы (§7 №2):
    - `required` — запись с первого байта, стоп недоступен, в keybar нет;
    - `forbidden` — команда выключена;
    - `user` — по `[ssh].recording`: `off` / `manual` / `always`.
- **Формат asciicast v2:**
  - заголовок `{"version":2,"width","height","timestamp","env":{"TERM","SHELL"},"title":"<профиль>"}`;
  - события `[t, "o", data]` — сырой вывод PTY до рендера;
  - resize — `[t, "r", "WxH"]`;
  - ввод (`"i"`) не пишется: пароли.
- **Файл:**
  - `<recordings_dir>\<профиль>-YYYY-MM-DD-HHMM.cast`;
  - буфер 64 КиБ, сброс раз в 1 с, `FlushFileBuffers` при остановке;
  - ошибка записи при `required` — строка `danger_bg` «запись невозможна — ввод заблокирован» и ввод в сеанс блокируется.
- **Чип** (№91): «● Запись мм:сс», при `required` — «🔒 обязательна · политика · TOML/GPO» (источник — из `PolicySet`), иначе в чипе «Остановить Ctrl+Alt+R».
- **Статус:** «Запись: `<путь>` · 1,2 МБ · asciicast v2».

### 3.6 Просмотр записи F3 (`screen-sshrecview`)

- Режим вьювера S7 `Cast` для `.cast`: переключатель «Запись / Текст / Hex» справа в шапке, рядом кнопка «Подсветка» (вкл. — `cursor` + рамка `accent`). Слева — путь папки и «только чтение». Образец — F3 (№91).
- **Плеер:**
  - события проигрываются в отдельный `alacritty Term` с размером из заголовка;
  - перемотка — повтор с начала до t; индекс ключевых смещений раз в 5 с ускоряет повтор;
  - бюджет перемотки ≤50 мс для файла 10 МБ.
- **Нижняя панель:**
  - ▶ (Пробел), время, шкала с ползунком и метками совпадений (`highlight`, текущее — `accent`), длительность;
  - скорость 1×/2×/4× (клавиши 1/2/4), ← → — ±5 с;
  - поиск: F7, общий компонент поля с историей (№70), Alt+↓, «N из M», Shift+F7 — следующее. Поиск идёт по тексту без VT, совпадение даёт время.
- **Текст** — вывод без VT. **Hex** — штатный режим S7.
- **Статус** одной группой (№92): «Сеанс admin@srv1 · терминал 132×30 · начало 23.10.26 14:02 UTC+3 · длительность 12:47 · asciicast v2, 1,2 МБ».

## 4. Файловые операции SFTP

### 4.1 Движок

S5 `Engine::Vfs` с записью через `open_write` (S8 §5): F5, F6, F7, F8, Shift+F6, атрибуты.
- **Перемещение внутри одного профиля** — `rename`, с `posix-rename@openssh.com`, если сервер его объявил.
- **Между профилями или с локальным диском** — копия + удаление.
- **Ограничения:** удалённые операции — полоса устройства «Сеть» (S5 §3.3, слоты «Сеть = 2», `screen-settings-ops`). Внутри задачи — до `transfer_channels` каналов.
- **Адреса** в строках F5/F6, job-баре и списке задач — `sftp://srv1/…` (№87). Путь назначения — общий компонент поля с историей путей (№70).

### 4.2 Докачка и целостность

- **Закачка:**
  1. Пишем в `<имя>.urfin-part` на сервере.
  2. После последнего байта — `fsync@openssh.com`, если объявлен.
  3. `rename` поверх (с `posix-rename`, иначе `remove` + `rename`, окно риска — в логе).
- **Скачивание** — по правилам S5 (`.urfin-part` локально, commit S5 §6.1).
- **Докачка** (после обрыва и при повторе job):
  - если part есть и не больше источника, сверяются последние 1 МиБ part и источника (xxh3);
  - совпало — продолжаем с конца part (`screen-sftpcopy`, «докачка с 61 %»);
  - нет — пишем заново.
- **Проверка после записи** (S5 §4.9): «Размер» — `stat`; «Хэш» — чтение назад и xxh3 (дорого, предупреждение в строке F5).
- **«Сохранить права и даты»** (флажок F5, по умолчанию вкл.) — `setstat` mode (только для удалённой цели) и mtime. Владелец не меняется.

### 4.3 F3/F4 удалённых файлов (`screen-sftpedit`)

1. Скачивание во временный файл `%LOCALAPPDATA%\Urfin\temp\sftp\<профиль>\<hash(path)>\<имя>` — job с прогрессом, для файлов >1 МиБ.
2. Открытие вьювера или редактора S7. У таба — чип «srv1».
3. **F2 в редакторе** — сохранение локально, затем закачка: строка «Закачка app.conf → srv1» с прогрессом, затем «готово» `added`. Закачка атомарная (§4.2), права файла сохраняются.
4. **Конфликт:** если mtime или size на сервере изменились с момента скачивания — строка конфликта S5 «Файл на сервере изменился» с кнопками Перезаписать / Сравнить / Отмена.
5. Временная папка удаляется при закрытии таба. Остатки старше 7 дней чистятся при старте.

### 4.4 Сравнение и синхронизация (`screen-sftpsync`)

- S5 §4.13 Quick для пары «локальная ↔ `sftp://`»: равенство по size и `|Δmtime| ≤ 1 с` (точность SFTP — секунды), подпись «точность 1 с». Content (хэш) — только по явному выбору, с предупреждением о чтении всего с сервера.
- Синхронизация — план S5: стрелки направления у строк, итог «Синхронизировать: → N файлов · размер». «Удалять лишнее на сервере» выключено по умолчанию (`delete_extra`).

## 6. Запросы к S0

1. **Схема `sftp`:** `Location.authority` = имя профиля, URI `sftp://<профиль>/путь` (№87). Уточняет запрос S8 №6 (`user@host:port` — только как ввод). Таб `sftp://` сохраняется в сессии без подключения.
2. **Колонки схемы (v6 №1) для не-виртуальных схем:** `sftp` объявляет «Права» и «Владелец», данные — `Entry.ext`. Публичный `Entry` не меняется.
3. **`urfin-term`, публичные безопасные API:**
   - `SessionKind::External { argv, env, title }` — без интеграции, фаза `NoIntegration`, OSC 7 доверен;
   - `TermApi::broadcast(ids, bytes)`;
   - отвод сырого вывода `TermApi::tap(id) -> TapRx` для записи;
   - флаг «цвет по умолчанию» у ячейки в снапшоте (S6 §1.5).
4. **Крейт `urfin-net` (фаза 3), без `unsafe`.** Зависимости:
   - `russh` и `russh-sftp` (Apache-2.0);
   - `tokio` (MIT): rt, net, io-util, time, sync; Windows named pipes;
   - `keyring` (MIT OR Apache-2.0, только Windows Credential Manager);
   - `shell-words` (MIT/Apache-2.0);
   - `zeroize` (уже в S8).

   Версии пинятся в F03-01 по `cargo-deny`. Рост exe — строкой в PR (№80).
5. **Флаг app `--askpass`:** ранний выход из `boot.rs` до GPUI, без окна, IPC единственного экземпляра не действует (как v6 №17).
6. **Команды и контексты keymap.**
   - Namespace `ssh`:

     | Команда | Клавиша |
     |---|---|
     | `ssh.new` | Ins в меню дисков |
     | `ssh.edit` | F4 |
     | `ssh.disconnect` | Del |
     | `ssh.reconnect` | — |
     | `ssh.terminal` | Shift+Enter в «Подключениях» |
     | `ssh.pair_focus` | Ctrl+Tab, контекст `in_sshpair` |
     | `ssh.cd_here` | — |
     | `ssh.group.edit` | Ctrl+Alt+G |
     | `ssh.group.toggle` | Пробел в списке сеансов |
     | `ssh.group.leave` | Esc, контекст `ssh_group` |

     Служебные (шлёт UI, без привязок keymap; решение владельца 2026-11-02):

     | Команда | Откуда |
     |---|---|
     | `ssh.connect {host, user?, port?, via?, auth?, save?, edit?, side?}` | Enter в строке «Новое подключение» (F03-05) |
     | `ssh.answer {choice, text?, remember?}` | ответ на вопрос подключения: ключ сервера, пароль, код; Esc — `choice=cancel` |
     | `ssh.remove {profile?}` | Del на своём профиле в «Подключениях» (импортированные не удаляются) |
     | `ssh.reload` | перечитать профили, историю хостов и `known_hosts` («Импорт…», меню дисков) |

   - Namespace `sftp`: `sftp.open {profile, path?}` (Enter на профиле), `sftp.refresh` (Ctrl+R).
   - `term` (S6): `term.highlight.toggle` (Ctrl+Alt+H), `term.record.toggle` (Ctrl+Alt+R).
   - `viewer` (S7): режим `Cast` и `viewer.cast.play` (Пробел), `viewer.cast.seek {s}` (← →), `viewer.cast.speed {1|2|4}`.
   - Контексты: `in_sftp`, `in_sshpair`, `ssh_term`, `ssh_group`, `cast_view`.
   - Ctrl+Tab в `in_sshpair` не конфликтует с `in_du` (№84), проверка `commands_doc`.
7. **Файлы на диске** (формат фиксирован):
   - `%APPDATA%\Urfin\connections.toml` v1;
   - `state/ssh/history.toml`;
   - `state/ssh/run/<nonce>/` (временные known_hosts);
   - `%LOCALAPPDATA%\Urfin\recordings\*.cast`;
   - `%LOCALAPPDATA%\Urfin\temp\sftp\`;
   - Урфин дописывает `~/.ssh/known_hosts` (append) и заменяет строку только по явному действию.
8. **Спаны tracing** (v5 №10): `net.connect`, `net.auth`, `net.hostkey`, `net.sftp.list`, `net.sftp.transfer`, `ssh.term.spawn`, `term.record`, `term.highlight`, `viewer.cast.seek`. Секреты в полях спанов запрещены (тест).
