# F01 — Анализ места: спецификация

Статус: draft v1 (2026-10-22). Основание: S0-decisions №81, №83, №84; `docs/01-ROADMAP.md` «Приоритетные фичи» F-01; дизайн `docs/design/DESIGN.md` (`screen-utilmenu`, `screen-du*`). Опирается на S4 (§5.6 `vfs.dir_size`, `urfin_vfs::walk`, §3.1 NtQuery), S5 (DeviceGate, Job, Корзина §4.7, xxh3), S8 (виртуальный VFS `search:` — образец для `du:`), ADR-0020 (политики удаления). Изменения контрактов — только через §6.

---

## 0. Ключевые решения

- **Решение:** подсчёт — только по явной команде (Ctrl+F9 → «Утилиты» → «Анализ места…», №81/№83). Нет фонового подсчёта, нет автозапуска при старте, нет индексатора.
  **Почему:** решение владельца; бюджет «0% CPU в простое».
- **Решение:** результат — снимок (`DuSnapshot`), кэш на диске в `%LOCALAPPDATA%\Urfin\state\du\`. Повторное открытие сразу показывает кэш с датой и «Обновить» (`screen-ducached`).
  **Почему:** повторный полный обход C: — десятки секунд; кэш читается за ≤100 мс.
- **Решение:** снимок хранит **каталоги** (агрегаты) и **крупные файлы** (≥ `track_min`, 1 МиБ). Мелкие файлы — только в агрегатах. Файлы текущего каталога вкладки дочитываются живым листингом (один каталог, Interactive).
  **Почему:** 1M файлов в памяти — 60+ МБ; каталогов ~300k (≈12 МБ), крупных файлов ~5–10% (≈3 МБ). Укладываемся в бюджет памяти.
- **Решение:** актуальность, по нарастанию стоимости:
  1. пока вкладка `du:` открыта — `ReadDirectoryChangesW` (поддерево корня), дочитка только затронутых каталогов;
  2. при повторном открытии, если есть права на том, — дочитка **USN-журнала NTFS** с сохранённого USN;
  3. без прав — перепроверка mtime каталогов снимка; «●» у изменившихся, «Обновить» пересчитывает только их.
  **Почему:** без прав полный обход — единственный честный способ; mtime-проверка дешевле его в разы (stat вместо листинга) и даёт пользователю выбор.
- **Решение:** размер по умолчанию — **на диске** (`AllocationSize`, с поправкой для сжатых/WOF), логический — в подсказке и переключателем `[du] size`.
  **Почему:** цель фичи — освободить место; сжатые, разреженные, облачные заглушки и резидентные в MFT файлы иначе врут в разы.
- **Решение:** жёсткие ссылки считаются один раз (битсет по номеру записи MFT), symlink/junction/mount point не обходятся (как S4 §6).
  **Почему:** WinSxS иначе удваивает «Windows»; ссылки дают циклы и чужие тома.
- **Решение:** удаление — существующий `ops.delete` (F8) в Корзину по правилам S5 §4.7 и политикам ADR-0020; своего удаления у F-01 нет.
  **Почему:** один путь удаления, одни политики, один журнал.
- **Решение:** каталоги без прав — «нет доступа: N папок · размер неизвестен». «Досчитать с правами администратора» — **отдельный процесс** через UAC, только чтение размеров, см. ADR-0021 (`docs/adr/0021-du-elevated-helper.md`, пишет другой исполнитель). Основной процесс никогда не повышается.
  **Почему:** минимальные привилегии; повышенный процесс без UI и без операций записи.
- **Решение:** без новых крейтов: движок — модуль `urfin_vfs::du`, UI — `urfin-ui` (`du_view`, `treemap`).

## 2. API

### 2.1 Типы

```rust
pub type DirId = u32;                       // индекс в DuTree/DuSnapshot; 0 — корень
pub struct DuNode {                         // 48 Б, repr(C), фиксированный размер (кэш)
    pub parent: DirId,                      // u32::MAX у корня
    pub name: NameRef,                      // (off: u32, len: u16) в арене UTF-8; ESCAPED — флаг
    pub file_id: u64,                       // FileId каталога (USN-маппинг), 0 — неизвестен
    pub disk: u64, pub logical: u64,        // агрегаты поддерева
    pub own_files: u32, pub files: u32,     // файлов в каталоге / в поддереве
    pub mtime: i64,                         // LastWriteTime каталога (mtime-перепроверка)
    pub flags: NodeFlags,                   // DONE, DENIED, PARTIAL_DENIED, CHANGED, LINK_SKIPPED
}
pub struct FileRec { pub dir: DirId, pub name: NameRef, pub disk: u64, pub logical: u64,
                     pub mtime: i64, pub file_id: u64, pub ty: DuType, pub attrs: u8 /*OFFLINE,COMPRESSED,HIDDEN,SYSTEM*/ }
#[repr(u8)] pub enum DuType { Video, Audio, Image, Doc, Archive, DiskImage, Exec, Code, Temp, Other }
pub struct TypeAgg { pub disk: [u64; 10], pub files: [u64; 10] }   // по всем файлам, включая мелкие

pub struct DuTree { /* сегменты по 4096 узлов, AtomicU64 disk/logical/files, AtomicU32 pending; читается без блокировок */ }
pub struct DuSnapshot {
    pub root: PathBuf, pub volume: VolumeKey,       // serial + FsKind
    pub scanned_at: i64, pub took_ms: u32, pub gen: u64,
    pub usn: Option<UsnMark>,                       // { journal_id: u64, next_usn: i64 }
    pub dirs: Vec<DuNode>, pub names: Vec<u8>,
    pub files: Vec<FileRec>,                        // только disk ≥ track_min, по убыванию disk
    pub types: TypeAgg, pub denied: Vec<DirId>, pub size_mode: SizeMode,
}
pub enum DuFilter { Dirs, Large, Types, Old, Dups, Temp }          // Ctrl+1…6
pub enum SizeMode { Disk, Logical }
pub struct DupGroup { pub size: u64, pub files: SmallVec<[u32; 4]> /*индексы FileRec*/, pub level: DupLevel }
pub enum DupLevel { Size, Partial, Full }                          // «только размер» / «совпадает по хэшу» (Full)
```

Конфиг `[du]` (дефолты):

| ключ | дефолт | смысл |
|---|---|---|
| `size` | `"disk"` | `disk` \| `logical` |
| `threads` | `0` | 0 = авто: NVMe 8, SSD 4, HDD 1, сеть 2 |
| `track_min` | `"1 MiB"` | порог файла для Крупные/Старые/Дубликаты |
| `old_age` | `"1y"` | порог «Старые» (6m / 1y / 2y / 5y в UI) |
| `dup_min` | `"1 MiB"` | меньше — в дубликаты не идут |
| `cache_max` | `"256 MiB"` | общий лимит `state\du\`, LRU по времени открытия |
| `cache_keep` | `8` | снимков максимум |

### 2.2 Кэш на диске

- Путь: `%LOCALAPPDATA%\Urfin\state\du\<serial:08x>-<xxh3_64(root нормализованный, lowercase):016x>.du`. В portable-режиме — тот же резолвер `state`, что у сессии (`<exe>\state\du\`).
- Формат v1, little-endian:

| секция | содержимое |
|---|---|
| заголовок | magic `URFDU\0`, `ver: u16 = 1`, `flags`, длина и CRC32 заголовка |
| meta | postcard: `root`, `VolumeKey`, `scanned_at`, `took_ms`, `usn`, `size_mode`, `track_min`, счётчики |
| dirs | `[DuNode; n]` как есть (repr(C), 48 Б) |
| names | арена UTF-8 |
| files | `[FileRec; m]` как есть |
| types, denied | postcard |
| трейлер | xxh3_64 всего тела |

- Запись: во временный `*.tmp` + `ReplaceFileW`/rename, Lane::Bulk, после завершения скана и после применённых изменений (не чаще 1/30 с, и при закрытии вкладки).
- Чтение: один `read` в `Vec<u8>`, секции dirs/files — копия без разбора. Битый трейлер или чужая `ver` → файл удаляется, открывается как «нет кэша».
- Сжатие в v1 нет (≈20 МБ на 300k каталогов) — см. §7 №5.

### 2.3 Схема `du:`

- `Location { backend: "du", path: "/<snap_id>/<rel>" }`, `snap_id` — индекс открытого снимка в `DuRegistry`; `rel` — путь от корня анализа. Фильтр — query: `du:/3/Users?f=large`.
- `DuVfs::list` (образец — `SearchVfs`, S8 §2): для `f=dirs` — подкаталоги из снимка (`Entry.size` = агрегат, `Attrs::SIZE_KNOWN`; у незавершённых — `SIZE_PARTIAL`, запрос §6 №4) + файлы живым листингом каталога (Interactive); для остальных фильтров — плоский список, `Entry.name` = `dir\name` (как VIRTUAL-панели, S0 v5 №18).
- `caps = VIRTUAL | READ_ONLY_DIR`; `stat`/`open_read`/`local_path` проксируются к реальному пути — поэтому F3, F4, F8, Alt+F7 работают штатно.
- Сортировка по умолчанию — Размер ↓. В сессии `du:` не сохраняется (как `search:`, v5 №8) — §7 №4.

## 3. Алгоритмы

### 3.1 Обход

- Job `kind: "du"` в `JobRegistry`, потоки — `spawn_dedicated` (S5 §0), слот `DeviceGate` физического диска: скан не дерётся с копией на том же HDD. Interactive — только листинг одного каталога (Enter, live-дочитка). Bulk — запись кэша.
- Планировщик — общий `urfin_vfs::walk` (S0 v5 №14), обобщённый до `walk_with(&dyn DirLister, …)`; пул `[du] threads` (авто через `volume::walk_threads` + класс `Media`).
- `NtLister` (NTFS/ReFS): handle каталога как в S4 §3.1, `NtQueryDirectoryFile(FileIdFullDirectoryInformation = 38)`, буфер 64 КиБ (первый вызов — 64 КиБ, т.к. первые строки не нужны). Из записи: имя, `EndOfFile` (логический), `AllocationSize` (на диске), `LastWriteTime`, атрибуты, `FileId`, тег reparse из `EaSize`. Открытие подкаталога — относительно handle родителя (`NtCreateFile` с `RootDirectory`), путь не собирается.
- `FindLister` (fallback при `STATUS_INVALID_INFO_CLASS` и т.п.): `FindFirstFileExW(FindExInfoBasic, FIND_FIRST_EX_LARGE_FETCH)`; нет `AllocationSize` и `FileId` → размер на диске = логический, округлённый до кластера; дедуп ссылок выключен; снимок помечается `APPROX`.
- `VfsLister` — прочие ФС (сеть, exFAT): `Vfs::list` как `dir_size`.
- Размер на диске: `AllocationSize`; для `COMPRESSED`/`SPARSE`/тега `WOF` и только при `disk ≥ track_min` — уточнение `GetCompressedFileSizeW`. `OFFLINE`/cloud-заглушки — 0 на диске, логический учитывается, файлы не открываются (без гидрации). Резидентные в MFT — 0.
- Жёсткие ссылки: `links.rs` — на NTFS атомарный растущий битсет по младшим 48 битам `FileId` (номер записи MFT, ≤ ~5M → ≤ 640 КБ); `test_and_set` = первая встреча считается, повторные — нет. ReFS (128-бит id) — шардированный `FxHashSet<u128>`. Приписывается первой встреченной ссылке; итог корня детерминирован.
- Ссылки: `REPARSE` c тегом SYMLINK/MOUNT_POINT — не входим, размер 0, `LINK_SKIPPED` у родителя (подсказка «пропущено ссылок: N»).
- Нет прав (`STATUS_ACCESS_DENIED`) — узел `DENIED`, у предков `PARTIAL_DENIED`, `denied.push(id)`.

### 3.2 Агрегация и частичные результаты

- `DuTree`: узел появляется при листинге родителя (`pending += 1` у родителя). После листинга каталога его файлы суммируются локально и одной атомарной прибавкой идут в узел и цепочку предков (глубина ~10 → ~3M `fetch_add` на 300k каталогов). Когда `pending` каталога и всех детей = 0 — `DONE`, вверх по цепочке.
- UI читает `DuTree` напрямую (видимые строки, атомики, без копий). Не `DONE` → «≥ X» цветом `secondary`. Обновление вкладки — тик `walk` раз в 100 мс: `listing_msg(Patch)` с `size` видимых каталогов (+ `Order` при сортировке по размеру), счётчик «N файлов · X ГБ» справа.
- Крупные файлы: на поток — min-heap; `FileRec` пишутся в поточные буферы, слияние в конце; во время скана «Крупные» показывает текущий топ.
- Конец: `DuTree` → `DuSnapshot` (O(n), без I/O), запись кэша, `Patch` финальный. Отмена (`du.stop`/Esc): ≤100 мс, снимок сохраняется с флагом `PARTIAL`, «Обновить» продолжает с нуля.

### 3.3 Актуальность (`fresh.rs`)

- **Live** (вкладка открыта): один `ReadDirectoryChangesW(root, bWatchSubtree=TRUE, FILE_NAME|DIR_NAME|SIZE|LAST_WRITE)` overlapped, поток ждёт в `WaitForMultipleObjects` (0% CPU). События → `DirId` по пути, debounce 250 мс, коалесцирование по каталогу → перелистать каталог (Interactive), дельта по агрегатам вверх, `gen += 1`. Переполнение буфера (`ERROR_NOTIFY_ENUM_DIR`) → весь снимок `CHANGED`, «Обновить». Последняя вкладка закрыта → наблюдатель снят, кэш записан.
- **USN** (повторное открытие, NTFS, права есть): `FSCTL_QUERY_USN_JOURNAL` на `\\.\X:`; `journal_id` совпал и `next_usn ≥ FirstUsn` → `FSCTL_READ_USN_JOURNAL` с сохранённого USN; `ParentFileReferenceNumber` → `DirId` (`FxHashMap<u64, DirId>` строится при загрузке) → множество затронутых каталогов → перелистать их; новые каталоги — дообход поддерева. Иначе (нет прав / журнал пересоздан / усечён) — mtime-путь.
- **mtime-перепроверка** (без прав): `GetFileAttributesExW` по каждому каталогу снимка (пул `threads`, DeviceGate), отличие mtime или исчезновение → `CHANGED` («●» `context_remote` у размера, `screen-ducached`). Ctrl+R перелистывает только `CHANGED` и дообходит новые поддеревья. Ограничение (в подсказке): рост существующего файла mtime каталога не меняет — его ловят только live/USN или полный скан (`du.refresh full`).

### 3.4 Карта (`treemap.rs`)

- Во второй (пассивной) панели — карта текущего каталога активной `du:`-вкладки (`screen-dumap`). 2 уровня: дети каталога; внутри каждого подкаталога — его дети. Файлы < `track_min` подкаталога — один блок «мелкие файлы».
- Раскладка — squarified (Bruls–Huizing–van Wijk, 2000): элементы по убыванию; строка вдоль короткой стороны остатка; элемент добавляется, пока худшее соотношение сторон строки не ухудшается, иначе строка фиксируется. O(n log n) из-за сортировки (у нас вход уже отсортирован → O(n)). Элементы < 16 px² сливаются в «прочее» (серый).
- Кэш: LRU на 8 раскладок, ключ `(DirId, gen_поддерева, w, h, scale)` → `Vec<Tile { rect: [f32;4], id, depth }>`. Пересчёт только при смене ключа; курсор/hover/отметка — отдельный слой поверх, без перераскладки.
- Рисование: quads GPUI; цвет — по `DuType` из ролей подсветки файлов темы (новых токенов нет), границы 1 px `panel`, подписи — где помещаются (≥ 2 строки текста по высоте). Курсор — рамка 2 px `text`; отмеченные — `cursor` со штриховкой; легенда типов внизу.
- Связь: курсор списка ↔ подсветка плитки; клик по плитке — курсор на строку; двойной клик / Enter на карте — вход; отметка с карты (Shift+ЛКМ) = отметка строки. Ctrl+Tab переключает фокус.
- Если > 5000 плиток — раскладка на cpu-pool, кадр рисует предыдущую.

Временные — правила (путь относительно корня анализа; совпадения подсвечиваются в «По папкам» тоже):

| правило | что это |
|---|---|
| `%TEMP%`, `%LOCALAPPDATA%\Temp`, `%WINDIR%\Temp` | временные файлы программ |
| `%WINDIR%\SoftwareDistribution\Download` | загрузки Windows Update |
| `%WINDIR%\ServiceProfiles\NetworkService\AppData\Local\Microsoft\Windows\DeliveryOptimization\Cache` | кэш доставки обновлений |
| `%LOCALAPPDATA%\CrashDumps`, `%WINDIR%\Minidump`, `%WINDIR%\MEMORY.DMP`, `%PROGRAMDATA%\Microsoft\Windows\WER\Report*` | дампы и отчёты об ошибках |
| `%LOCALAPPDATA%\Microsoft\Windows\Explorer\thumbcache_*.db` | кэш эскизов |
| `%LOCALAPPDATA%\{Google\Chrome,Microsoft\Edge,BraveSoftware\Brave-Browser}\User Data\*\{Cache,Code Cache,GPUCache}`, `%LOCALAPPDATA%\Mozilla\Firefox\Profiles\*\cache2` | кэши браузеров |

| `$Recycle.Bin` | Корзина (очищать через Корзину) |
| имена `*.tmp`, `~$*`, `*.dmp` вне правил выше | одиночные временные файлы |

### 3.6 Дубликаты

1. При входе в фильтр: группы `FileRec` по `logical` (≥ `dup_min`), без `OFFLINE`, без совпадающих `file_id` (жёсткие ссылки — не дубликаты). Уровень `Size`.
2. Сразу там же (часть явного действия «открыть фильтр», job `du.dups`, DeviceGate): xxh3-64 первых 64 КиБ каждого кандидата (`FILE_FLAG_SEQUENTIAL_SCAN`) → разбиение групп, уровень `Partial`. Файлы ≤ 64 КиБ получают сразу `Full`.
3. Ctrl+H / «Проверить хэшем N групп»: xxh3-128 целиком (поток 1 МиБ, тот же код, что S5 verify) → `Full` («совпадает по хэшу»). Отмена — Esc.
- Порядок в группе: самый старый mtime первым (вероятный оригинал). Автоотметка «все кроме первой» — только в группах `Full` (§7 №3). Сводка «освободится X» считает только отмеченное.

### 3.7 Отметка и удаление

- Отметка — штатная панельная (`accent` + полужирный). Строка сводки «Отмечено N · освободится X» + «Удалить в Корзину F8»; X — сумма `disk` отмеченного с учётом вложенности (отмеченный каталог поглощает отмеченных потомков).
- F8 → `ops.delete` по `Targets` (`local_path` от `DuVfs`): Корзина/насовсем по S5 §4.7 и ADR-0020 (`DeleteToTrash`). После операции ops перечитывает вкладку `du:`; удалённое вычитается из снимка **по перечитыванию** ([решение 2026-11-01](../decisions/2026-11-01-du-subtract-reread.md)), без пересчёта: «По папкам» — исчезнувшие подкаталоги и файлы (разница с прошлым листингом каталога), виды фильтров — строки, которых нет на диске при повторном листинге того же вида; из каталога, предков и сумм по типам. `Report.done` не используется; удалённое другими программами вычитается так же. `NoTrash`/ошибки — штатно в job-баре.

## 6. Запросы к S0

1. **Команды `du.*`** (§2.4): `du.open`, `du.refresh`, `du.stop`, `du.filter`, `du.map`, `du.verify_hash`, `du.elevate`, `du.old_age`; namespace `du`, handler в `urfin_vfs::du`. Привязки из №84: Ctrl+R, Ctrl+1…6, Ctrl+Tab, Ctrl+H; Esc — `du.stop` при активном скане.
2. **Keymap-флаг `in_du`** (панель на `du:`), по образцу `in_search` (S8): нужен, т.к. Ctrl+Tab, Ctrl+1…6, Ctrl+R, Ctrl+H вне `du:` значат другое.
3. **Схема `du:`** (§2.3): `Location { backend: "du", path: "/<snap_id>/<rel>" }`, query `f=`; `caps = VIRTUAL | READ_ONLY_DIR`; в сессии не сохраняется (как `search:`/`cmp:`, v5 №8).
4. **`Attrs::SIZE_PARTIAL`** — размер каталога ещё досчитывается («≥ X»). Рядом с `SIZE_KNOWN` (S4 запрос №5).
5. **Колонка `share`** (Доля: полоса + %) в наборе колонок S2; значение — `size / parent_total`, родитель задаёт `ListingService` через `Done{ total }` или Ext-состояние.
6. **Вид пассивной панели «карта»**: пассивная панель рисует провайдер, привязанный к активной вкладке (как quick view, v5 №3) — `ui::du::treemap`; фокус в неё по `du.map`.
7. **Формат кэша `state\du\*.du` v1** (§2.2) — фиксируется как формат на диске: смена — только с повышением `ver`, старое удаляется.
8. **`walk_with(&dyn DirLister)`** — расширение публичного `urfin_vfs::walk` (v5 №14); `walk` остаётся.
9. **Ext-состояние** для `DuState` (фильтр, сводка, баннеры) — механизм S5 запрос №4.
10. **Спаны tracing** (контракт v5 №10): `du.scan`, `du.first_rows`, `du.cache_load`, `du.layout`.

## 7. Решения для владельца

1. **Размер по умолчанию.** (а) на диске; (б) логический. Рекомендация: **(а)**, логический — в подсказке и `[du] size`.
2. **Порог отслеживаемых файлов `track_min`.** Меньше — не видны в Крупные/Старые/Дубликаты (только в суммах). Рекомендация: **1 МиБ** (память ≈3 МБ на C:); 64 КиБ — ≈4× памяти.
3. **Автоотметка дубликатов.** Дизайн: «отмечены все кроме первой». Рекомендация: отмечать только группы «совпадает по хэшу» (полный xxh3); «только размер» — без отметки, пока не нажат Ctrl+H.
4. **Сессия.** (а) `du:` не сохраняется, таб → корень анализа; (б) восстанавливается из кэша без скана. Рекомендация: **(а)**, как `search:`.
5. **Сжатие кэша.** v1 без сжатия (≈20 МБ на C:). Если мало — `lz4_flex` (новая зависимость, ≈50 КБ к бинарю).
6. **Полный пересчёт.** Ctrl+R — по «●», без «●» — полный. Нужна ли отдельная клавиша полного (предложение: Ctrl+Shift+R)?

## 8. Решено владельцем (2026-10-22)
- Размер — «на диске»; в снимок — файлы от 1 МиБ, мелкие — в суммах; вкладка `du:` в сессии не сохраняется (кэш — да); кэш без сжатия; Ctrl+R — пересчёт изменённого, Ctrl+Shift+R — полный.
- Дубликаты: автоотметка — только в группах, совпавших по полному хэшу. Группы «только размер» не отмечаются; Ctrl+H — проверить хэшем все непроверенные группы (или группу под курсором), после проверки совпавшие группы отмечаются (все копии кроме первой), несовпавшие — распадаются.
- Ограничение «рост файла без смены mtime папки» без прав — принято.
- ADR-0021: отдельный помощник, подпись кода обязательна, политики `DuElevatedHelper`/`DuElevatedMft`, найденное с правами — только показ.
