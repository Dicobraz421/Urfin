## 0. Ключевые решения

- **Решение:** поиск обходит дерево общим обходчиком `urfin_vfs::walk::walk_with` (S0 v5 №14), тем же, что у анализа места: листеры `NtLister`, `FindLister`, `VfsLister`, выбор — `pick_lister`, потоки — `volume::walk_threads`. Второго walker'а нет, `crossbeam-deque` и `ignore::WalkParallel` не берём.
  **Почему:** обходчик уже отдаёт размер, время и флаги без лишних syscall, открывает подкаталог относительно родителя и проверен F-01 на дисках на миллионы файлов; `DirVisitor::entry` даёт и пропуск каталога, и глубину через `tag`.
- **Решение:** экран поиска (`screen-search`) и панель результатов (`screen-searchpanel`, `-searchgrep`) — два вида одного `SearchStore`. Экран — строка на совпадение, панель — строка на файл с первым совпадением. Панель — виртуальный VFS `search:` (`Location { backend: "search", path: "/<id>" }`).
  **Почему:** так требуют макеты: «Найдено 9 совпадений в 7 файлах» и `scan.rs:88`, `scan.rs:131` на экране, «одна строка на файл» в панели. Панель как обычный листинг даёт стриминг, сортировку, отметку и F3/F5/F8 без новых контрактов core. Поиск (job) и вид разделены: уход из панели не отменяет поиск.
- **Решение:** поиск по содержимому — `grep-searcher` + `grep-regex` через `search_reader` поверх своего файла или `Vfs::open_read`. Mmap не используем. Режим «все кодировки» для литерала: игла кодируется в UTF-8, UTF-16LE, cp1251, cp866 (+ регистр как классы символов) и собирается в один байтовый regex.
  **Почему:** движок ripgrep — самый быстрый доступный; ripgrep сам не берёт mmap на обходе дерева, а `MmapChoice::auto` — `unsafe`, которого в `urfin-search` нет. Перекодировать файл в каждую кодировку — ×4 чтения, байтовая альтернатива — один проход. Кириллица в cp1251/cp866 — реальный сценарий (как в Far).
- **Решение:** своего MFT/USN-индекса нет (№38). M5b: ускоритель Everything IPC, если Everything запущен (только поиск по имени, результат сверяется со `stat`).
  **Почему:** служба с правами администратора — новая поверхность атаки; обход на NVMe даёт ≈1M файлов за 2–4 с, этого хватает на 95 % сценариев.
- **Решение:** архив — VFS-бэкенд по схеме (`zip`, `tar`, `7z`, `rar`) в `urfin-arc`. Адрес — `Location { backend: "zip", path: "/dir", outer: Some(<файл архива>) }`, вложенность — цепочка `outer` (≤ 8, `LocError::TooDeep`). При первом входе строится `ArchiveIndex`, кэш LRU по `(outer, size, mtime)`, лимит 256 МиБ.
  **Почему:** S4 заложил `Location.outer` и `VfsRegistry::register` ровно под это; индекс делает повторный вход и навигацию мгновенными.
- **Решение:** чтение по форматам: zip — random access по central directory; plain tar — индекс смещений; tar.gz/xz/zst/bz2, solid-7z и rar — последовательно, выборка извлекается одним проходом в порядке архива (`extract_plan`). Backend без `Caps::SEEK` отдаёт `VfsRead`, у которого `seek` — ошибка.
  **Почему:** в сжатом tar и solid-блоке произвольного доступа нет физически; один упорядоченный проход вместо N распаковок с начала — O(N) против O(N²). Вьювер такие источники уже умеет: нет `Caps::SEEK` — поток идёт через `SpoolSource`.
- **Решение:** запись (№40). M5a — только чтение: `ArcVfs` ставит `Caps::READ_ONLY`, ops отказывает до задачи (контракт), F4 в архиве открывает вьювер. M5b — создание новых архивов (`arc.add`, Shift+F1). Фаза 3 — изменение существующих через `Vfs::writer(at) -> VfsWriteTxn` ([решение «vfs-write»](../decisions/2026-11-04-vfs-write.md)). RAR не создаём никогда (запрещено лицензией UnRAR).
  **Почему:** чтение и извлечение покрывают основной сценарий; изменение архива — транзакционная перепаковка, а запись с позиции у контейнера невозможна (`open_write(Some(n))` — `NoWrite`).
- **Решение:** копирование из архива идёт существующим `Engine::Vfs` (`crates/ops/src/ops/vfs_copy.rs`, F03-07) с архивом как источником, новый движок не пишем. Сравнение папок — движок `ops/compare.rs`.
  **Почему:** конфликты, job-бар, очередь устройств и отчёт уже есть. Запись в архив остаётся запрещённой, чтение разрешает строка контракта (§9 №4).

## 2. Поиск (Alt+F7)

### 2.1 Запрос

```rust
#[derive(Clone, Debug, Serialize, Deserialize)] #[serde(default)]
pub struct SearchQuery {
    pub roots: Vec<Location>,       // поле «В»: путь или несколько через `;`
    pub name: Option<Mask>,         // поле «Имя»; пусто = всё
    pub text: Option<TextQuery>,    // поле «Текст»
    pub depth: Option<u16>,         // «Подкаталоги» выкл. = Some(0)
    pub kinds: KindFilter,          // Files | Dirs | Both; search.dirs = Dirs
    pub size: Option<(u64, u64)>,   // включительно
    pub mtime: Option<(i64, i64)>,  // нс
    pub hidden: bool,               // true
    pub skip_offline: bool,         // true: облачные (Attrs::OFFLINE) не открываем ради содержимого
    pub in_archives: bool,          // M5b
    pub accel: Accel,               // Auto | Off (M5b)
}
pub struct TextQuery {
    pub pattern: String,
    pub mode: TextMode,             // Literal | Regex (.*) | Hex
    pub case: bool,                 // Aa
    pub whole_word: bool,
    pub encoding: EncodingMode,     // All | Auto | Named(&'static Encoding)
    pub binary: bool,               // false: бинарные файлы пропускаются
    pub invert: bool,               // «не содержит»
}
```

- Форма макета задаёт только Имя, Текст, Aa, .*, В, Подкаталоги. Остальное — значения `[search]` и аргументы `search.run` (вопрос В3). Умолчание `encoding`: `All` для литерала, `Auto` для regex.
- `gitignore`, `name_regex`, обход по ссылкам и фильтр атрибутов из черновика сняты: в макете их нет, обходчик ссылки не обходит, `RawEntry` несёт только скрытый, системный, офлайн и сжатый. Вернуть можно вместе с В3.
- Порядок фильтров для записи (дешёвые первыми): kind → name → size/mtime (из `RawEntry`, без syscall) → content.
- Типы `SearchQuery` и `TextQuery` живут в `urfin-search`: UI передаёт поля плоскими аргументами `search.run`.

### 2.2 Обход

`urfin_search::walk` реализует `DirVisitor` поверх `walk_with`:

- `entry` фильтрует запись и возвращает `Some(глубина + 1)`, чтобы войти в каталог, `None` — пропустить; глубина лежит в `DirRef.tag`.
- `Acc` — буфер каталога; `done` прогоняет содержимое по его файлам, пишет попадания в store, ошибки каталога — в список для `search.errors`. Так хэндл каталога уже закрыт, пока читаются файлы.
- Корень: `pick_lister` по ФС (`Nt`, `Find`, `Vfs`), потоки — `walk_threads(cfg.threads, root)`; корни на разных носителях — свой проход на корень.
- Пропускаем `System Volume Information` и `$Recycle.Bin` (`[search] skip`). Ссылки на каталоги не обходятся — циклов нет.
- Ошибки доступа не останавливают обход: счётчик `denied`.
- Отмена — `halted` у `walk_with` (каждые 256 записей и между каталогами) и чтение файла кусками.
- Запуск — `Runtime::spawn_dedicated`, job `search`, `owner_ns: "search"`. `DeviceGate` поиск не берёт (вопрос В6).

### 2.3 Содержимое

- `ContentSearcher` на поток: `SearcherBuilder` — `line_number(true)`, `binary_detection(quit(0))` или `none`, если `binary`; чтение — `search_reader`, файл открывается путём `vfs::name::join_os`, не-локальный — `Vfs::open_read`.
- Sink собирает совпавшие строки файла (`[search] max_per_file`, 1000) и останавливается на лимите; при `invert` — одна запись на файл. Для каждой: номер строки, диапазон совпадения, фрагмент ≤ 120 символов, декодированный из кодировки совпадения.
- Матчер: `RegexMatcherBuilder` — `case_insensitive(!case)`, `word(whole_word)`, `fixed_strings(mode == Literal)`. Hex: `(?-u)\xAB\xCD…`.
- `EncodingMode::Auto`: `encoding(None)` + BOM-сниффинг (UTF-16 с BOM транскодируется). `Named(enc)`: `Searcher::set_encoding(Some(enc))`.
- `EncodingMode::All` (только Literal): игла в каждой кодировке; без учёта регистра каждый символ — класс байтовых последовательностей; итог — `(?-u)(?:utf8|utf16le|cp1251|cp866)`, дубли ASCII-игл схлопываются. Файл не транскодируется, поэтому бинарность решаем сами по первым 8 КБ: NUL и нет BOM UTF-16 — бинарный.
- Содержимое — только у локальных файлов и файлов с `Caps::SEEK`. Корень внутри архива без `SEEK` в M5a ищется по имени, содержимое — M5b (`extract_plan`).
- Облачные файлы (`Attrs::OFFLINE`) при `skip_offline` не открываются, иначе OneDrive начнёт скачивание.

### 2.4 SearchStore и SearchVfs

```rust
// urfin_core::search — чистые данные, без grep и I/O
pub struct SearchId(pub u32);
pub struct Hit { pub e: Entry /* name = rel path */, pub root: u16, pub line: u32,
                 pub hl: (u16, u16), pub preview: Option<CompactString> /* ≤120 симв. */, pub status: u8 /* cmp */ }
pub struct SearchStore {            // Arc, append-only, куски по ≤2048
    rows: RwLock<Vec<Arc<[Hit]>>>,  // экран: строка на совпадение
    files: RwLock<Vec<Arc<[u32]>>>, // панель: индекс первой строки файла
    pub info: SearchInfo,           // атомики: каталоги, файлы, найдено, denied, done, время
}
pub struct SearchModel { /* в AppState.ext: сторы по id, текущий на экране, история запросов, rev */ }
```

- Поток обхода сбрасывает попадания в store каждые 256 или 16 мс и будит окно (`MsgSink::poke`). UI берёт только видимое окно (рецепт «окно строк»), `rev` — как у `PkgFeed`.
- `SearchVfs::list(search:/id)` → `ListStream` по `files`: куски от курсора; нет новых и `!done` — ждёт с таймаутом 50 мс; `done` → `Ok(false)`. Стриминг и сортировка — штатные S4.
- `Vfs::resolve(base, item)` даёт реальный адрес (`roots[root]` + rel); `stat`, `open_read`, `local_path` проксируются. `caps = VIRTUAL | READ_ONLY`. Viewer, editor и ops разрешают элемент через `resolve`, новых веток вроде `du::dvfs::localize` не добавляем.
- `Vfs::columns`: без текста — Размер · Изменён; с текстом — `line` (Стр, 34, моно) · `hit` (Первое совпадение). `Vfs::ext` отдаёт `ExtCell::Text`; `hit` — новый `ExtCell::Snippet { text, hl }` и `ColumnView::Snippet` (§9 №3).
- `panel.refresh` (Ctrl+R «Перепроверить») на `search:` → параллельный `stat` попаданий на `Lane::Bulk`; исчезнувшие удаляются, изменённые обновляются через `Patch`. Watch — как у `du:`, hub не опрашивает.
- Жизнь стора: `TabEvent::Closed` последнего таба и закрытие экрана (Esc, новый поиск) → LRU (8 поисков, 64 МиБ); активная job держит store до конца. В сессии `search:` не сохраняется, таб восстанавливается в первый корень поиска.
- Память: `Hit` 104 Б; 1M попаданий ≈ 110 МиБ для поиска по имени, ≈ 240 МиБ для текстового ([решение 2026-11-06](../decisions/2026-11-06-s8-answers.md)). При `search.max_hits` (1M) поиск останавливается с баннером.

Экран (`screen-search`, DESIGN) — фича окна `Main::Replace`, один набор табов, как у вьювера. Фокус — `Focus::Overlay(OverlayKind::Search)` (§9 №3), поля формы — с автодополнением и историей (№70).

- Слева: форма 2 ряда, шапка «Файл | Совпадение» 24, строки `файл:строка` + фрагмент моно с `highlight`, внизу полоса 2 `accent` и итог «Найдено N совпадений в M файлах», «просмотрено K файлов · время».
- Справа: шапка 30 с путём и «стр N · предпросмотр», текст с номерами 44, строка совпадения — `current_line`, совпадение — `highlight`. Правило «подсветка только при открытой строке „Найти“» к предпросмотру не относится: это не строка поиска документа, на макете подсветка есть.
- Статус: «Поиск «…» в …», «N совпадений», «готово за X с».
- Keybar макета: Enter Перейти, F3 Смотр, F4 Ред, Ctrl+Enter В панель, Alt+F7 Новый поиск, Esc Закрыть. Enter в форме запускает поиск, Enter в списке — переход. Alt+F7 — к форме с выделенным текстом. Esc при идущем поиске отменяет его и закрывает экран, найденное остаётся: Alt+F7 возвращает последний поиск, новый запрос + Enter — новый поиск, прежний уходит в недавние (§2.4).

Панель (`screen-searchpanel`, `screen-searchgrep`):

- заголовок: чип «Поиск», запрос (`*.toml в C:\Dev` или `«Lane::Bulk» в …`), справа «найдено N · просмотрено M» или «N файлов · время», тонкий неопределённый прогресс под заголовком, пока идёт поиск; имя таба — запрос;
- имя рисуется как приглушённое `dir\` + `name` (§9 №7), статус показывает только имя файла;
- `..` нет; Enter и двойной клик по найденной папке — в настоящую папку (`OpenResolver::enter_dir`, [решение 2026-11-08](../decisions/2026-11-08-s8-esc-nav.md));
- keybar: Ctrl+PgUp К папке файла, Alt+F7 Изменить запрос; пока идёт — Ctrl+Break Остановить поиск; готово — F3 Смотр на совпадении, Ctrl+R Перепроверить;
- F3 — `viewer.open { path, line }` на совпадении, F4 — `editor.open { path, line }`; F5, F6, F8, отметка — штатные ops через `resolve` (вопрос В2).
- F5, F6 из результатов воссоздают в назначении путь от корня поиска. Корней несколько — путь начинается с имени своего корня (`core\src\lib.rs`, `ops\src\lib.rs`): последняя часть пути корня, при совпадении — ещё части слева (`a\src`, `b\src`; `C\x\src`, `D\x\src`), диск `D:\` — `D`; имя корня не бывает началом чужого ([решение 2026-11-08](../decisions/2026-11-08-s8-copy-roots.md)).

Флаги keymap: `in_search` (панель на `search:`, `cmp:`), `search_screen` (экран открыт). Поля прогресса job — троттлинг ≤ 30/с (S1).

### 2.6 Ускоритель Everything (M5b)

Если найдено окно `EVERYTHING_TASKBAR_NOTIFICATION` (Everything ≥ 1.4 запущен) и запрос без текста, он транслируется в синтаксис Everything (`path:"C:\x\" ext:rs size:>1mb`) и уходит через IPC (`WM_COPYDATA`). Ответ стримится в store; на каждое попадание — `stat_entry`. Опция `search.accel = "auto"|"off"`. Everything не входит в дистрибутив.

## 3. Архивы как VFS

### 3.1 Определение и вход

- `detect.rs`: по расширению (`zip, 7z, rar, tar, tgz, tar.gz, tbz2, tar.bz2, txz, tar.xz, tzst, tar.zst, gz, xz, zst, bz2`) и сигнатуре (первые 512 Б: `PK\x03\x04`/`PK\x05\x06`, `7z\xBC\xAF\x27\x1C`, `Rar!\x1A\x07\x00/01`, `ustar` @257, `1F 8B`, `FD 37 7A 58 5A 00`, `28 B5 2F FD`, `BZh`). Одиночные `.gz/.xz/.zst/.bz2` без tar внутри — псевдо-архив из одного файла.
- **Enter** (`panel.enter`, `OpenResolver`): S8 перехватывает только `[arc] enter_exts` (по умолчанию все архивные, без `docx, xlsx, pptx, odt, jar, apk, epub, nupkg, vsix` — они открываются в приложении ОС, №39). **Ctrl+Shift+PgDn** (`arc.enter`) — вход в любой файл по сигнатуре; сейчас клавиша есть только в пресете Far, нужна во всех (№39).
- Вход: `panel.go(Location { backend, path: "/", outer: Some(file) })`. Выход за корень — `Location::parent()` → `outer` с `pending_focus` на имя архива. Таб внутри архива восстанавливается, если файл архива есть.
- Флаг keymap `in_archive`.
- Вид (`screen-archive`): путь продолжается внутрь архива (`C:\Dev\urfin\urfin-0.4.2.zip\urfin-0.4.2`), метка формата рядом с путём, колонка «Сжато» 80, статус «имя · 1,2 КБ, сжато до 0,5 КБ · дата», справа «архив 8,9 МБ · сжатие 38 %». Колонки — `Vfs::columns`/`ext`, сводка — `urfin_core::arc::ArcModel` (§9 №3).

### 3.2 ArchiveIndex

```rust
pub struct ArchiveIndex {
    pub format: Format, pub outer_key: OuterKey /* loc, size, mtime */,
    names: NameArena,                       // все имена одним Vec<u8>
    nodes: Vec<Node>,                       // 0 = корень
    children: Vec<u32>,                     // CSR: Node.first_child..+n_children, отсортировано по имени
    pub encrypted: bool, pub solid: bool, pub comment: Option<Box<str>>,
}
#[repr(C)] pub struct Node { name: u32, parent: u32, first_child: u32, n_children: u32, kind: EntryKind, attrs: Attrs,
                             size: u64, packed: u64, mtime: i64, loc: EntryLoc /* zip: index; tar: data_offset; 7z: (folder, idx); rar: ordinal */ }
```

- Построение — job `arc.index` на `Lane::Interactive`, **стримится**. Zip и 7z: индекс готов после разбора оглавления. Tar.* и rar: `ListStream` корня отдаёт записи по мере чтения заголовков.
- Неявные каталоги создаются; при дублях имён побеждает последняя запись (как в 7-Zip).
- Пути: `\` и `/` → разделитель; абсолютные и `..` нормализуются лексически внутрь корня (zip-slip; ops всё равно проверяет dest).
- Кэш: `ArcCache` LRU по `OuterKey`, лимит 256 МиБ. Изменение файла архива → новый ключ. `ArcVfs::watch` подписывается на каталог `outer` через `LocalFs::watch` и шлёт `Gone`/`Overflow`.
- `caps`: всегда `READ_ONLY`; `SEEK` — у stored-записей zip и plain tar; `SEQUENTIAL` — tar.*, solid-7z, rar. `transfer_channels()` — число независимых читателей.

### 3.3 Форматы

**zip** (`zip` 9.4, `default-features = false`; features `deflate-flate2-zlib-rs`, `deflate64`, `bzip2`, `zstd`, `lzma`, `xz`, `ppmd`, `aes-crypto`):
- `ZipArchive::new(reader)` — central directory, ZIP64. Записи → `Node` (`EntryLoc::Zip(index)`).
- Имена: UTF-8 при флаге bit 11 или extra 0x7075; иначе `name_raw` декодируется OEM-страницей (`arc.zip_codepage = "auto"`, §1) через `encoding_rs`/`oem_cp`. Невалидное → `ESCAPED_NAME`.
- Время: extra 0x5455 → UTC; иначе DOS-время как локальное.
- Чтение: клон `ZipArchive` и свой reader на поток (SSD — 4, HDD — 1). Stored — поддиапазон с seek; сжатые — потоковый `VfsRead`, `len()` известен, `seek` — ошибка.
- Шифрование: AES-1/2 и ZipCrypto (§3.7).
- Многотомные `.z01` — не поддерживаются (сообщение).

**tar** (`tar` 0.4 + `flate2`, `zstd` 0.14, `lzma-rust2`, `bzip2` 0.6):
- Plain `.tar`: проход по заголовкам с seek → `EntryLoc::Tar(data_offset)`; чтение `seek + take(size)`.
- Сжатые: последовательный проход распаковкой, `SEQUENTIAL`. Выборка — один проход (`extract_plan`).
- PAX/GNU long names, sparse (GNU) — через `tar`; hardlink/symlink-записи → `LinkFile`/`LinkDir`.
- `.gz` multi-member (`MultiGzDecoder`).

**7z** (`sevenz-rust2` 0.24; features `aes256`, `bzip2`, `ppmd`, `zstd`, `lz4`, `brotli`, `deflate`; `compress` — только M5b):
- `Archive::read` → записи и папки (folders = solid-блоки). `EntryLoc::SevenZ { folder, index_in_folder }`. `solid` = есть folder с >1 файлом.
- Извлечение: план по folder; разные folder'ы — параллельно, внутри — последовательно, ненужные файлы распаковываются в никуда. Несолидный архив — фактически random access.
- Зашифрованные заголовки → пароль до листинга. Многотомные `.7z.001` — M5b.
- Запасной вариант при проблемах совместимости или скорости — `zesven` 3.x; выбор фиксирует бенч S8-37.

**rar** (`unrar` 0.5.8, feature `rar`, C++ UnRAR; сборка только MSVC, №57):
- Листинг: `open_for_listing` — RAR4/RAR5, многотомные (`open_for_listing_split`).
- Извлечение: `open_for_processing` → `read_header` → `extract_to`/`read`/`skip` строго по порядку; `SEQUENTIAL`; выборка — один проход. Цель `extract_to` — всегда наш временный или проверенный путь, имя из архива в UnRAR не передаём.
- UnRAR открывает файл по пути: вложенный rar сначала спиллится.
- Лицензия (№37): распаковка разрешена, создание RAR-совместимого архиватора запрещено; текст — в `THIRD_PARTY` и в комментарии исходника. Метаданные `unrar_sys` говорят `MIT OR Apache-2.0`, поэтому `cargo deny` UnRAR не заметит: нужен `[[licenses.clarify]]` на `LicenseRef-UnRAR` и исключение только для `unrar_sys`. Свежесть встроенного UnRAR — вопрос В7.

### 3.4 Вложенные архивы и спилл

- `open_read` на записи, которая сама архив: stored и outer seekable — поддиапазон без копирования; иначе спилл в `cache_dir/arc/<xxh3(outer-uri)>.<ext>` (удаляется при выходе из LRU и при старте — старше 24 ч).
- Лимиты против zip-бомб: `arc.spill_max` 4 ГиБ, `arc.ratio_max` 1000:1 на запись, вложенность ≤ 8 — при превышении вопрос «Распаковать N ГБ во временный каталог?».

### 3.5 Интеграция с ops (копирование из архива)

- `ops.copy` из архива идёт в `Engine::Vfs`: `End::of` принимает адрес с `outer` как источник; `End::writable` даёт `false` по `Caps::READ_ONLY`, так что цель в архиве отвергается до задачи (`ops-no-write`). Обход — `Vfs::list`, данные — `extract_plan(files)`, если backend его даёт, иначе `open_read`. Докачка `.urfin-part` — только при `Caps::SEEK` у источника.
- `extract_plan` (в коде — S8-21, по умолчанию `None`):
  ```rust
  pub trait ExtractStream: Send {
      /// Следующий файл в оптимальном для архива порядке. None — конец.
      fn next(&mut self, cancel: &CancelToken) -> Result<Option<(u32 /*индекс во входном списке*/, Box<dyn Read + '_>)>, VfsError>;
  }
  fn extract_plan(&self, files: &[Location], parallel: u8) -> Option<Vec<Box<dyn ExtractStream>>>; // по потоку на элемент Vec
  ```
- `ops.move` из архива — черновик копирования (контракт); `ops.delete` внутри архива — отказ `ops-no-write`.
- **`arc.extract`** (Shift+F2, `screen-extract`): встроенная строка по образцу F5 на всю ширину: «Распаковать <архив> · размер в» + путь другой панели; «В подпапку <имя>» (включена), «Если файл есть» (Спросить, Заменить, Пропустить, Заменить, если новее), «Сохранять пути» (включено), кнопки Распаковать Enter, В фоне Shift+Enter, Отмена Esc; keybar — Tab, Alt+↓ История путей. Работает на выделенном внутри архива и на выделенных архивах без входа; несколько архивов — job на архив, каждый в свою подпапку.
- **`arc.test`** (из `arc.commands`): job — полная распаковка в никуда и проверка CRC; итог — отчёт job.
- F3 (S7): `open_source` сам выберет `Owned` или `Spool` по `Caps::SEEK`. F4 в архиве — вьювер и тост «только чтение».

### 3.6 Создание архивов (M5b) и изменение (фаза 3)

- `arc.add` (Shift+F1, `screen-pack`, `-pack-pw`): строка на всю ширину по образцу F5: «Упаковать N · размер в», **формат слева** (`zip ▾`: `zip`, `7z`, `tar.zst`, `tar.gz`), имя с расширением в другой панели; сжатие Быстро/Обычно/Макс; «Пароль» → поле + «AES-256» (только zip/7z); solid — только 7z; «Удалить исходные после»; Упаковать Enter, В фоне Shift+Enter, Отмена Esc; keybar — Tab, Alt+↓ Список форматов.
- Job: обход выделенного → потоковая запись во временный файл рядом с целью → `rename`; цель на схеме с записью (`sftp://`) — временный локальный файл и `Engine::Vfs`. «Удалить исходные после» — штатный `ops.delete` только при успехе. Создание нового архива — не запись в схему: `Vfs::writer` тут не участвует.
- Фаза 3: `Vfs::writer(at) -> Box<dyn VfsWriteTxn>` — надстройка над методами записи ([решение «vfs-write»](../decisions/2026-11-04-vfs-write.md), CONTRACTS «VFS и операции»). `zip`, `7z` её переопределяют: шаги (`open_write(None)`, `mkdir`, `remove`, `rename`, `set_meta`) копятся, `commit` перепаковывает один раз, отмена — без следа. `open_write(Some(n))` у них — `NoWrite`, докачки нет; методы записи без транзакции — тоже `NoWrite`. Zip — новая центральная директория + `raw_copy_file` неизменённых записей, 7z и tar — пересборка. Тогда снимается `Caps::READ_ONLY`, и F5/F8/F7 внутри архива работают как в Far.

### 3.7 Пароли

- При Shift+F2 (`screen-extractpw`): чтение заголовка показывает строку пароля в самой встроенной строке — поле, «AES-256 · имена зашифрованы», ошибка `modified` «Неверный пароль — осталось N попытки». Три попытки.
- При входе в архив с зашифрованными именами, F3 и F5 — `JobHandle::ask` с `PromptSpec { input: Some(""), secret: true }`, те же три попытки (вопрос В5: макета нет).
- Пароль живёт в памяти до выхода индекса из LRU (`zeroize`), в логи, историю и сессию не попадает.

## 4. Сравнение каталогов

- Движок — `ops::compare` (S5 §4.13, S5-24; F03-07), команды `ops.compare {mode}`, `ops.sync`, итог — фича окна `gpui_shell/compare.rs`, `screen-compare`. Сравнивает листинги текущих папок, не рекурсивно; `sftp` работает через `end_checker`.
- M5a: разрешить сторону-архив (local↔архив, архив↔архив): `End::of` для чтения (§3.5), `end_checker` читает через `open_read`. Допуск времени: zip DOS-время — 2 с, как FAT; tar — 1 с; 7z — 100 нс.
- `ops.compare { recursive }` и панель `cmp:` (в контракте есть, в коде нет): различия пишутся в `SearchStore` с `status` (`only_left`, `only_right`, `newer_left`, `newer_right`, `differs`) и открывается `cmp:/id`. Функция остаётся в M5a: сначала макет панели сравнения поверх готовой панели поиска (D-12, после S8-11), затем S8-38, S8-39 (В4).
- Сравнение двух файлов (diff) не делаем, отдельной фичи и карточки нет (В8, [решение 2026-11-06 «s8-answers»](../decisions/2026-11-06-s8-answers.md)). Кнопка «Сравнить» в конфликте закачки остаётся вьювером версии на сервере ([решение 2026-11-04](../decisions/2026-11-04-sftp-compare.md)).
- Бюджет: Quick по 100k local↔local — бенч S5; local↔zip 10k файлов (Content) ≤1,3× распаковки.

## 5. Сеть

Вынесена в F-03 (`docs/specs/F03.md`, крейт `urfin-net`, `sftp://`). SMB — UNC через локальный backend. FTP, WebDAV, S3 не запланированы. Для S8 это значит одно: поиск и копирование из архива работают и на `sftp://` через те же `VfsLister`, `open_read`, один поток на корень.

## 6. Безопасность

- Zip-slip: имена нормализуются в индексе; ops при извлечении дополнительно проверяет, что dest остаётся внутри цели (`..`, абсолютные, `C:`, ADS `:`, зарезервированные имена → ошибка элемента).
- Symlink-записи из архивов извлекаются как ссылки только при `LinkMode::Preserve` и только если цель внутри dest; иначе — как файл с текстом цели.
- Пароли — §3.7.
- Mark-of-the-Web: при извлечении из архива с `Zone.Identifier` он копируется на извлечённые файлы (как Explorer) — опция `arc.propagate_motw = true`.
- Парсеры форматов — fuzz (S8-45, M5b).

## 9. Запросы к S0 — состояние на 2026-11-06

1. ✅ **Новые крейты и зависимости.** `urfin-search`, `urfin-arc` есть (заглушки). Зависимости — №58, CONTRACTS «Политика и бюджеты», карточки S8-00, S8-20, S8-33, S8-47. Снято: `crossbeam-deque`, `blake3`, `regex` напрямую, `ignore` в M5a.
2. ✅ **Общий walker в vfs.** `urfin_vfs::walk` (S0 v5 №14), на нём `dir_size`, `du`. S8 пишет только `DirVisitor`. S5 оставляет свой обход (`ops/engine/walker.rs`). Нужно: `pick_lister` сделать публичным (S8-01).
3. ✅ **Расширение trait `Vfs`.** `Caps::{READ_ONLY, SEQUENTIAL, VIRTUAL}` есть. `resolve` (S8-01), `extract_plan` + `ExtractStream` (S8-21) — в коде. `writer` — форма контракта, фаза 3. **Новое, класс B:** `ExtCell::Snippet` и `ColumnView::Snippet` (подсвеченная ячейка «Первое совпадение»), `OverlayKind::Search`, `urfin_core::search` (S8-01), `urfin_core::arc` (S8-21). `Caps::VIRTUAL` в коде описан как «`du:`, `pkg:`», нужна строка про `search:`, `cmp:`.
4. ✅ **`Engine::Vfs` для не-локального источника.** Движок есть (F03-07). CONTRACTS сейчас говорит: «`Caps::VIRTUAL` и адреса с `outer` — не через `Engine::Vfs`», а [решение «vfs-write»](../decisions/2026-11-04-vfs-write.md) — то же про путь записи. Для S8 нужно уточнение, класс B: запрет — на запись; источником адрес с `outer` быть может, адрес `search:` — через `resolve` (S8-01, S8-21). Сделано: `End::of` принимает адрес с `outer`, `End::writable` по `outer` — `false` (S8-21).
5. ✅ **`PromptSpec.secret`** — есть.
6. ✅ **Location:** `outer` ≤ 8, `LocError::TooDeep`, `>>` в `to_uri`, `authority`, `search`/`cmp` не в сессии — всё есть.
7. ⚠ **S2: виртуальные панели и формы.** Дополняется: `UiEvent::Ext` ids `search.screen`, `arc.draft`; `dir\` + `name` приглушённо в панели, колонка статуса `cmp` (В4), флаги `in_search`, `search_screen`, `in_archive` (S8-03, S8-23). Встроенные строки — `strip.rs`, а не inline-форма.

10. ✅ **Команды.** Id по S3: `search.files`, `search.dirs`, `arc.enter/extract/add/commands`, плюс `search.run/to_panel/cursor/view/edit/close/cancel/again/goto/errors`, `arc.test`. `ops.compare { recursive }` — в контракте, в коде нет (В4). Привязки дополняет S8-03, S8-23.
