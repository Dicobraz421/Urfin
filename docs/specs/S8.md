# S8 — Поиск, архивы, сеть: спецификация

Статус: draft v1 (2026-10-14). Владелец: S8. Опирается на specs/S1, S4, S5, S0-contracts-v2/v3/v4, S0-decisions. Чужие контракты меняются только через «Запросы к S0» (§9).
Версии крейтов сверены 2026-10-14: zip 9.0.1 (MIT, MSRV 1.88), tar 0.4, flate2 1.x (backend zlib-rs), zstd 0.13, lzma-rust2, bzip2 0.6 (чистый Rust), sevenz-rust2 0.24 (Apache-2.0), unrar 0.5.8 (обёртка C++ UnRAR), ignore 0.4.33, grep-searcher 0.1.17 / grep-regex / grep-matcher (Unlicense OR MIT), smb 0.12.1 (pre-1.0, только оценка).

Фазы: **M5a (MVP S8)** — поиск, архивы только на чтение (zip, tar.*, 7z, rar), извлечение, сравнение. **M5b (фаза 2)** — создание архивов, ускорители (Everything/Spotlight), поиск внутри архивов, многотомные. **Фаза 3** (после M6) — изменение существующих архивов, сетевые бэкенды, собственный MFT-индекс (если владелец одобрит).

## 0. Ключевые решения

- **Решение:** поиск обходит дерево своим параллельным walker'ом поверх `Vfs::list` (S4 fast paths: NtQueryDirectoryFile / getattrlistbulk / getdents+statx), work-stealing (crossbeam-deque). Из `ignore` берём только модуль `gitignore` (опция «учитывать .gitignore»), `WalkParallel` не используем.
  **Почему:** `ignore::WalkParallel` ходит через `std::fs::read_dir` (на Windows — FindFirstFile + stat на файл), теряет наши fast paths и не умеет Vfs (архивы, сеть). Листинг S4 сразу отдаёт size/mtime/attrs — фильтры по размеру/дате/атрибутам без лишних syscall.
- **Решение:** результаты поиска — виртуальный VFS `search:` (`Location { backend: "search", path: "/<id>" }`). `SearchVfs::list` отдаёт `ListStream`, который читает растущий `SearchStore` и ждёт новых попаданий до конца поиска. `Entry.name` = относительный путь от корня поиска.
  **Почему:** панель результатов — обычный листинг: стриминг, сортировка, выделение, F3/F5/F8 работают без новых контрактов core. Поиск (job) и вид (листинг) разделены: уход из панели не отменяет поиск, `panel.refresh` мгновенно отдаёт уже найденное.
- **Решение:** поиск по содержимому — `grep-searcher` + `grep-regex`. Локальные файлы — `search_path` (mmap ≥1 МиБ), остальные — `search_reader` поверх `VfsRead`. Режим «все кодировки» для литерала: игла кодируется в UTF-8, UTF-16LE, cp1251, cp866 (+ регистр как классы символов) и собирается в один байтовый regex; для regex-режима — UTF-8 + автоопределение BOM (UTF-16).
  **Почему:** движок ripgrep — самый быстрый доступный; перекодирование файла в каждую кодировку стоит ×4 чтения, а байтовая альтернатива — один проход. Кириллица в cp1251/cp866 — реальный сценарий пользователя (как в Far).
- **Решение:** собственный MFT/USN-индекс в M5 **не делаем**. Чтение MFT (`FSCTL_ENUM_USN_DATA`) требует handle тома `\\.\C:`, то есть прав администратора; Urfin работает без elevation. Фаза 2: ускоритель через Everything IPC, если Everything запущен (только поиск по имени, результат сверяется со `stat`). macOS: Spotlight (`MDQuery`, `kMDItemFSName`) — фаза 2, как источник «первых результатов», walker остаётся источником истины. Собственный MFT-индекс через службу — вопрос владельцу (§10).
  **Почему:** служба с правами администратора — новая поверхность атаки и установщик; выигрыш есть только для поиска по имени по всему диску. Walker на NVMe даёт ≈1M файлов за 2–4 с — для 95% сценариев (поиск в проекте/папке) этого достаточно. Spotlight неполон (исключения, нет скрытых, задержка индекса) — поэтому только ускоритель.
- **Решение:** архив — VFS-бэкенд по схеме (`zip`, `tar`, `7z`, `rar`) в новом крейте `urfin-arc`. Адрес — `Location { backend: "zip", path: "/dir", outer: Some(<файл архива>) }`, вложенность через цепочку `outer` (≤8 уровней). При первом входе строится `ArchiveIndex` (дерево каталогов, плотные массивы), кэш LRU по `(outer, size, mtime)`, лимит 256 МиБ.
  **Почему:** S4 заложил `Location.outer` и `VfsRegistry::register` ровно под это; индекс делает повторный вход и навигацию внутри архива мгновенными (без повторного разбора central directory/заголовков).
- **Решение:** чтение по форматам: zip — random access по central directory (`zip` 9.x, ZIP64, AES/ZipCrypto); plain tar — индекс смещений, чтение seek+take; tar.gz/xz/zst/bz2 и solid-7z — последовательный доступ, извлечение выборки одним проходом в порядке архива (`extract_plan`), одиночный файл (F3) — распаковка до него со спиллом во временный файл; rar — `unrar` (UnRAR, только чтение, поток заголовков).
  **Почему:** в сжатом tar и solid-блоке 7z произвольного доступа нет физически; один упорядоченный проход вместо N распаковок с начала — разница O(N) vs O(N²).
- **Решение:** запись в архивы: M5a — только чтение (F5 в архив → черновик с пояснением «архив только для чтения»). M5b — создание (`arc.add`, Shift+F1): zip (deflate/zstd), 7z (LZMA2), tar.zst/tar.gz, потоковой job. Фаза 3 — изменение существующих (zip — `raw_copy_file` неизменённых записей во временный архив и атомарная замена; 7z/tar — пересборка). RAR — никогда (запрещено лицензией UnRAR).
  **Почему:** чтение/извлечение покрывает основной сценарий; изменение архива — это транзакционная перезапись, ей нужен новый контракт `VfsWriteTxn` и ops-интеграция.
- **Решение:** сравнение каталогов — движок S5 (`ops.compare`, §4.13 S5). S8 даёт ему: общий walker по любому Vfs (архив ↔ папка), хэш через `VfsRead`, и рекурсивный режим с выводом различий в виртуальную панель `cmp:` (тот же `SearchStore`, поле статуса).
  **Почему:** один движок сравнения/синхронизации; S8 добавляет только то, что связано с Vfs и виртуальными панелями.
- **Решение:** сеть — Vfs-бэкенды в отдельном крейте `urfin-net` (фаза 3). SMB на Windows — через UNC и локальный бэкенд S4 (уже работает, плюс copychunk S5), на macOS — монтирование NetFS и локальный бэкенд; собственного SMB-клиента нет. SFTP — `russh` + `russh-sftp`, FTP/FTPS — `suppaftp`.
  **Почему:** ОС-клиент SMB быстрее, поддерживает Kerberos/DFS и серверное копирование; чистый `smb` 0.12 пока pre-1.0.

## 2. Поиск (Alt+F7)

### 2.1 Запрос

```rust
#[derive(Clone, Debug, Serialize, Deserialize)] #[serde(default)]
pub struct SearchQuery {
    pub roots: Vec<Location>,              // текущий каталог | выделенные | все диски (roots S4) | PATH
    pub name: Option<Mask>,                // Far-маска core::Mask; "*" по умолчанию
    pub name_regex: Option<String>,        // альтернатива маске (regex по имени)
    pub text: Option<TextQuery>,
    pub size: Option<(u64, u64)>,          // включительно
    pub mtime: Option<(i64, i64)>,         // нс
    pub attrs_set: u32, pub attrs_clear: u32,
    pub kinds: KindFilter,                 // Files | Dirs | Both
    pub depth: Option<u16>,
    pub follow_links: bool,                // false: junction/symlink не обходим
    pub hidden: bool,                      // true (поиск видит скрытые)
    pub gitignore: bool,                   // false
    pub skip_offline: bool,                // true: облачные (Attrs::OFFLINE) не открываем для content
    pub in_archives: bool,                 // M5b
    pub accel: Accel,                      // Auto | Off  (M5b)
}
pub struct TextQuery {
    pub pattern: String,
    pub mode: TextMode,                    // Literal | Regex | Hex
    pub case: bool, pub whole_word: bool,
    pub encoding: EncodingMode,            // Auto (UTF-8 + BOM) | All (UTF-8, UTF-16LE, cp1251, cp866) | Named(&'static Encoding)
    pub binary: bool,                      // false: файл с NUL в первых 8 КБ пропускается
    pub invert: bool,                      // «не содержит»
}
```

Порядок фильтров для записи (дешёвые первыми): kind → name → size/mtime/attrs (из `Entry`, без syscall) → content.

### 2.2 Walker

```rust
pub struct WalkOpts { pub threads: u8 /*0=авто*/, pub follow_links: bool, pub max_depth: Option<u16>, pub skip: SkipSet }
pub enum WalkEvent<'a> { Dir { loc: &'a Location, depth: u16 }, Entry { dir: &'a Location, e: &'a Entry }, Error { loc: &'a Location, err: VfsError } }
pub trait WalkVisitor: Send { fn visit(&mut self, ev: WalkEvent<'_>) -> WalkCtl; }   // Continue | SkipDir | Quit
pub fn walk(reg: &VfsRegistry, roots: &[Location], opts: &WalkOpts, cancel: &CancelToken, mk: impl Fn() -> Box<dyn WalkVisitor>);
```

- Очередь каталогов: `crossbeam_deque::Injector` + `Worker/Stealer` на поток; каталог листингуется целиком одним потоком (`Vfs::list` → `next_batch`), подкаталоги пушатся в локальный deque (DFS локально — кэш-дружелюбно, стелинг — BFS).
- Потоки: по `VolumeInfo.media` корня: NVMe/SSD — `min(8, cpus)`, HDD — 2, Net — 6, USB — 2. Через `Runtime::spawn_dedicated` (долгая задача, S0 v2 №7), завершаются вместе с job.
- По умолчанию пропускаются: reparse-точки каталогов (если не `follow_links`), `System Volume Information`, `$Recycle.Bin` (опция), на macOS `/System/Volumes/Data` дубль `/` при поиске от корня, на Linux `/proc`, `/sys`, `/dev`. При `follow_links` — детект циклов по `file_id`.
- Ошибки доступа не останавливают обход: счётчик `denied` в прогрессе, список — в `search.errors`.
- Отмена — проверка `cancel` между батчами: ≤ одного системного буфера.

### 2.3 Содержимое

- `ContentSearcher` на поток: `grep_searcher::SearcherBuilder` — `binary_detection(quit(0))` (или `convert` при `binary`), `memory_map(MmapChoice::auto())` только для local, `line_number(true)`, `stop_on_nonmatch(false)`; sink останавливается на первом совпадении (`Ok(false)`), фиксируя строку и номер. Для отчёта «сколько совпадений» — опция `count`.
- Матчер: `grep_regex::RegexMatcherBuilder` — `case_insensitive(!case)`, `word(whole_word)`, `fixed_strings(mode==Literal)`. Hex: `"(?-u)\\xAB\\xCD…"`.
- `EncodingMode::Auto`: `encoding(None)` + BOM-sniffing grep-searcher (UTF-16LE/BE с BOM транскодируются). `Named(enc)`: `Searcher::set_encoding(Some(enc))`.
- `EncodingMode::All` (только Literal): игла кодируется в каждую кодировку; для регистронезависимого поиска каждый символ → класс байтовых последовательностей `{lower, upper}` в этой кодировке; итог — `(?-u)(?:utf8|utf16le|cp1251|cp866)` в `RegexMatcher` (без транскодинга файла). Дубли альтернатив (ASCII-иглы) схлопываются.
- Чтение не-локальных файлов — через `Vfs::open_read`; для архивов в M5b — `extract_plan` (последовательно).
- Облачные файлы (`Attrs::OFFLINE`) при `skip_offline` не открываются (иначе OneDrive начнёт скачивание).
- Пул содержимого = потоки walker'а (файл ищется в том же потоке, где найден): меньше передач, естественный бэкпрешер. Для HDD (2 потока) — чтение не параллелится сверх этого.

### 2.4 SearchStore и SearchVfs

```rust
pub struct SearchId(pub u32);
pub struct Hit { pub e: Entry /* name = rel path */, pub root: u16, pub line: u32, pub preview: Option<CompactString> /*≤120 симв.*/, pub status: u8 /*cmp*/ }
pub struct SearchStore {           // Arc, append-only
    chunks: RwLock<Vec<Arc<[Hit]>>>,   // куски по ≤2048, без копирования при чтении
    len: AtomicU32, done: AtomicBool, notify: (Mutex<()>, Condvar),
    pub query: SearchQuery, pub roots: Vec<Location>, pub progress: Arc<Progress>,
}
pub struct SearchRegistry { /* FxHashMap<SearchId, Arc<SearchStore>>, LRU 8 завершённых */ }
```

- Walker пишет попадания в локальный буфер потока, сбрасывает в store каждые 256 попаданий или 16 мс → `notify_all`.
- `SearchVfs::list(search:/id)` → `ListStream`: отдаёт куски от курсора; при отсутствии новых и `!done` ждёт `Condvar` с таймаутом 50 мс (проверка cancel); `done` → `Ok(false)`. Стриминг/Batcher/сортировка — штатные S4.
- `stat`/`open_read`/`local_path` проксируются к реальному `Location` (root + rel). `caps` = `VIRTUAL | READ_ONLY_DIR` (запрос №3).
- `panel.refresh` на `search:` → перечитывание store + параллельный `stat` попаданий (Lane::Bulk, ≤8 потоков); исчезнувшие удаляются, изменённые обновляются (идут как `Patch`). Watch — `Unsupported` (hub не поллит виртуальные — запрос №3).
- Жизненный цикл: `TabEvent::Closed` последнего таба со store → store в LRU (8 последних поисков, лимит 64 МиБ); активная job держит store до конца. В сессии `search:` не сохраняется — таб восстанавливается в первый корень поиска.
- Память: `Hit` ≈64 Б + имя; 1M попаданий ≈90 МиБ. При превышении `search.max_hits` (1M по умолчанию) — поиск останавливается с баннером.

### 2.6 Ускорители (M5b)

- **Windows / Everything IPC:** если найдено окно `EVERYTHING_TASKBAR_NOTIFICATION` (Everything ≥1.4 запущен) и запрос — только имя/размер/дата без текста, запрос транслируется в синтаксис Everything (`path:"C:\x\" ext:rs size:>1mb`) и отправляется через IPC (`WM_COPYDATA`, Everything SDK). Ответ стримится в store; для каждого попадания — `stat_entry` (проверка существования и метаданных). Опция `search.accel = "auto"|"off"`. Everything не входит в дистрибутив.
- **macOS / Spotlight:** `MDQueryCreate` с `kMDItemFSName like[cd] "<mask>"`, `MDQuerySetSearchScope(roots)`, асинхронно; первые результаты (обычно <100 мс) пишутся в store с дедупом по пути, параллельно идёт обычный walker, который досчитывает полноту. Content — не через Spotlight (неполнота для кода/скрытых).
- **MFT/USN (Windows, фаза 3, только при решении владельца):** служба `urfin-indexd` (LocalSystem), `FSCTL_ENUM_USN_DATA` (`MFT_ENUM_DATA_V0`) → таблица FRN→(parent, name, attrs), поддержка через `FSCTL_READ_USN_JOURNAL`; клиент — named pipe с ACL текущего пользователя, выдача фильтруется проверкой доступа (`AccessCheck`) — иначе утечка имён чужих файлов.

## 3. Архивы как VFS

### 3.1 Определение и вход

- `detect.rs`: по расширению (`zip, jar*, 7z, rar, tar, tgz, tar.gz, tbz2, tar.bz2, txz, tar.xz, tzst, tar.zst, gz, xz, zst, bz2`) и сигнатуре (первые 512 Б: `PK\x03\x04`/`PK\x05\x06`, `7z\xBC\xAF\x27\x1C`, `Rar!\x1A\x07\x00/01`, `ustar` @257, `1F 8B`, `FD 37 7A 58 5A 00`, `28 B5 2F FD`, `BZh`). Одиночные `.gz/.xz/.zst/.bz2` без tar внутри — псевдо-архив из одного файла (имя без суффикса).
- **Enter** (`file.open`, цепочка S0 v3 №9): S8 перехватывает только расширения из `[arc] enter_exts` (по умолчанию все архивные, **без** офисных/пакетных `docx, xlsx, pptx, odt, jar, apk, epub, nupkg, vsix`) — те открываются в приложении ОС. **Ctrl+Shift+PgDn** (`arc.enter`) — вход в любой файл по сигнатуре.
- Вход: `panel.go(Location { backend, path: "/", outer: Some(file) })`. Выход за корень — `Location::parent()` → `outer` с `pending_focus` на имя архива (S1 уже так определяет `parent`).
- Флаг keymap `in_archive`.

### 3.2 ArchiveIndex

```rust
pub struct ArchiveIndex {
    pub format: Format, pub outer_key: OuterKey /* loc, size, mtime */,
    names: NameArena,                       // все имена одним Vec<u8>
    nodes: Vec<Node>,                        // 0 = корень
    children: Vec<u32>,                      // CSR: Node.first_child..+n_children, отсортировано по имени при построении
    pub encrypted: bool, pub solid: bool, pub comment: Option<Box<str>>,
}
#[repr(C)] pub struct Node { name: u32, parent: u32, first_child: u32, n_children: u32, kind: EntryKind, attrs: Attrs,
                             size: u64, packed: u64, mtime: i64, loc: EntryLoc /* zip: index; tar: data_offset; 7z: (folder, idx); rar: ordinal */ }
```

- Построение — в job `arc.index` (Lane::Interactive для первого экрана, потом продолжение): **стримится**. Для форматов с оглавлением в конце (zip, 7z) индекс готов сразу после разбора; для tar.*/rar — `ListStream` корня отдаёт записи по мере чтения заголовков (первые строки tar.gz без ожидания конца).
- Неявные каталоги (запись `a/b/c.txt` без `a/`) создаются; при дублях имён побеждает последняя запись (как в 7-Zip).
- Пути: `\` и `/` → разделитель; абсолютные (`/x`, `C:\x`) и `..` нормализуются лексически внутрь корня (защита от zip-slip при извлечении — ops всё равно проверяет dest).
- Кэш: `ArcCache` LRU по `OuterKey`, лимит по байтам индекса (256 МиБ), `TabEvent::Left` не нужен — индекс живёт, пока в LRU. Изменение файла архива (mtime/size) → новый ключ. Watch: `ArcVfs::watch` подписывается на каталог outer (через S4) и шлёт `Gone`/`Overflow` при изменении файла.

### 3.3 Форматы

**zip** (`zip` 9.0.1, features `deflate`(zlib-rs), `deflate64`, `bzip2`, `zstd`, `lzma`, `xz`, `ppmd`, `aes-crypto`):
- `ZipArchive::new(reader)` — разбор central directory (ZIP64 поддержан). Записи → Node (`EntryLoc::Zip(index)`).
- Имена: UTF-8 при флаге bit 11 или extra 0x7075; иначе `name_raw` декодируется OEM-кодовой страницей (`arc.zip_codepage = "auto"`: Windows `GetOEMCP()`, иначе cp437; при RU-локали — cp866) через `encoding_rs`/`oem_cp`. Невалидное → экранирование `ESCAPED_NAME` (S0 v2 №5).
- Время: extra 0x5455 (UT) → UTC; иначе DOS-время как локальное.
- Чтение: `by_index_seek`/`by_index` на собственном клоне `ZipArchive` (клон делит метаданные) и собственном reader'е — для параллельного извлечения N читателей (SSD — 4, HDD — 1). Stored-записи отдают `VfsRead` с seek (поддиапазон outer), сжатые — потоковый `VfsRead` без seek (`len()` известен).
- Шифрование: AES-1/2 и ZipCrypto; пароль — `JobHandle::ask` с `PromptSpec { input: Some(""), secret: true }` (запрос №5), хранится в памяти на время жизни индекса; неверный пароль → повторный вопрос (3 попытки).
- Многотомные `.z01` — не поддерживаются (сообщение).

**tar** (`tar` 0.4 + `flate2` с `zlib-rs`, `zstd` 0.13, `lzma-rust2` (XZ), `bzip2` 0.6):
- Plain `.tar`: проход по заголовкам с seek через данные (без чтения данных) → `EntryLoc::Tar(data_offset)`; чтение — `seek + take(size)`, random access, параллельно.
- Сжатые: последовательный проход распаковкой (данные пропускаются чтением); `caps |= SEQUENTIAL`. Извлечение выборки — один проход (`extract_plan`). F3 на одном файле — распаковка до него, если файл ≤64 МиБ — в память, иначе спилл.
- PAX/GNU long names, sparse (GNU) — через `tar`; hardlink/symlink-записи → `LinkFile`/`LinkDir` (при извлечении — S5 `LinkMode`).
- `.gz` multi-member (`MultiGzDecoder`).

**7z** (`sevenz-rust2` 0.24, features `aes256`, `zstd`, `brotli`, `lz4`, `bzip2`, `deflate`):
- `Archive::read` → записи и папки (folders = solid-блоки). `EntryLoc::SevenZ { folder, index_in_folder }`. `solid` = есть folder с >1 файлом.
- Извлечение: план группируется по folder; разные folder'ы — параллельно (каждый в своём потоке и своём reader'е), внутри folder — последовательно, ненужные файлы распаковываются в /dev/null. Несолидный архив — фактически random access.
- F3 на файле в solid-блоке — распаковка блока до файла со спиллом.
- Зашифрованные заголовки → пароль до листинга. Многотомные `.7z.001` — M5b (склеивающий reader).
- Запасной вариант при проблемах совместимости/скорости — `zesven` 3.x (MIT/Apache, parallel); выбор фиксирует бенч S8-17.

**rar** (`unrar` 0.5.8, feature `rar`, C++ UnRAR):
- Листинг: `open_for_listing` (заголовки, данные пропускаются seek'ом) — RAR4/RAR5, многотомные (`open_for_listing_split`).
- Извлечение: `open_for_processing` → `read_header` → `extract_to`/`read`/`skip` строго по порядку архива; `caps |= SEQUENTIAL`; выборка — один проход (`extract_plan`).
- Только локальный outer (UnRAR открывает файл по пути): вложенный rar сначала спиллится.
- Лицензия UnRAR: использование для распаковки — без ограничений; запрещено создавать RAR-совместимый архиватор (не делаем); текст лицензии — в `THIRD_PARTY` и в комментарии исходника. cargo-deny: исключение `LicenseRef-UnRAR` только для `unrar_sys`. Решение о включении в официальную сборку — владелец (§10).

### 3.4 Вложенные архивы и спилл

- `open_read` на записи архива, которая сама архив: если запись stored и outer seekable — поддиапазон без копирования; иначе спилл в `cache_dir/arc/<blake3(outer-uri)>.<ext>` (удаляется при выходе из LRU и при старте — чистка старше 24 ч).
- Лимиты против zip-бомб: `arc.spill_max` 4 ГиБ, `arc.ratio_max` 1000:1 на запись, вложенность ≤8 — при превышении вопрос «Распаковать N ГБ во временный каталог?».
- Индекс вложенного архива строится по спиллу/поддиапазону как обычно.

### 3.5 Интеграция с ops (копирование из архива)

- `ops.copy` из архива в локальную ФС: S5 видит не-локальный `base` и использует `Engine::Vfs` (запрос №4): обход — общий walker по `Vfs::list`, данные — `extract_plan(files)` если бэкенд его даёт (порядок архива, параллель по folder/читателям), иначе `open_read` на файл. Конфликты, verify, журнал, прогресс — штатные S5.
- `extract_plan` (запрос №3):
  ```rust
  pub trait ExtractStream: Send {
      /// Следующий файл в оптимальном для архива порядке. None — конец.
      fn next(&mut self, cancel: &CancelToken) -> Result<Option<(u32 /*индекс во входном списке*/, Box<dyn Read + '_>)>, VfsError>;
  }
  fn extract_plan(&self, files: &[Location], parallel: u8) -> Option<Vec<Box<dyn ExtractStream>>>; // по потоку на элемент Vec
  ```
- `ops.move` из архива в M5a — только копия (черновик предлагает «Копировать»); `ops.delete` внутри архива — `Unsupported` до фазы 3.
- **`arc.extract`** (Shift+F2): `ops.copy` выделенного из архива или **выделенных архивов** (без входа) в пассивную панель; опции черновика: «в подкаталог по имени архива» (по умолчанию для нескольких архивов), «без путей», пароль, политика конфликтов. Для архивов из панели — `Location` строится как `{backend, "/", outer: file}`, далее тот же `Engine::Vfs`.
- **`arc.test`** (из `arc.commands`): job — полная распаковка в никуда + проверка CRC; отчёт в job-баре.
- F3/F4 (S7) по файлу в архиве: `open_read` (seekable — сразу; иначе спилл ≤64 МиБ в память). F4 на файле в архиве в M5a — только просмотр (редактирование требует записи).

### 3.6 Создание архивов (M5b) и изменение (фаза 3)

- `arc.add` (Shift+F1): inline-черновик (S2): имя, формат (`zip`|`7z`|`tar.zst`|`tar.gz`), уровень, пароль (zip AES-256 / 7z AES-256 + шифрование заголовков), «solid» для 7z, многопоточность (zstd `multithread`, 7z — LZMA2 по блокам). Job: walker по выделенному → потоковая запись во временный файл рядом → атомарный rename (журнал S5 для temp).
- Фаза 3: `VfsWriteTxn` (запрос №3, фаза 3): `put(rel, meta, reader)`, `mkdir`, `delete`, `commit()`. Zip — новая центральная директория + `raw_copy_file` неизменённых записей (без перепаковки), 7z/tar — пересборка. Тогда F5/F8/F7 внутри архива работают как в Far.

## 4. Сравнение каталогов

- Движок и команды — S5 (`ops.compare {mode}`, `ops.sync`). Вход — две панели (активная/пассивная) любых Vfs: local↔local, local↔архив (проверка распаковки), архив↔архив.
- S8 даёт: общий walker (§2.2) для не-локальных сторон, content-хэш xxh3 через `VfsRead`/`extract_plan` (для solid-архивов — один проход), и **рекурсивный режим**: `ops.compare { recursive=true }` пишет различия в `SearchStore` с полем `status` (`only_left`, `only_right`, `newer_left`, `newer_right`, `differs`) и открывает виртуальную панель `cmp:/id` (имена — относительные пути). F5/F8 из неё — штатные ops через `resolve` (запрос №3).
- Нерекурсивный режим — как в S5 (подсветка/выделение в самих панелях).
- Время в архивах: zip DOS-время — точность 2 с, допуск как у FAT (S5 §4.13); tar — 1 с; 7z — 100 нс.
- Бюджет: Quick по 100k local↔local — S5 бенч #15; local↔zip 10k файлов (Content) ≤1,3× распаковки.

## 5. Сеть (архитектура, фаза 3, без задач MVP)

- Крейт `urfin-net`, бэкенды Vfs: `sftp` (`russh` + `russh-sftp`), `ftp`/`ftps` (`suppaftp`), позже `webdav`, `s3`. SMB — средствами ОС (Windows UNC через локальный бэкенд; macOS `NetFSMountURLSync` → локальный путь; Linux — gio/cifs mount), собственного SMB-клиента нет; `smb` 0.12 пересмотреть в фазе 3+.
- Адрес: `Location { backend: "sftp", path: "/home/u/x" }` + authority в URI `sftp://user@host:22/home/u/x` (запрос №6, фаза 3).
- Потоки: один tokio current-thread runtime на крейт (`spawn_dedicated`), синхронный фасад `Vfs` (каналы); пул соединений на хост (листинг — 1 канал, передачи — до 4 каналов SFTP), keep-alive, переподключение с `ops`-ретраями S5 (транзиентные ошибки).
- `ListStream` — батчи `READDIR` (SFTP отдаёт ~100 записей за ответ); кэш S4 без watch, `poll` по команде refresh.
- Учётные данные: `keyring` (Windows Credential Manager / macOS Keychain); known_hosts — `~/.ssh/known_hosts` + свой файл; ssh-agent / Pageant / ключи из `~/.ssh/config`.
- Копирование: `Engine::Vfs` S5 (тот же, что для архивов) + запись через `VfsWriteTxn`-подобный `open_write` (фаза 3).
- Закладки соединений — в настройках профиля; пароли в конфиг не пишутся.

## 6. Безопасность

- Zip-slip: имена нормализуются в индексе; S5 при извлечении дополнительно проверяет, что dest остаётся внутри цели (`..`, абсолютные, `C:`, ADS `:`, зарезервированные имена → `InvalidName`).
- Symlink-записи из архивов извлекаются как ссылки только при `LinkMode::Preserve` и только если цель внутри dest; иначе — как файл с текстом цели.
- Пароли — только в памяти (`zeroize` при выходе из LRU), в логи/историю не попадают.
- Mark-of-the-Web: при извлечении из архива с `Zone.Identifier` (Windows) он копируется на извлечённые файлы (как Explorer) — опция `arc.propagate_motw = true`.
- Парсеры форматов — в fuzz-тестах (cargo-fuzz, S9).

## 9. Запросы к S0

1. **Новые крейты и зависимости.** `urfin-search`, `urfin-arc` (фаза 3 — `urfin-net`). Зависимости: ignore 0.4.33 (только `gitignore`), grep-searcher 0.1.17, grep-regex, grep-matcher, regex, encoding_rs, oem_cp, crossbeam-deque, zip 9.0.1 (**MSRV workspace ≥1.88**), tar 0.4, flate2 (feature `zlib-rs`), zstd 0.13 (C, `zstd-sys`), lzma-rust2, bzip2 0.6, sevenz-rust2 0.24, unrar 0.5.8 (feature `rar`, C++; cargo-deny `LicenseRef-UnRAR` только для `unrar_sys`), zeroize. Фаза 3: russh, russh-sftp, suppaftp, keyring.
2. **Общий walker в vfs.** `urfin_vfs::walk::{walk, WalkOpts, WalkVisitor, WalkCtl}` поверх `Vfs::list` — единый для S8 (поиск, сравнение), S4 (`vfs.dir_size`), S5 (обход не-локальных источников). S5 сохраняет свой sys-walker для local или мигрирует по бенчу. Реализует S8-02.
3. **Расширение trait `Vfs`** (дефолты не ломают S4):
   - `fn resolve(&self, base: &Location, item: &str) -> Result<Location, VfsError>` — дефолт: join; для `search:`/`cmp:` — реальный адрес попадания. ops и S7 разрешают элементы виртуальных панелей только через него; `OpRequest.items` может содержать относительные пути с разделителями.
   - `fn extract_plan(&self, files: &[Location], parallel: u8) -> Option<Vec<Box<dyn ExtractStream>>>` — дефолт `None` (§3.5).
   - `Caps`: `READ_ONLY`, `SEQUENTIAL` (нет дешёвого random access), `VIRTUAL` (search/cmp: WatchHub не поллит, DirCache не кэширует).
   - Фаза 3: `fn writer(&self, dir: &Location) -> Result<Box<dyn VfsWriteTxn>, VfsError>`.
4. **S5: `Engine::Vfs` для не-локального источника** — обход через walker (№2), данные через `extract_plan`/`open_read`, dest — только local в M5a (не-local dest → `Unsupported` → черновик «только чтение»). `ops.move` с `READ_ONLY`-источником предлагает копию. Разграничение: S5 реализует движок, S8 — `extract_plan` бэкендов (S8-14).
5. **`PromptSpec.secret: bool`** — маскированный ввод (пароли архивов), не пишется в историю/логи/сессию.
6. **Location:** глубина `outer` ≤8 (`LocError::TooDeep`); экранирование `>>` в именах в `to_uri`; схемы `search`, `cmp` (не сохраняются в сессии — таб восстанавливается в первый корень поиска / левую сторону сравнения); вкладка внутри архива восстанавливается, если файл архива существует. Фаза 3: authority в URI (`sftp://user@host:port/path`).

8. **S7:** `viewer.open { pos?: Int /*байт*/, line?: Int }` — открыть на позиции совпадения; просмотр файлов из архива через `Vfs::open_read` (seekable или спилл).

## 10. Решения для владельца

1. **RAR в официальной сборке.** Чтение RAR возможно только через C++ UnRAR (лицензия не OSI: распаковка разрешена бесплатно, создание RAR запрещено). Включить чтение RAR в официальную сборку? *Рекомендация S8: да, только чтение, с текстом лицензии в «Сторонние компоненты».*
2. **Мгновенный поиск по всему диску на Windows.** Собственный индекс MFT требует службы с правами администратора (ставится установщиком, работает постоянно). Варианты: (а) не делать — обычный параллельный поиск (≈2–4 с на диск NVMe) + использовать Everything, если он установлен (фаза 2); (б) своя служба-индексатор в фазе 3. *Рекомендация S8: (а).*
3. **Enter на документах-архивах.** `.docx/.xlsx/.jar/.apk/.epub` технически zip. Enter открывает их в приложении ОС, а внутрь — Ctrl+Shift+PgDn (как в Far). *Рекомендация S8: да.*
4. **Объём записи в архивы.** M5: только просмотр и извлечение; создание архивов (Shift+F1: zip, 7z, tar.zst) — фаза 2; копирование/удаление внутри существующих архивов (как в Far) — фаза 3. *Рекомендация S8: принять этот порядок.*
