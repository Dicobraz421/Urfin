## 0. Ключевые решения

- **Решение:** гейты в CI — только детерминированные метрики: число инструкций (gungraun/valgrind, ubuntu), число аллокаций (считающий аллокатор), размер бинаря, корректность. Wall-time в CI — A/B на одном раннере (base и head в одном job) с мягким порогом. Абсолютные бюджеты (мс, МБ/с, RSS, против Explorer) проверяются **только на стенде**.
  **Почему:** shared-раннеры дают разброс 10–30% по времени, абсолютные мс там бессмысленны; инструкции стабильны до ±0,5% при закреплённом toolchain.
- **Решение:** self-hosted раннер на стенде **не используем**. Стенд гоняет `xtask perf` вручную/по расписанию Windows, результаты коммитятся JSON-ом в `docs/perf/runs/`. PR, меняющий горячие пути vfs/ops/term, обязан приложить прогон стенда (CI-проверка `perf-evidence`).
  **Почему:** self-hosted раннер на публичном репо исполняет код из чужих PR на ноуте владельца — неприемлемо по ИБ.
- **Решение:** один генератор данных — dev-крейт `urfin-testdata` (publish=false, детерминированный ChaCha8 по сиду), используется и `examples/gen_tree.rs` (S4), и `xtask gen-dataset`. Генерация полностью офлайн, данные не хранятся, только манифест.
  **Почему:** одинаковые датасеты во всех бенчах и тестах, никаких скачиваний, воспроизводимость по `(dataset, seed, version)`.
- **Решение:** профилировщик — **Tracy** (`tracing-tracy` + `profiling` с бэкендом tracy, feature `profile`), puffin не используем. Startup/IO на Windows — **WPR/WPA** с закоммиченными профилями.
  **Почему:** tracing уже есть во всех крейтах (S1) — спаны идут в Tracy без дублирования; Tracy видит потоки, блокировки, аллокации, переключения контекста (ETW), фреймы. Один инструмент вместо двух.
- **Решение:** релизный конвейер — свой `release.yml` + `xtask dist`, без cargo-dist и cargo-wix. MSI — WiX 7 напрямую (`.wxs` в репо), `Scope="perUserOrMachine"` (по умолчанию per-user, без UAC). Подпись — абстракция `xtask sign --provider signpath|pfx|none`. MSIX — после M6.
  **Почему:** cargo-wix/cargo-dist сидят на WiX v3 (EOL); нужен порядок «подписать exe → упаковать → подписать MSI», sideload `conpty.dll`/`OpenConsole.exe` (S6), portable-маркер (S0 №1). MSIX требует подписи всё равно, а Store-аккаунт из РФ под вопросом.
- **Решение:** macOS-сборка, подпись и notarization идут на `macos-15` раннере CI (`codesign` + `notarytool --wait` + `stapler`), бинарь universal2. Реальный Mac нужен только для ручного QA и перф-замеров против Finder.
  **Почему:** notarytool работает на любом macOS с API-ключом App Store Connect; железо для сборки не требуется.

## 1. Датасеты (`xtask gen-dataset`)

CLI: `cargo xtask gen-dataset <ID…|all> --root <dir> [--seed N] [--verify] [--force]`.
- Детерминизм: `ChaCha8Rng::seed_from_u64(seed ^ hash(ID))`; дефолтный сид = 1. Версия генератора `GEN_VER` входит в манифест; смена алгоритма → новый `GEN_VER`.
- Манифест `<root>/<ID>/.urfin-dataset.json`: `{id, seed, gen_ver, files, dirs, bytes, allocated, tree_hash(xxh3 по путям+размерам), created}`. Повторный запуск при совпадении манифеста — no-op; `--verify` перепроверяет дерево (≤1 мин на 1M).
- Содержимое файлов: псевдослучайные несжимаемые блоки (xoshiro, ≥2 ГБ/с), чтобы NTFS-compression/дедуп/ZFS не искажали замер. Для кода — текстовые блоки (сжимаемые), см. B3.
- Запись: параллельно (rayon, N = ядра), крупные — с preallocate; mtime фиксируется детерминированно (2020-01-01 + i·с).
- Проверка места заранее; `--root` обязан быть на целевом томе (VHDX/Dev Drive/loop).

- регистр `A`/`a` (case-sensitive ФС), кириллица/греческий/CJK/эмодзи с ZWJ/RTL с метками направления/комбинирующие;
- Windows: хвостовые точки и пробелы, `CON`, `NUL.txt`, непарные суррогаты (только через `\\?\`), ADS (`file:stream`);
- Linux: не-UTF-8 байты, `\n` в имени, имя 255 байт;
- symlink (abs/rel/битый/цикл), junction (Windows), hardlink ×3, файл 0 Б, sparse, read-only, hidden/system.

## 3. Сценарные бенчи против конкурентов (стенд)

### 3.1 Харнесс `xtask perf`
- `xtask perf run <suite> [--cold|--warm] [--tools urfin,explorer,robocopy,far,tc]` → `docs/perf/runs/<date>-<host>-<suite>.json`; `xtask perf report` → `docs/perf/report.md`; `xtask perf compare <a> <b>`.
- Внутри — hyperfine (≥1.19, `--export-json`, `--prepare` для сброса кэша и очистки dst, `--conclude` для проверки результата) для CLI-инструментов и для Urfin в headless-режиме `urfin --bench <scenario.toml>` (Core + реальные сервисы без окна, выход по Done, JSON-метрики из спанов на stdout; Запрос к S0 №2).
- Отпечаток окружения в каждом JSON: ОС/билд, CPU, RAM, модель диска, ФС, режим Defender (штатный / Dev Drive performance), план питания, версии Urfin (sha) и конкурентов, температура CPU (если доступна).

### 3.2 Методика
- **Warm:** датасет прочитан один раз; 2 warmup + 10 прогонов; dst очищается в `--prepare`, затем пауза 5 с (TRIM/запись кэша).
- **Cold:** данные на отдельном VHDX/Dev Drive → `Dismount-DiskImage`/`Mount-DiskImage` (сбрасывает и метаданные NTFS), для системного тома — `RAMMap -Et`; Linux — `sync; echo 3 > /proc/sys/vm/drop_caches` (VMware; в WSL2 — только ext4 внутри VHDX, `/mnt/c` (9p) не меряем); macOS — `sudo purge`. Затем 10 с простоя. 5 прогонов.
- Операции >60 с — 3 прогона. Перед B1/B6 — 60 с простоя (SLC-кэш SSD).
- Статистика: медиана, p95 (при ≥10), min, CV. CV >5% → набор повторяется один раз, затем помечается `unstable`.
- Условия: питание от сети, режим «Максимальная производительность», Windows Update на паузе, фон <2% CPU 10 с до старта (проверяется харнессом), интернет не нужен.

### 3.3 Драйверы конкурентов (Windows)
| Инструмент | Листинг | Операции | Детектор завершения |
|---|---|---|---|
| Explorer | `IShellWindows` → `Navigate2` в уже открытое окно; UIA-события: `StructureChanged` списка (t_first), текст статус-бара «N элементов» (t_done) | `IFileOperation` (движок Explorer) с диалогом прогресса, `FOF_NOCONFIRMATION` | возврат `PerformOperations` |
| robocopy | — | `/E /MT:16 /NFL /NDL /NP /R:0`, крупные `/J` | код выхода |
| `rd /s /q`, `cmd dir`, `Get-ChildItem` | CLI-базлайны S4 | delete-базлайн | код выхода |
| Far 3 x64 | отдельный профиль, фиксированный конфиг; SendInput (Enter) | SendInput F5/F6/F8 + Enter | внешний детектор |
| Total Commander x64 | `/O /N /L= /R= /i=bench.ini`, команды через `WM_USER+51` (`cm_*`) | `cm_Copy`/`cm_Delete` + Enter | внешний детектор |

- **Внешний детектор:** опрос dst своим `NtQueryDirectoryFile`-обходом раз в 100 мс (число/байты = ожидание) + `GetProcessIoCounters` процесса; конец = последний момент I/O-активности перед 500 мс тишины. Точность ±100 мс — для операций <2 с дополнительно запись экрана 120 fps (протокол S4), 3 прогона.
- TC: нужна лицензия или обработка nag-окна в драйвере; версии Far/TC фиксируются в отчёте.
- Linux: `cp -r --reflink=auto`, `rsync -a`, `rm -rf`, `ls -f`, `ls -la`, `fd --max-depth 1`. macOS: Finder через AppleScript (`duplicate`/`move`/`delete`), `cp -c`, `ditto` — при наличии Mac.

### 3.4 Отчёт
`docs/perf/report.md` (генерируется): сценарий × инструмент → медиана, p95, отношение к Urfin, CV, статус бюджета; отдельные таблицы warm/cold и по ФС. Сводка M6 — `docs/perf/m6-report.md`.

## 4. Профилирование

- **Кадр:** feature `profile` в app → `tracing-tracy` (наши спаны) + `profiling` с бэкендом tracy (внутренние скоупы egui/epaint), `frame_mark` в конце `update`, plots: длина очереди Msg, Msg/кадр, промахи `RowCache`, байты GL-загрузок. Версия Tracy GUI = версия протокола `tracy-client`, фиксируется в `docs/perf/profiling.md`. В release без feature — нулевая стоимость (CI проверяет, что `profile`, `dhat-heap`, `count-alloc` не включены в релизной сборке).
- **Старт:** спаны `startup.{paths,config,tracing,session,core,window,fonts,first_frame}` от времени создания процесса (`GetProcessTimes`/`/proc/self/stat`) — включая загрузчик ОС. `urfin --bench-startup` пишет JSON и выходит после первого кадра. Глубокий разбор — WPR: `perf/wpr/urfin.wprp` (CPU, FileIO, DiskIO, ImageLoad, VirtualAlloc) + `perf/wpa/startup.wpaProfile`; `xtask perf startup --wpr` снимает `.etl`.
- **Память:** peak/текущий private и working set (Windows `PROCESS_MEMORY_COUNTERS_EX`, unix `/proc` / `task_info`) — семплер в харнессе; аллокации — `dhat` (feature `dhat-heap`) и считающий `GlobalAlloc` (feature `count-alloc`, используется гейтом F.2); утечки — soak S.6. Куча Windows по требованию — WPR `Heap`.
- **GPU:** при подозрении — RenderDoc на glow; GL-зоны Tracy не включаем по умолчанию.

| SMB | windows: loopback `New-SmbShare` → `\\localhost\…` (корректность, copychunk) | NAS/вторая машина 1 GbE | O.11, листинг по сети |
| APFS | macos-15 (системный), exFAT/HFS+ через `hdiutil create` | Mac (при наличии) | clonefile, NFC/NFD |
| ext4 / btrfs / xfs / tmpfs | ubuntu: loop-образы 4 ГиБ (`mkfs.*`, `btrfs-progs`, `xfsprogs`) | VMware (виртуальные диски), WSL2 ext4 | FICLONE, copy_file_range, statx, inotify |
| 9p (WSL `/mnt/c`) | — | WSL2 | только корректная деградация |

Тесты на конкретной ФС помечаются `#[ignore]` и запускаются с `URFIN_TEST_FS=<путь>` (`xtask test-fs <fs>`).

## 9. Решения для владельца

1. **Публичный репозиторий на GitHub с M6** (или раньше). Даёт бесплатную OSS-подпись (SignPath Foundation), безлимитные минуты Actions (macOS-минуты в приватном репо тарифицируются ×10), arm64-раннеры, доверие к winget-пакету. Варианты: (а) публично — рекомендация; (б) приватно до 1.0 — платные минуты, подпись только платная или без подписи.
2. **Подпись Windows.** (а) SignPath Foundation — бесплатно, нужны публичный репо, MFA, страница политики подписи и ручное подтверждение каждой подписи — рекомендация; (б) Azure Artifact Signing ($9.99/мес) — недоступна: только юрлица US/CA/EU/UK и физлица US/CA; (в) OV-сертификат у CA через иностранное юрлицо (~$200–500/год, HSM/токен); (г) без подписи — предупреждение SmartScreen «Неизвестный издатель».
3. **Apple Developer Program ($99/год) для Developer ID и notarization.** Для граждан и резидентов РФ регистрация и оплата затруднены (санкционная проверка, способы оплаты).
