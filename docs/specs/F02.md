# F02 — Менеджеры пакетов: спецификация

Статус: draft v1 (2026-10-22). Владелец: F-02. Основание: `01-ROADMAP.md` «Приоритетные фичи» F-02, S0-decisions №82–76, `design/DESIGN.md` (`screen-pkg*`, `screen-settings-pkg`, `screen-utilmenu`). Опирается на S6 (процессы, job object, вывод) и S5/S1 (JobRegistry, job-бар, `Banner`). Изменения чужих контрактов — только через «Запросы к S0» (§6).

## 0. Ключевые решения

- **Решение:** работаем только с системными менеджерами, найденными на машине: winget, scoop, choco. Свой каталог, свой установщик и свои источники не делаем. Ненайденный менеджер в настройках показан пунктиром и в запросы не попадает.
  **Почему:** пакеты, зависимости, хэши и подписи уже проверяет менеджер. Урфин даёт им общий вид в стиле панели.
- **Решение:** Урфин запускает менеджер внешним процессом и читает его вывод. В сеть ходит сам менеджер. Урфин в рантайме сеть не трогает: иконок, размеров загрузки и HEAD-запросов к инсталляторам нет. Издателя Урфин берёт локально, из реестра Uninstall (ARP).
  **Почему:** так держится правило офлайна из CLAUDE.md. Доверие и обновление источников остаются у менеджера.
- **Решение:** права даёт UAC самого менеджера или инсталлятора. winget работает без повышения прав, а инсталлятор, если ему нужно, сам вызывает UAC. scoop работает в профиле пользователя, без UAC; глобальные установки (`-g`) в F-02 не поддерживаем. choco сам права не повышает, поэтому его мутирующие команды Урфин запускает через `runas` (§3.4). UAC при этом показан для запуска менеджера, сам Урфин прав администратора не получает.
  **Почему:** без прав администратора choco ставит пакеты частично или падает. Держать весь Урфин с повышенными правами нельзя.
- **Решение:** всё асинхронно. Каждый запрос — отдельный процесс на `spawn_dedicated`. Результаты приходят через `MsgSink` в `PkgState` (`AppState.ext`). Поиск в «Все» идёт параллельно во все менеджеры, ответы показываются по мере готовности. Мутирующие операции встают в очередь: одна на менеджер (`JobHandle::set_state(Queued)`).
  **Почему:** UI-поток без I/O. У msiexec и у установщиков менеджеров глобальная блокировка, поэтому параллельные установки одного менеджера всё равно встают в очередь, только непредсказуемо.
- **Решение:** процессы запускаются через pipes, не через ConPTY. Вывод дублируется в «ленточный» сеанс терминала только для чтения, его показывает Ctrl+O (§3.1).
  **Почему:** один механизм нужен для парсинга, для безоконной проверки `--pkg-check` и для choco с повышенными правами (тот через ConPTY не запустить).
- **Решение:** расписание делает Планировщик заданий Windows. Задача запускает `urfin.exe --pkg-check` без окна. Итог пишется в state-файл и при следующем запуске показывается баннером. По умолчанию расписание выключено.
  **Почему:** нет резидентного процесса и 0% CPU в простое. Сеть трогают только менеджеры, только по расписанию, которое включил пользователь.
- **Решение:** «важные» — список программ, который ведёт пользователь (`[pkg] important`, чипы в настройках). В обновлениях они стоят сверху, и баннер считает их отдельно.
  **Почему:** winget не различает обновления безопасности (№82, ROADMAP).
- **Решение:** «Вне менеджера» — программы, которые winget видит в ARP/MSIX без источника (`Source` пуст) и которых нет в списках scoop/choco. Обновлять их Урфин не предлагает. Удаление — через `winget uninstall`, он вызывает деинсталлятор ARP.
  **Почему:** показать, что стоит на машине, честно и без своего инвентаризатора.

## 1. Состав

Новый крейт **`urfin-pkg`** (запрос S0 №1). В нём нет `unsafe` и UI. Зависимости: `urfin-core`, `urfin-term` (процессы и ленточный сеанс, запрос №2), `urfin-i18n`, `serde`, `serde_json`, `toml`, `windows-registry` (запрос №3), `tracing`, `thiserror`. Без GPUI.
Запасной вариант, если S0 против нового крейта, — модуль `urfin-app::pkg` с той же структурой. Отдельный крейт даёт тесты парсеров без app и быструю инкрементальную сборку.

```
crates/pkg/src/
  lib.rs        — PkgHandler (ns pkg), PkgState (AppState.ext), register
  config.rs     — [pkg] (§2.6)
  api.rs        — PackageManager, PkgId, Package, Update, Hit, PkgOp, PkgError
  proc.rs       — run_query / run_action поверх term::proc: таймауты, отмена, декодирование
  decode.rs     — UTF-8 строго → OEM CP (encoding_rs), снятие \r-спиннеров и VT
  table.rs      — разбор табличного вывода (колонки по разделителю «---»)
  adapters/     — winget.rs, scoop.rs, choco.rs, fake.rs (тесты)
  arp.rs        — чтение Uninstall-ключей HKLM/HKCU (+WOW6432Node): DisplayName, Publisher, DisplayVersion
  merge.rs      — сводный список установленных, группировка поиска, сравнение версий
  vfs.rs        — схема `pkg:` (Caps::VIRTUAL | READ_ONLY)
  jobs.rs       — install/upgrade/uninstall как job, очередь по менеджеру, UAC-эвристика
  schedule.rs   — XML задачи, schtasks /Create|/Delete|/Query
  check.rs      — режим --pkg-check (без GPUI), check.json
crates/pkg/tests/fixtures/ — снимки вывода winget/scoop/choco (EN и RU) со стенда
```
`urfin-app`: флаги `--pkg-check` и `--pkg-elevated` в `boot.rs`, без инициализации GPUI. `urfin-ui`: колонки `pkg:`, строка поиска, мешочек менеджеров, раздел настроек.

## 2. API

### 2.1 Трейт и типы
```rust
pub enum Mgr { Winget, Scoop, Choco }               // порядок = [pkg].order
pub struct PkgId { pub mgr: Mgr, pub id: CompactString }   // winget Id / scoop bucket/name / choco id
pub struct Detected { pub mgr: Mgr, pub exe: PathBuf, pub version: Option<CompactString>, pub caps: MgrCaps }
pub struct Package { pub id: PkgId, pub name: CompactString, pub version: CompactString,
                     pub source: Option<CompactString>, pub publisher: Option<CompactString> }
pub struct Update  { pub pkg: Package, pub available: CompactString, pub pinned: bool }
pub struct Hit     { pub pkg: Package, pub matched: MatchKind }   // Exact | IdTail | Prefix | Contains
pub enum PkgOp { Install, Upgrade, Uninstall }

pub trait PackageManager: Send + Sync {
    fn mgr(&self) -> Mgr;
    fn detect(&self) -> Option<Detected>;                                  // без запуска процесса
    fn version(&self, cx: &RunCx) -> Result<CompactString, PkgError>;      // лениво, кэш
    fn list_installed(&self, cx: &RunCx) -> Result<Vec<Package>, PkgError>;
    fn list_updates(&self, cx: &RunCx) -> Result<Vec<Update>, PkgError>;
    fn search(&self, q: &str, cx: &RunCx) -> Result<Vec<Hit>, PkgError>;
    fn action(&self, op: PkgOp, id: &PkgId, cx: &RunCx) -> Result<ActionPlan, PkgError>; // argv + elevate
}
```
`RunCx` содержит `CancelToken`, таймаут, приёмник строк вывода (для ленточного сеанса и прогресса). Адаптеры `WingetAdapter`, `ScoopAdapter`, `ChocoAdapter` и `FakeAdapter` (тесты, повтор фикстур) — все синхронные. Асинхронность создаёт `PkgHandler`: он поднимает поток на запрос.
`action` ничего не запускает. Он возвращает `ActionPlan { argv, elevate: bool, success_codes, reboot_codes }`, а исполняет его `jobs.rs` (§3). Так адаптер проверяется без процессов.
`PkgError`: `NotFound`, `Timeout`, `Cancelled`, `Exit { code, tail }`, `Parse { line }`, `Elevation(Declined)`.

### 2.2 Обнаружение (`detect`, без процессов, ≤5 мс)
- winget: `winget.exe` в PATH, обычно `%LOCALAPPDATA%\Microsoft\WindowsApps` (алиас App Installer, reparse `APPEXECLINK`, `CreateProcess` его открывает).
- scoop: `%SCOOP%\shims\scoop.ps1`, иначе `%USERPROFILE%\scoop\shims`. PowerShell для запуска берётся из кэша S6 `term/shells.toml` (pwsh, иначе powershell 5.1).
- choco: `%ChocolateyInstall%\bin\choco.exe`, иначе `C:\ProgramData\chocolatey\bin`. Номер версии (v1 или v2) влияет на синтаксис `list`.
Кэш — `state/pkg/managers.toml`. Перепроверка — при открытии `pkg:` и по Ctrl+R.

### 2.3 Парсинг по менеджерам
Общие правила:
- argv — массивом, без shell-обёрток. Каждый `PkgId` перед подстановкой проверяется регэкспом своего менеджера.
- Флаги неинтерактивности ставятся всегда.
- Парсер не зависит от текста заголовков: заголовки локализованы под язык Windows, а сменить язык вывода winget нельзя.

**winget** (флаги всегда: `--accept-source-agreements --disable-interactivity`; для install/upgrade также `--accept-package-agreements`, плюс `--silent` по настройке):
- `--output json` у `list`/`search`/`upgrade` в известных версиях winget нет, JSON даёт только `export`. F02-04 сверяет это на стенде: если `winget list --help` знает `--output`, берём JSON, иначе текст.
- Установленные: `winget export -o <tmp>.json --include-versions` даёт точные Id и версии всего, что сопоставлено с источником. `winget list` даёт таблицу с именами, `Available` и строками ARP/MSIX без источника.
- Таблица: строка-разделитель из `-` отмечает начало данных. Границы колонок — начала слов заголовка над ней. Число колонок переменное (`Available` бывает только при наличии обновлений), поэтому роль колонки определяется по содержимому: Id без пробелов, Source из известных имён источников, версии по шаблону.
- Усечённые `…` Id восстанавливаются по префиксу из `export`, имена — из ARP DisplayName. Хвостовые строки («N upgrades available», пины) отбрасываются: ширина их не совпадает с сеткой.
- Обновления: `winget upgrade` (та же таблица); `--include-unknown` — по настройке.
- Поиск: `winget search <q>` → колонки Name, Id, Version, [Match], Source. Издатель — префикс Id до первой точки.
- Структурный путь без парсинга текста — модуль PowerShell `Microsoft.WinGet.Client` (`Get-WinGetPackage`/`Find-WinGetPackage | ConvertTo-Json`), если пользователь его установил. Это решение владельца №2.

**scoop** — через `powershell -NoProfile -NonInteractive -EncodedCommand`, как в S6, чтобы ExecutionPolicy не мешал. Скрипт сначала выставляет `[Console]::OutputEncoding = UTF8`, затем подавляет `Write-Host` (`6>$null`), печатает маркер `<<URFIN>>`, а за ним — JSON:
- установленные: `scoop export` (`apps[]: Name, Version, Source, Updated, Info`);
- обновления: `scoop update` (git pull бакетов, сеть scoop; отключается `scoop_update_buckets = false`), затем `scoop status --local | ConvertTo-Json`;
- поиск: `scoop search <q> | ConvertTo-Json` (Name, Version, Source).
Старт PowerShell стоит 0,3–0,6 с — это приемлемо для фоновой работы.

**choco** — `--limit-output` (`|`-разделитель, без заголовков) и `--no-color`:
- v2: `choco list` — локальные пакеты; `choco outdated` → `id|current|available|pinned`; `choco search <q>` → `id|version`;
- v1: `choco list --local-only`; `search` = `list` без флага.
- Мутирующие команды (`install|upgrade|uninstall <id> -y --no-progress`) — с `elevate: true`.

**Кодировка.** Ребёнку подменяем консоль, `chcp` не вызываем: обёртка `cmd /c chcp 65001 && …` открыла бы инъекцию через кавычки cmd и добавила бы 30 мс. Декодер (`decode.rs`) берёт каждую строку как UTF-8 строго. Если строка невалидна, она декодируется из OEM CP (читаем `OEMCP` из реестра `Nls\CodePage`, `encoding_rs`: 866/437 и т.п.). PowerShell-скрипты отдают UTF-8 явно. Перед парсингом снимаются `\r`-перезаписи (остаётся последний сегмент) и VT-последовательности.

**Таймауты** (конфиг): `version` 5 с, `list_installed` 60 с, `list_updates` 180 с (обновление источников winget и `scoop update`), `search` 30 с на менеджер. У действий таймаута нет. Если вывода нет 10 мин, в job-баре появляется «нет вывода 10 мин» с кнопкой «Прервать». По таймауту процессное дерево убивается, ошибка показывается в чипе менеджера, результаты других менеджеров остаются.

**Отмена:** `TerminateJobObject` дерева (job object из `term::proc`) за ≤100 мс. Ограничение: повышенный инсталлятор, запущенный через UAC, в job не входит и продолжит работу. Задача тогда помечается «прервана, инсталлятор мог продолжить работу».

### 2.4 Объединение (`merge.rs`)
- **Установленные.** Объединяем списки менеджеров. Дубликаты сводятся так: choco-пакет и запись winget ARP с тем же нормализованным именем дают одну строку, менеджер — choco. Строка winget без источника и без пары — «вне менеджера» (`secondary`). Издатель: winget-Id → ARP Publisher; scoop/choco → ARP при совпадении имени, иначе пусто.
- **Обновления.** Дубль winget у программы, которую ведёт choco или scoop (общий псевдоним имени или хвоста Id), скрыт: остаётся строка своего менеджера — как в «Установленных» ([решение 2026-11-02 «pkg-updates»](../decisions/2026-11-02-pkg-updates.md) №1).
- **Нормализация имени:** NFKC, нижний регистр, удаление `(x64)`, `x86`, `64-bit`, хвостовых версий и всего, кроме букв и цифр. Хвост Id тоже даёт псевдоним: `Mozilla.Firefox` → `firefox`, scoop `extras/firefox` → `firefox`.
- **Ключ группы поиска:** `norm(name)` или `norm(id_tail)`. Если у одного ключа разные издатели winget (префиксы Id), группа делится на подгруппы. У scoop и choco издателя нет, они примыкают к группе с тем же ключом.
- **Версии:** сравнение по сегментам, разделители `.` `-` `+` `_`. Числовые сегменты сравниваются как числа, остальные лексикографически. Пре-релиз (`-beta`, `-rc`) ниже релиза. `Unknown` и `< x` не сравниваются. «Новейшая» внутри группы выделяется `accent`.
- **Порядок групп:** качество совпадения (Exact > IdTail > Prefix > Contains), затем число менеджеров с программой, затем имя.
- **«Рекомендуется»** — вариант первого менеджера по `[pkg].order` (winget > scoop > choco). Внутри winget источник `winget` идёт раньше `msstore`. Если новейшая версия есть только у другого менеджера, рекомендация остаётся по порядку, а новейшая подсвечивается отдельно (решение владельца №4).

### 2.5 VFS-схема `pkg:` и команды
`pkg:installed`, `pkg:updates`, `pkg:search?q=<q>&in=all|winget|scoop|choco`. Это `Vfs` с `Caps::VIRTUAL | READ_ONLY`. Строки — `Entry` (имя — программа) плюс данные строки пакета для колонок Программа · Версия · Доступна · Менеджер · Издатель (запрос №4). Таб в сессии не сохраняется (CONTRACTS, v6 №5). При открытии он сразу показывает кэш `state/pkg/cache.json` с датой и дальше перезапрашивает менеджеры только по Ctrl+R; если кэша ещё нет, при первом открытии проверка запускается сама ([решение 2026-11-02 «pkg-updates»](../decisions/2026-11-02-pkg-updates.md) №2). Фоновых запросов при старте нет.

Команды (ПРЕДЛОЖЕНИЕ к S0, запрос №5; контекст keymap `pkg` — активный таб на `pkg:`):

## 3. Запуск и вывод

### 3.1 Pipes, а не ConPTY — обоснование
- **Парсинг.** В ConPTY вывод проходит через эмуляцию экрана: таблица winget переносится по ширине PTY, `\r`-прогресс перерисовывает строки. В pipe приходят исходные строки.
- **Безоконный `--pkg-check`.** В нём нет терминала и GPUI. Pipes работают без них.
- **choco с повышенными правами.** Процесс, запущенный через UAC, создаёт AppInfo, а не Урфин. К нашему ConPTY его не подключить, иначе он открывает своё окно консоли. Через именованный pipe его вывод доходит (§3.4).
- **Интерактивность.** Под ConPTY менеджер считает, что перед ним человек, и может задать вопрос, несмотря на флаги. В pipe вопросы не задаются, все флаги неинтерактивности стоят.
- **Цена:** нет цветов и «живых» полос прогресса менеджера. Это приемлемо: прогресс показывает job-бар.

**Вывод по Ctrl+O.** Каждая строка процесса пакетов (запрос, действие, `pkg.info`) уходит в ленточный сеанс S6 «Пакеты»: `alacritty Term` без PTY, только для чтения, со скроллбэком. Перед каждой операцией он печатает заголовок `▸ winget upgrade Mozilla.Firefox`, после неё — `код выхода`. Сеанс один на процесс Урфина. Ctrl+O в `pkg:` показывает его вместо shell. API ленточного сеанса — запрос №2. Если S0 откажет, запасной план — простой текстовый лог в оверлее с той же клавишей.

### 3.2 Job и job-бар
- Каждое действие — job: `JobSpec { kind: "pkg", title: "Обновление Firefox (winget)", lane: Bulk-короткая постановка, owner_ns: "pkg" }`, выполнение — на `spawn_dedicated`.
- Пакетное «Обновить N» — одна родительская job на менеджер с `items_total = N`, пакеты внутри идут последовательно. Разные менеджеры выполняются параллельно.
- Прогресс из строк вывода, без опоры на слова: шаблоны `NN%` и `X.X MB / Y.Y MB` дают долю. Если шаблона нет, прогресс неопределённый и показывается фаза. Фаза — по ключевым строкам EN/RU из фикстур и только для подписи. Итог определяется кодом выхода.
- Коды выхода:
  - 0 — успех;
  - winget: таблица известных HRESULT (`0x8A15xxxx`) из документации winget, в коде — константы со ссылкой. «Обновление не применимо» и «нет пакета» — предупреждения, не ошибки;
  - 1641/3010 (choco и инсталляторы) — «нужна перезагрузка» (`Banner` с действием «Позже»).
- После действия перечитываются только затронутые менеджеры. Строка группы поиска показывает прогресс прямо в ней (`screen-pkginstall`).
- `job.retry {id}` роутится в `pkg` (S0 v2 №8). Выход с активными пакетными job — `on_quit` Veto («идёт установка: N»).

### 3.3 Ожидание UAC — честно
Надёжного API «процесс ждёт согласия UAC» нет. Повышение запрашивает инсталлятор через AppInfo. Окно consent.exe работает на защищённом рабочем столе, и Урфин его не видит.
- **choco:** точно. `ShellExecuteExW("runas")` блокируется до решения пользователя. Пока вызов не вернулся, job в состоянии «ждёт подтверждения UAC». `ERROR_CANCELLED` (1223) означает, что пользователь отказал, и job отменяется.
- **winget:** эвристика, подпись «возможно, ждёт подтверждения UAC» (`context_remote`). Условия: job активна, вывода нет ≥1,5 с и в сессии пользователя есть процесс `consent.exe`, появившийся после старта job. Проверка — снимок процессов раз в 500 мс, только пока job молчит (`term::proc::session_has_process`, запрос №2). Ложное срабатывание возможно: consent.exe мог вызвать кто-то другой. Поэтому формулировка с «возможно», и вывод/прогресс её снимают.

### 3.4 choco с повышенными правами
- Урфин создаёт именованный pipe `\\.\pipe\urfin-pkg-<nonce>` (DACL: текущий пользователь) и запускает `ShellExecuteExW(runas, urfin.exe --pkg-elevated <pipe> <nonce> -- choco upgrade <id> -y --no-progress --limit-output)`. Окно UAC показывает подписанный Urfin, а не cmd.
- Помощник с повышенными правами не создаёт окно и не инициализирует GPUI. Он проверяет nonce, запускает choco с `CREATE_NO_WINDOW` и pipes, пересылает строки в pipe и завершается с кодом choco.
- Отмена — команда `cancel` по тому же pipe: убить помощника из процесса без повышенных прав не даёт ACL.
- Помощник принимает только argv вида `choco (install|upgrade|uninstall) <id> <фикс. флаги>` и проверяет его регэкспом id. Произвольные команды с повышенными правами он не исполняет. ADR — в F02-06.

## 4. Расписание

- **Создание** (`pkg.schedule on`). Урфин пишет XML задачи и вызывает `schtasks /Create /TN "\Urfin\PkgCheck" /XML <file> /F` от текущего пользователя, без прав администратора. Параметры XML:
  - `LogonType=InteractiveToken`, `RunLevel=LeastPrivilege`;
  - триггер Daily в `at` и `StartWhenAvailable=true` — пропущенный запуск выполняется при входе;
  - `DisallowStartIfOnBatteries=true`, `RunOnlyIfNetworkAvailable=true`;
  - `ExecutionTimeLimit=PT30M`, `MultipleInstancesPolicy=IgnoreNew`;
  - действие — `"<путь urfin.exe>" --pkg-check`.
  COM `ITaskService` не нужен: XML покрывает все поля, `unsafe` не требуется.
- **Удаление** — `schtasks /Delete /TN "\Urfin\PkgCheck" /F`. Задачу убирает и деинсталлятор S9 (запрос №6).
- **Сверка пути.** При открытии настроек «Пакеты» Урфин выполняет `schtasks /Query /XML /TN …` и сравнивает путь. Если portable-копию перенесли, раздел показывает «задача указывает на другой путь — Обновить».
- **`--pkg-check`.** Это GUI-подсистема: окна нет, GPUI не инициализируется, консоли детей запускаются с `CREATE_NO_WINDOW` без мигания. Порядок:
  1. Взять `state/pkg/check.lock` (эксклюзивно; если занят — выход 0).
  2. `detect` и `list_updates` всех найденных менеджеров параллельно, с таймаутами §2.3.
  3. Атомарно записать `state/pkg/check.json`: `{ checked_at, managers: [{mgr, ok, error?}], updates: [...], important: [ids] }`.
  4. Выйти. Код 0, если хоть один менеджер ответил.
  Сам Урфин в сеть не обращается. Лог — `logs/pkg-check.log` (tracing, ротация как у app).
- **Баннер.** После первого кадра (Lane::Interactive) Урфин читает `check.json`. Если там есть обновления новее `dismissed_at` и не все они уже видны в открытом `pkg:`, появляется `Banner`: «Доступно N обновлений · M важных — проверено <дата>» с действиями `Показать` (`pkg.banner.show`) и `Позже` (`pkg.banner.later` записывает `dismissed_at`). Вид — `screen-pkgbanner` (вспышка по «Движению»). Если Урфин в момент проверки уже открыт, баннер появится при следующем запуске (решение владельца №3).

## 6. Запросы к S0

1. **Новый крейт `urfin-pkg`** (без `unsafe`) — для изоляции и тестов парсеров. Альтернатива — модуль `urfin-app::pkg`.
2. **`urfin-term` — публичные безопасные API** (`unsafe` остаётся в `term::sys`):
   - `term::proc::spawn_piped(argv, cwd, env, flags) -> PipedChild` — с job object, `kill_tree()`, `wait_timeout()`;
   - `term::proc::session_has_process(name, since) -> bool`;
   - ленточный сеанс `TermApi::feed_session(title) -> FeedSink` — Term без PTY, только для чтения, показывается Ctrl+O и в списке сеансов.
3. **Зависимость `windows-registry`** (MIT/Apache-2.0, семейство windows-rs) — безопасное чтение ARP и `OEMCP`. Альтернатива: функции чтения реестра в `urfin-app::sys`.
4. **Колонки, задаваемые схемой** для `Caps::VIRTUAL`: `Vfs::columns() -> &[ColumnSpec]` и данные строки (`Entry.ext` или провайдер ячеек). Та же потребность у `du:` (F-01), прецедент — колонка сравнения (S0 v5 №18).
5. **Команды `pkg.*`** (§2.5), контекст keymap `pkg`, привязки из №84 в контексте `pkg`. Ctrl+1/2/3 в `pkg:` не должны конфликтовать с пресетами (проверка `commands_doc` и конфликтов keymap).
6. **S9:** деинсталлятор удаляет задачу `\Urfin\PkgCheck`. Подпись `urfin.exe` нужна, чтобы UAC помощника показывал издателя.
7. **Флаги app `--pkg-check`, `--pkg-elevated`:** ранний выход из `boot.rs` до GPUI; IPC единственного экземпляра на них не распространяется.
8. **Нумерация S0-decisions:** номера 73–77 повторяются (записи от 2026-10-21 и 2026-10-22). В этой спеке ссылки №82–76 означают записи от 2026-10-22. Просьба перенумеровать.

## 7. Решения для владельца

1. **«Обновить N · размер»** (`screen-pkgupdates`). Ни один менеджер не сообщает размер загрузки локально, а узнать его без сетевых запросов Урфина нельзя. Рекомендация: убрать размер из строки и оставить «Обновить N».
2. **Модуль `Microsoft.WinGet.Client`.** Он даёт структурный вывод winget без зависимости от языка Windows. Варианты:
   - (а) использовать, если установлен, иначе текст;
   - (б) только текст;
   - (в) предлагать установить его кнопкой — `Install-Module`, сеть PowerShell.
   Рекомендация: **(а)**.
3. **Урфин открыт во время проверки по расписанию.** Варианты:
   - (а) баннер только при следующем запуске (как в ROADMAP);
   - (б) `--pkg-check` сообщает открытому Урфину по IPC, и баннер появляется сразу.
   Рекомендация: **(б)** — дёшево, IPC уже есть.
4. **«Рекомендуется» при более новой версии у другого менеджера.** Варианты:
   - (а) рекомендация строго по порядку менеджеров;
   - (б) новейшая версия побеждает.
   Рекомендация: **(а)** + подсветка новейшей — предсказуемо и совпадает с дизайном.
5. **choco через помощника с повышенными правами** (§3.4) отходит от формулы «UAC менеджера»: choco сам UAC не вызывает. Варианты:
   - (а) помощник `urfin.exe --pkg-elevated`;
   - (б) choco только для чтения (список и обновления), установку не предлагать;
   - (в) требовать, чтобы Урфин был запущен с правами администратора.
   Рекомендация: **(а)**.
6. **`scoop update` перед проверкой обновлений** меняет состояние бакетов (git pull). Рекомендация: включено (`scoop_update_buckets = true`), иначе scoop не видит новых версий.

## 8. Решено владельцем (2026-10-22)
- Размер загрузки в «Обновить N» не показываем.
- `Microsoft.WinGet.Client` — только если уже установлен; иначе разбор таблицы.
- Баннер по расписанию — сразу в открытом Урфине.
- «Рекомендуется» — строго по порядку менеджеров, более новая версия у другого — подсветка.
- choco с правами: без помощника. Перед действием — предупреждение строкой «choco требует прав администратора — будет запрос UAC», затем запуск choco через UAC (runas) в отдельном консольном окне; ход — по журналу choco (`%ProgramData%\chocolatey\logs\chocolatey.log`), итог — в job-баре. `--pkg-elevated` не делаем.
- `scoop update` перед проверкой — включён.
- winget: подпись «возможно, ждёт подтверждения UAC».
