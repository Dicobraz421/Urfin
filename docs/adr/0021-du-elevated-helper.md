# ADR-0021: Досчёт размеров с правами администратора

Статус: **принято** владельцем 2026-11-02 в изменённом виде — [решение «du-elevated-same-exe»](../decisions/2026-11-02-du-elevated-same-exe.md): тот же `urfin.exe` через UAC, без отдельного помощника и подписи. Связано с S0-decisions №81, №84; F-01 (`docs/specs/F01.md` §0, F01-12); ADR-0020 (политики); образец — choco в F02-06 (S0 v6 №17).

## Контекст
Анализ места (F-01) работает в процессе Урфина без прав: часть каталогов (`System Volume Information`, чужие профили, `WindowsApps`, каталоги с запрещающим ACL) не читается — вкладка `du:` показывает «нет доступа: N папок», их размер не учтён. Пользователь хочет нажать «Досчитать с правами администратора» и получить полную картину, не перезапуская Урфин.

Операции (S5) повышения прав не имеют — и это принцип: всё, что меняет данные, выполняется в процессе пользователя. Досчёт не должен этот принцип нарушить.

## Варианты
**(а) Перезапуск всего Урфина от администратора.** Отвергнут: под полным токеном оказываются GPUI, терминал, операции записи, плагины; перетаскивание из Проводника в повышенное окно не работает (UIPI); теряется состояние сессии.

**(б) Отдельный процесс-помощник `urfin-du-helper.exe`** с именованным каналом, DACL, проверкой сторон и подписью Authenticode. Отвергнут владельцем: новый крейт, бинарь, протокол и сертификат — несоразмерно чтению размеров нескольких папок.

**(в) Тот же `urfin.exe` с флагом через UAC** — как choco в F02-06: процесс выходит до конфига, логов и GPUI, считает тем же обходом, пишет один файл и выходит. **Принят.**

**(г) Чтение тома `FSCTL_ENUM_USN_DATA` + записи MFT.** Не делается: разбор дисковых структур и дескриптор тома в повышенном процессе; выигрыш — только на целом томе. Политика `DuElevatedMft` остаётся на будущее.

## Решение

### Запуск
- Кнопка «Досчитать с правами администратора» (`du.elevate`) — в баннере «N папок без доступа» вкладки `du:` («По папкам»), только когда подсчёт закончен и `denied > 0`. Корни — ровно недоступные папки снимка (не весь диск): пути на дисках с буквой, не больше 64 и длины командной строки; остальные — следующим нажатием.
- Задача `du.elevate` (job-бар «ждёт подтверждения UAC» → «Досчитываю…»): `ShellExecuteExW`, verb `runas`, `SEE_MASK_NOCLOSEPROCESS`, окно скрыто (`urfin_ui::sys::runas`). Аргументы — только `--du-elevated --out <файл> <корень>…`.
- Отказ в UAC (`ERROR_CANCELLED`) — тост «Отменено в UAC — ничего не досчитано», снимок не меняется. Отмена (Esc на вкладке, «Отмена» в job-баре, выход из Урфина) — знак `*.cancel` рядом с файлом ответа и `TerminateProcess`; повышенный процесс проверяет знак каждые 200 мс и выходит без файла.

### Повышенный режим (`urfin.exe --du-elevated`)
- Ранний выход в `main` до каталогов, конфига, логов, единственного экземпляра и GPUI (`boot::du_elevated`) — как `--askpass`.
- Проверка аргументов до всего остального (`urfin_vfs::du::elevated::Request::parse`): корни — абсолютные пути `X:\…` без UNC, `\\?\`, `\\.\`, потоков (`:`), `.`/`..`, шаблонов и управляющих символов, ≤ 64, без повторов; файл — `…\du\elevated\du-<32 hex>.dures`. Ошибка — код 2.
- Политика `DuElevatedHelper` перечитывается самим процессом (HKLM и `%ProgramData%\Urfin\policy.toml`); 0 — код 3.
- Укрепление (`urfin_vfs::sys::win_elev`): `SeBackupPrivilege` включена (обход ACL на чтение — `NtLister` открывает каталоги с `FILE_OPEN_FOR_BACKUP_INTENT`), `SeChangeNotifyPrivilege` оставлена, прочие привилегии удалены (`SE_PRIVILEGE_REMOVED`); дочерние процессы запрещены (`ProcessChildProcessPolicy`).
- Обход — `urfin_vfs::du::scan` (тот же, что у анализа): только метаданные каталогов; ссылки не раскрываются; файлы на чтение данных не открываются; крупные файлы не собираются (порог — максимум).
- Ответ — один файл: создаётся только новым (`CREATE_NEW`, без следования за ссылкой в последнем звене) и сверяется по итоговому пути хэндла (`GetFinalPathNameByHandleW`) с путём, который обычный процесс заранее раскрыл `canonicalize`: каталог подменили ссылкой — файл удаляется по хэндлу, код 5. Больше процесс ничего не пишет (логов нет).

### Файл ответа
- Каталог — `state\du\elevated\` Урфина (portable — рядом с exe), не общий `%TEMP%`. Имя — `du-<nonce>.dures`, nonce — 128 бит на запуск.
- Формат v1: magic `URFDUE\0\0` · `ver: u16` · postcard `{ nonce, roots: [{ path, ok, disk, logical, files, dirs, denied, types_disk[10], types_files[10] }] }` · `xxh3_64` всего предыдущего. Не больше 1 МиБ.
- Обычный процесс проверяет длину, magic, версию, сумму, nonce своего запроса и что каждый путь — один из запрошенных корней, без повторов; затем удаляет файл. Брошенные файлы и знаки отмены старше часа удаляются при следующем досчёте.

### Подмена файлов
Решение владельца 2026-11-02 (вариант 1): portable-копия может лежать в каталоге, куда пишет пользователь (и всё, что запущено от его имени), — `urfin.exe` или DLL рядом можно подменить между нажатием кнопки и стартом повышенного процесса.

Закрыто:
- **Обычный процесс до `runas`** (`urfin_ui::sys::runas::ImageLock`): свой exe (путь `GetModuleFileNameW`) и все `*.dll` его каталога открываются с `FILE_SHARE_READ`, без `FILE_SHARE_WRITE | FILE_SHARE_DELETE`, и держатся до выхода (или снятия) повышенного процесса. Пока они открыты, их нельзя переписать, переименовать и удалить, а NTFS не даёт переименовать каталоги над ними. Загрузчик повышенного процесса открывает файлы только на чтение и исполнение — замок ему не мешает.
- **Запуск — по пути из открытого хэндла** (`GetFinalPathNameByHandleW`: ссылки раскрыты, длинные имена), сверенному с хэндлом по тому и номеру файла; не по argv и не по конфигу.
- Кто-то держит exe или DLL на запись — досчёт не запускается, тост «Не удалось досчитать…: urfin.exe или библиотеку рядом с ним держит на запись другая программа — закройте её и повторите».
- **Повышенный режим первым делом**, до разбора аргументов и чтения политики: `SetDefaultDllDirectories(LOAD_LIBRARY_SEARCH_SYSTEM32)` и `SetDllDirectoryW("")` — всё, что грузится динамически (`LoadLibrary` и зависимости таких DLL), только из System32; не вышло — код выхода 6.

Остаётся:
- **Статические импорты exe** разрешает загрузчик до `main`: KnownDLLs — из System32, прочие — сначала из каталога exe. Новую DLL с именем системной (`dwmapi.dll`, `dxgi.dll`, `dwrite.dll` …) можно подложить рядом после замка — замок держит только существующие файлы. Импорты exe — системные DLL и `VCRUNTIME140.dll` (среда VC++: в System32, если стоит распространяемый пакет). Сужается флагом компоновщика `/DEPENDENTLOADFLAG:0x800` и статической CRT (`+crt-static`) — отдельным решением.
- Замену exe **до** нажатия (переименовать работающий `urfin.exe` и положить другой) замок не ловит: это уже чужой код от имени пользователя, он и сам может показать окно UAC.
- Полностью закрывает установка в `Program Files` (каталог без записи для пользователя): ни exe, ни DLL рядом не подменить. Подпись дистрибутива закрывает подмену exe (UAC покажет издателя), но не подложенную рядом с portable-копией DLL.

### Слияние в снимок
- Каталог из ответа (`ok`) получает размер на диске, логический, число файлов и суммы по типам поддерева (с предками), флаг `ELEVATED` (бит 7 `NodeFlags`, раскладка кэша v2 не меняется), уходит из `denied`; не прочитанное и с правами — `PARTIAL_DENIED`. Имён внутри нет — ни в снимке, ни в кэше; деталей поддерева тоже нет (Enter внутрь — живой листинг, как без прав).
- Снимок помечается изменённым и уходит в кэш (`state\du\*.du`).
- Журнал (tracing, обычный процесс): запрос UAC с числом корней; итог (`done`/`declined`/`cancelled`/`failed`) и длительность — без путей.

### Политика организации (ADR-0020)
| Значение | Тип | Смысл |
|---|---|---|
| `du_elevated_helper` / `DuElevatedHelper` | DWORD | 0 — досчёт с правами запрещён: кнопка с замком, `du.elevate` отказывает, повышенный режим сам выходит с кодом 3; 1/нет — разрешён |
| `du_elevated_mft` / `DuElevatedMft` | DWORD | зарезервировано под вариант (г); сейчас не действует |

## Последствия
- Новых крейтов, бинарей и межпроцессных каналов нет; флаг `--du-elevated` — ранний выход `urfin.exe` (список флагов app в `CONTRACTS.md` — вопрос владельцу, PR класса B).
- UAC показывает «неизвестный издатель» и путь `urfin.exe`. Подмена exe и DLL рядом с portable-копией во время запроса UAC закрыта замком файлов и поиском DLL только в System32; остаток — раздел «Подмена файлов».
- Процесс без прав узнаёт итоги защищённых каталогов — то, на что пользователь дал согласие в UAC; имён изнутри он не получает.
- Жёсткие ссылки между недоступной папкой и остальным диском могут посчитаться дважды (дедуп — внутри одного обхода).
- Строки UI — urfin-i18n (EN+RU).

## Проверить на стенде (ручная проверка `docs/manual-tests/F01-12.md`)
- UAC: согласие, отказ, ввод учётки другого администратора.
- `System Volume Information`, `C:\Users\<другой>`, `C:\Program Files\WindowsApps` — досчитаны; «нет доступа» исчезает.
- Esc / «Отмена» в job-баре / выход из Урфина во время досчёта — повышенный процесс выходит ≤ 1 с, в Диспетчере задач не остаётся.
- `DuElevatedHelper` = 0 — кнопка с замком; ручной запуск `urfin.exe --du-elevated …` из консоли администратора — код 3.
- Process Explorer: у процесса из привилегий — Backup и ChangeNotify; дочерних процессов нет. Procmon: записи в ФС — только файл ответа.
- Пока открыто окно UAC: переписать, переименовать, удалить `urfin.exe`, DLL рядом или каталог portable-копии — отказ; exe открыт другой программой на запись — тост, окна UAC нет.
