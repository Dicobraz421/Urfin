# ADR-0024: точная подсветка видимого окна для файлов любого размера

Статус: **принято** ([решение владельца 2026-11-02](../decisions/2026-11-02-windowed-highlight.md)), класс A — межкрейтовый контракт (`docs/CONTRACTS.md`) не меняется. Заменяет ADR-0023 §7 и ответ 4 «Решено владельцем 2026-11-01» в части подсветки и свёртки; S7 §5.7 — по этому ADR. Карточка — [S7-41](../tasks/S7-41.md).

## Контекст

- S7-21 (#253): вьювер разбирал tree-sitter'ом весь файл ≤ 16 МиБ; S7-35 (#266): редактор — тоже весь файл ≤ 16 МиБ, с прежним деревом. Замер S7-35 (`docs/perf/s7.md`): на 16 МиБ цвета после правки — JSON 0,16–0,23 с, TOML 1,3–2,9 с, дерево — 0,6–0,8 ГБ памяти. Бюджеты (ADR-0023 §6, решение 2026-10-29): ≤ 64 МиБ на документ, цвета после правки ≤ 50 мс, кадр p99 ≤ 6 мс.
- Владелец 2026-11-02: подсветка — «как сам редактор: только видимый кусок», для файлов **любого размера**, «никаких неточностей» — в том числе для структуры на много экранов и строк/комментариев, начавшихся далеко выше экрана.
- Цвет байта зависит от всего текста выше (открытая кавычка, комментарий, ключ или значение JSON по стеку скобок). Поэтому «только окно» без знания состояния на его начале неточно; знание состояния — проход по файлу, но проход лёгкий (лексика, не дерево) и хранит только контрольные точки.

## Решение

### 1. Один источник истины на язык, для любого размера

| Языки | Чем красится окно | Почему так |
|---|---|---|
| JSON, TOML, INI, XML | **Свой возобновляемый лексер** (`view/src/syntax/lex/`) | Роль токена определяется лексикой и стеком скобок; внутри одного значения JSON на 10 ГБ нет места, с которого tree-sitter можно начать |
| YAML, Markdown | **tree-sitter + свой `highlights.scm`** по отрезку `[S, E)` вокруг окна | Грамматики сложные (сканер YAML — 1,4 тыс. строк), зато у них есть строки, с которых разбор начинается заново без потери точности (п. 3) |
| Пакетные (Rust, C/C++, C#, JS/TS, Python, Go, Java, Bash, PowerShell, Lua, CSS, HTML, Make, CMake, Diff) | Как сейчас: полный разбор ≤ 16 МиБ (`MARKUP_MAX`), больше — без подсветки | Не в этой волне (S7-41 «Осталось») |

Малые и большие файлы идут одним путём: цвета не зависят от размера.

### 2. Контрольные точки (`syntax::marks`)

- Фоновый проход по всему файлу (вьювер — `ByteSource`, редактор — снимок `TextSnap`) кусками по 1 МиБ, без загрузки файла в память. Не-UTF-8 — перекодирование куска в UTF-8 с картой смещений (`search::transcode`, как поиск), BOM пропускается; ISO-2022-JP (состояние декодера между кусками) — без подсветки.
- Точка — не реже чем через 64 КиБ, в месте, где состояние лексера полно (не внутри короткого токена): смещение (байт источника), состояние `St` (16 байт: режим языка и роли контейнеров верхних 64 уровней стека битами), глубина вложенности на точке и минимум глубины на куске до следующей точки. 10 ГБ → ≈ 160 тыс. точек ≈ 6 МБ.
- Глубже 64 уровней стек не хранится: роль уровня `j` восстанавливается по сводкам — последний кусок, где глубина опускалась ниже `j`, проходится заново (≤ 64 КиБ). Так у патологической вложенности (`[[[[…` на гигабайт) память не растёт.
- YAML и Markdown — свой лёгкий построчный трекер вместо лексера: состояние на точке — многострочная конструкция, в которой стоит начало строки (ограждённый код, HTML-блок 1–5; кавычки, поток `[`/`{`, блочный скаляр).

### 3. Окно

- Окно — видимые байты ± 64 КиБ (как S7-35). Лексер: от ближайшей точки ≤ начала окна до конца окна; итог — отрезки ролей (`Span`, смещения `u64`), места свёртки, «инертные зоны» (п. 4).
- **Markdown**: `S` — ближайшая «безопасная» строка ≤ начала окна, `E` — первая ≥ конца. Безопасная строка — с колонки 0, вне ограждённого кода и HTML-блока типов 1–5 верхнего уровня, и: после пустой строки (кроме `---`/`+++` — метаданные), или заголовок ATX, или пункт маркированного списка, или `1.`/`1)`. Такая строка закрывает все контейнеры и абзац выше, а начатое ею не зависит от текста выше.
- **YAML**: `S` — строка ключа или элемента списка (`- `) вне многострочного, `---`, или начало файла; отрезок `S` — до первой содержательной строки с меньшим отступом, с тем же отступом другого вида или маркера документа; разрез `E` — следующая за концом окна строка того же отступа и вида. Отрезки идут подряд, пока не покроют окно; каждый — отдельный разбор.
- Разбор `[S, E)` — тот же запрос `highlights.scm`; Markdown — строчная грамматика **по каждому узлу `inline`/ячейке таблицы отдельно** (как `MarkdownParser` крейта `tree-sitter-md`). Прежний код разбирал все абзацы одним строчным документом — код и ссылки «перетекали» между абзацами; это исправлено и для полного разбора.

### 4. Правка (редактор) и «без неточных цветов»

- Точки до правки верны; после — сдвигаются и «под вопросом». Пересчёт — от точки перед правкой вперёд, пока состояние не совпадёт со старой (сдвинутой) точкой: тогда все точки за ней снова верны (глубина хранится разностями — лишняя скобка их не портит). Обычно это один кусок (≈ 0,1 мс). Не совпало (открыли кавычку или скобку) — проход идёт до конца файла в фоне, а окно считается сразу от точки перед правкой: для него точки за правкой не нужны.
- На экране только гарантированно верное:
  - **правка внутри инертной зоны** (внутренность строки или комментария, где вставленные/удалённые байты — не кавычка, не `\`, не перевод строки и не символы конца комментария) — цвета сдвигаются: состояние лексера после зоны доказуемо то же;
  - **иначе** — отрезки до начала строки правки остаются (лексер — слева направо, роль токена задаёт его начало), YAML — до начала отрезка `S`, Markdown — до безопасной строки; от этого места до конца окна — без цвета, пока не придёт окно (единицы мс, кадр-два).
- Вьювер: окно вне посчитанного — без цвета до ответа; если проход ещё не дошёл до окна (10 ГБ, прыжок в конец), окно ждёт прохода (без цвета), состояние «Подсветка N %» видно в статусе.

### 5. Свёртка — из тех же событий структуры

Лексер и трекер выдают «открыть»/«закрыть»: скобки JSON и TOML, таблица TOML (до следующего заголовка), элемент XML, многострочные комментарий, строка, CDATA; YAML — уровень отступа строки ключа или элемента; Markdown — раздел заголовка ATX (до заголовка того же или старшего уровня) и ограждённый код. Место свёртки строки — первое открытие на ней, закрытие которого на другой строке; закрывающая строка видна, если закрытие стоит первым на ней (`}`, `</a>`, следующая таблица, закрывающая ограда), пустые строки в конце скрытого видны. Закрытие далеко ниже окна ищется по сводкам минимума глубины (без чтения файла) и проходом одного куска. Правило одно для всех размеров; для пакетных языков — прежняя свёртка по дереву.

### 6. Гарантия точности

Дифференциальные тесты (`syntax/lex/*_tests.rs`, корпус — файлы репозитория и генераторы):
1. **Лексер = tree-sitter + `highlights.scm`** для JSON, TOML, INI, XML: корпус репозитория, генераторы proptest корректных документов, перебор случайных цепочек токенов (принимаются только разобранные tree-sitter без `ERROR`/`MISSING`). Сравнение — роль каждого непробельного байта: пробел, табуляция и перевод строки цвета на экране не имеют.
2. **Отрезок = полный разбор** для YAML и Markdown: с каждой безопасной строки до каждой следующей роли совпадают с полным разбором (локальная проверка на корпусе `~/.cargo/registry`: Markdown — 2528 файлов, 29 тыс. отрезков, YAML — 969 файлов, 23 тыс. отрезков; в CI — корпус репозитория и генераторы).
3. **Окно с любой точки = проход с начала** (все языки); **точки после случайных правок = проход с нуля**; восстановление стека глубже 64 уровней = полный стек.
4. Неверный документ (ошибка синтаксиса): у лексера — свои локальные правила (описаны в модулях: незакрытая строка JSON кончается на переводе строки, как токен tree-sitter, и т. п.); у YAML/Markdown — восстановление tree-sitter в пределах отрезка. Полный разбор tree-sitter на неверном документе «истиной» не считается: его восстановление после ошибки зависит от всего файла (ошибка в начале красит конец).

### 7. Бюджеты и потоки

- Память на документ: точки ≈ 0,6 МБ на ГБ (10 ГБ — 6 МБ) + окно; дерево tree-sitter — только отрезка окна. В потолке ADR-0023 §6 (64 МиБ).
- Цвета после правки ≤ 50 мс (лексер — десятки мкс на окно, tree-sitter отрезка — единицы мс), кадр p99 ≤ 6 мс: UI-поток только сдвигает и рисует готовые отрезки; проход, окно и разбор — `Lane::Interactive` (окно) и `Lane::Bulk` (проход по файлу).
- Имена tracing-спанов — `view.syntax.*` (пространство `view.*` контракта).

## Отвергнуто

- **Полный разбор tree-sitter для малых, окна для больших** — два источника истины, цвета менялись бы на пороге; полный разбор на 16 МиБ и так вне бюджета (S7-35).
- **tree-sitter по окну без состояния** («разобрать видимое») — неточно: строка, комментарий, ключ/значение начинаются выше окна.
- **tree-sitter для JSON/TOML/XML по отрезкам** (с искусственным префиксом скобок) — внутри одного значения нет безопасной строки, а префикс — тот же лексер стека; свой лексер проще и в 100 раз быстрее.
- **Свои лексеры для YAML и Markdown** — грамматики с отступами, ленивыми продолжениями и setext-заголовками; повторить их точно дороже, чем найти безопасные строки (проверено на корпусе, п. 6).
- **Старые цвета, сдвинутые правкой, до нового окна** — могут быть неверны (открыли кавычку); показываются только там, где верны доказуемо (п. 4).

## Последствия

- Вьювер («Разметка», быстрый просмотр) и редактор красят JSON/TOML/INI/XML/YAML/Markdown любого размера; порог 16 МиБ остаётся только у пакетных языков.
- Свёртка встроенных языков — по своим правилам (п. 5): места те же для обычных документов, но у XML не сворачивается текст между тегами, у Markdown — списки и цитаты (только разделы и код).
- В Markdown строчные элементы больше не перетекают между абзацами (исправление ошибки).
- Новый язык в exe — лексер или трекер безопасных строк и дифференциальный тест.
