# Проверки — на CI, локально без дублей

(владелец, 2026-11-02) CI на каждом PR и в очереди (`.github/workflows/ci.yml`, job `test (windows)`) уже гоняет полный `cargo clippy --workspace --all-targets -D warnings`, `cargo nextest run --workspace` и doc-тесты. Локально их не дублировать.

Агент локально делает только:
- `cargo fmt --all --check`;
- `cargo check`/clippy **своего** крейта при правке;
- nextest только своих новых/изменённых тестов (`-E 'test(...)'`), пока их пишет;
- снимки `--screens` затронутых сцен dev-сборкой (CI их не делает);
- release — только для замеров по заданию.

Полные прогоны и `rdeps` — на CI; падения чинить по `gh run view <id> --log-failed`. Параллельно — не больше 2–3 агентов. Стенд (14 ядер / 15 ГБ): в `~/.cargo/config.toml` — `incremental = false`, `jobs = 6`, sccache ≤ 4 ГБ.

Заменяет «в конце волны: fmt, clippy и nextest затронутых (`rdeps`)» из решения 2026-10-24 и `CLAUDE.md`. Скилл pets-dev обновлён тем же правилом.

## Почему

- Двойная работа (локально и на CI) перегружала стенд, диск доходил до 0.
- CI всё равно обязателен (`gate`), локальный полный прогон ничего не добавляет к мержу.
