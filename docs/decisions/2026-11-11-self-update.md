# Обновление продуктов: свой механизм, общий крейт в pets

(владелец, 2026-11-11; Урфин и Postman, Postman#503) Дополняет S9 §6 (MSI, winget) и делает одно исключение из правила «ни сети в рантайме».

1. **Механизм свой и общий.** Проверка новой версии и установка — один крейт в репозитории pets, его подключают Урфин и Postman. Отдельных реализаций в продуктах нет.
2. **Проверка.** Раз в сутки и по кнопке «Проверить» программа спрашивает у GitHub Releases своего репозитория номер последнего выпуска. В запросе нет данных пользователя. Канал (стабильный или бета) — по настройке.
3. **Установка — только по согласию.** Уведомление «Вышла версия X · Установить». После согласия программа скачивает установщик (MSI, для portable — архив), проверяет подпись ключом, вшитым в программу, закрывается и ставит новую версию. Без согласия ничего не скачивается; файл с неверной подписью не запускается.
4. **Включено по умолчанию в обоих продуктах.** Выключатель — в настройках и в групповой политике (`HKLM\Software\Policies\Aahz\<продукт>`). Выключено — сетевых запросов нет, остаётся ручная кнопка.
5. **Исключение из офлайна.** Запросы модуля обновления (проверка и скачивание по согласию) — единственная сеть Урфина в рантайме по его инициативе. Телеметрии по-прежнему нет.
6. **winget остаётся** каналом для администраторов и стабильных версий (S9-22, Postman#500). Microsoft Store (MSIX) основным путём не делаем.

## Почему

- Тестировщики сидят на бета-версиях, а winget принимает только стабильные и после модерации; своя проверка работает уже сейчас.
- Один код на оба продукта — одна проверка подписи и одно место для ошибок.
- Выключенная по умолчанию проверка не работает ни у кого; закрытым сетям и администраторам хватает выключателя и политики.
- Сертификата для подписи кода нет, поэтому подлинность обновления держится на собственном ключе, а не на SmartScreen.
