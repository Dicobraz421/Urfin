# Остаток #310 принят: бюджеты нажатия в одной строке и ресайза

(владелец, 2026-11-06) Дословно: «По рекомендациям». Остаток issue #310 принят, форк gpui ради него не правим, волна по форку отклонена. «Правки gpui ради бюджета не делаем» (решение 2026-10-29) остаётся в силе, единственное исключение — быстрый путь DirectWrite ([решение 2026-11-06](2026-11-06-dwrite-fast-path.md)).

Цифры: release, стенд, CPU UI-потока, p50 / p99, мс, сборка B из `docs/perf/s7.md`, «Хвосты #310». Общий бюджет кадра 3 / 6 ([решение 2026-10-29](2026-10-29-frame-budget.md)) для остального не меняется.

| Что | Бюджет был | Бюджет теперь | Замер |
|---|---|---|---|
| Нажатие в файле в одну строку | 3 / 6 | **3,5 / 7** | 3,0–3,4 / 4,3–6,3 |
| Ресайз панелей | 3 / 6 | **9 / 12** | 6,8–8,6 / 10,3–11,1 |

Первый экран вьювера на файлах от 50 МБ: бюджет 50 мс остаётся целью, известное отступление — 19–88 мс, один прогон 285 мс.

Почему:

- Нажатие: весь экран сдвигается на колонку и рисуется заново, остаток — глифы gpui.
- Ресайз: 66 % времени — `ResizeBuffers` в драйвере, шейпинг и раскладка — единицы процентов. Без правки форка не сдвинуть.
- Первый экран: ожидание внутри `DirectXRenderer::render`, на условной переменной драйвера, CPU нет. Есть в обеих сборках и не зависит от числа потоков индекса.
