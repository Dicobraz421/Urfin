# Быстрый путь DirectWrite в форке gpui; смена всего экрана — p99 ≤ 8 мс

(владелец, 2026-11-06) Дословно: «Правку включить». Условия, принятые им же: перемер на датасетах `docs/perf/s7.md` перед мержем, разбор разницы в пике памяти панели, Segoe UI не дорабатываем, ядро `gpui-pre` не форкаем.

Быстрый путь `layout_line` из `pets-gpui-windows` включён в Урфин. Это единственное исключение из «правки gpui ради бюджета не делаем» (решение 2026-10-29): запрет остаётся для всего остального. Правка живёт в форке Windows-платформы, ядро `gpui-pre` не тронуто.

Бюджет полной смены экрана снижен с p99 ≤ 12 мс ([решение 2026-11-05](2026-11-05-fullscreen-frame-budget.md)) до **p99 ≤ 8 мс**: страница и прыжок в документах со строками (логи, текст, Markdown). Остальные бюджеты кадра не меняются. Строка на весь файл (JSON в одну строку) в этот бюджет не укладывается, как и раньше: там время не в шейпинге, A и B равны, p99 прыжка 14–20 мс (`docs/perf/s7.md`, «Что не укладывается»).

Цифры: release, стенд, CPU UI-потока, p50 / p99, мс. A — main, B — быстрый путь; таблица по всем файлам — `docs/perf/s7.md`.

| Что | A | B |
|---|---|---|
| Редактор 10 ГБ, страница | 3,1–3,3 / 4,0–4,8 | 1,9–2,2 / 2,5–3,2 |
| Редактор 10 ГБ, прыжок | 2,6–3,5 / 4,3–4,8 | 2,3–2,5 / 2,8–3,5 |
| Редактор 10 ГБ, прыжок, 6 ядер заняты, медиана p99 | 10,9 | 7,2 |
| Вьювер 10 ГБ, страница, медиана | 3,7 / 6,6 | 2,3 / 3,9 |
| Редактор 10 ГБ, нажатие | 2,3–2,4 / 3,3–3,9 | 2,1–2,3 / 3,0–3,6 |

Почему 8: на тихом стенде худший p99 B на документах со строками — 7,3 мс (README с предпросмотром), на логах — до 5,6 мс; разовые всплески до 13 мс есть в обеих сборках. При шести занятых ядрах медиана p99 B — до 8,5 мс.

Память: своей памяти правка добавляет не больше 0,25 МБ. Верхняя мода пика панели (+12,8 МБ) — пул write-combined драйвера Intel, она есть и в main; разбор — `docs/perf/s7.md`.
