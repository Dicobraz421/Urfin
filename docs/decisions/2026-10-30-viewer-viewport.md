# Видимая область вьювера: событие `InboxMsg::Viewport`

(владелец, 2026-10-30, класс B) UI передаёт ядру окно текста вьювера событием `InboxMsg::Viewport { doc, cols, rows }` через `ViewInbox` (колонки и строки окна). UI шлёт его при открытии документа, при ресайзе, смене режима и размера шрифта; handler хранит размер в `ViewerDoc` (`view_cols`, `view_rows`).

По этому размеру handler `viewer` сам: прокручивает (`viewer.scroll` — строки, страницы, начало и конец, горизонталь; в Hex — по `hex_cols`), выводит найденное на треть экрана (`reveal`), выбирает `hex_cols = auto` по ширине и просит у `PageCache` видимые страницы (`want` + `pump`) — в handler и `Msg`, не в кадре UI.

Почему: размер окна — состояние документа, а не аргумент каждой команды; поиск (`reveal`), загрузка страниц и восстановление позиции идут без команды от UI и тоже должны знать окно. Событие идёт тем же каналом UI → handler, что и события редактора (решение 2026-10-30 №1), без записи в журнал команд.

Отвергнуто: аргументы `cols`/`rows` у `viewer.scroll` — их нужно передавать в каждую команду (клавиши keymap их не знают), а `reveal` и подгрузка страниц после `PagesMsg` остались бы без размера окна.
