# Ответ на вопрос выхода — handler'у, наложившему вето

(владелец, 2026-10-31) Ответ на вопрос выхода (`QuitDecision::Veto`) получает handler, который этот вопрос задал: `Handler::on_quit_reply(&mut self, choice, cx) -> QuitReply { Quit, Stay }`. По умолчанию — `Quit` на `choice = "quit"`, иначе `Stay`, поэтому прежние вето (ops, term, net) работают как раньше. `Quit` — core опрашивает handlers после этого (следующее вето — свой вопрос), никого — выход с отменой задач; `Stay` — остаёмся. Долгое действие handler делает сам и по готовности снова шлёт `app.quit` (опрос с начала). Отмена вопроса (Esc) handler'у не приходит.

Редактор (S7 §5.4): «Не сохранено: N [Сохранить все] [Не сохранять] [Отмена]». «Сохранить все» — снимки документов с правками тем же путём, что `editor.save_all`; все сохранены — `app.quit`; вопрос документа («изменён на диске», кодировка, «только чтение»), ошибка записи или не-локальный файл — выход отменён (тост).

Почему метод, а не команда `{ns}.quit_reply`: команду пришлось бы регистрировать в каждом namespace с вето (палитра, `COMMANDS.md`, keymap), а core и так держит вопрос выхода и знает, чей он. Класс B (контракт core «Выход»).
