# Досчёт с правами администратора — тот же `urfin.exe` через UAC

(владелец, 2026-11-02, F01-12) Принимает [ADR-0021](../adr/0021-du-elevated-helper.md) в изменённом виде; заменяет в F01 §8 «ADR-0021: отдельный помощник, подпись кода обязательна».

1. **Не отдельный помощник, а тот же `urfin.exe`** — как choco в F02-06 (S0 v6 №17): `urfin.exe --du-elevated --out <файл> <корень>…` запускается через `ShellExecuteExW`, verb `runas`, считает размеры недоступных папок (только чтение метаданных), пишет один файл результата и выходит. Без нового крейта и бинаря, без именованного канала.
2. **Подпись кода не требуется.** UAC покажет «неизвестный издатель» — принято.
3. **Безопасность режима.** Параметры — только путь файла результата и корни. Режим не делает ничего, кроме чтения метаданных и записи одного файла. Файл — в каталоге состояния Урфина (`state\du\elevated\`), не в общем `%TEMP%`; обычный процесс проверяет формат, версию, nonce и что пути — из запрошенных корней. Отказ в UAC — понятное сообщение, снимок не меняется; отмена — повышенный процесс завершается.
4. **Политики** `DuElevatedHelper` / `DuElevatedMft` (ADR-0020) остаются: `DuElevatedHelper` = 0 — кнопка с замком, повышенный режим сам перечитывает политику и отказывает.

## Почему

- Отдельный бинарь, канал с DACL и проверкой подписи — много кода и сертификат ради чтения размеров нескольких папок; тот же exe уже умеет обход (`urfin_vfs::du::scan`).
- Повышенный процесс выходит до конфига, логов и GPUI: ни окна, ни терминала, ни операций записи — только обход и один файл.

## Следствия

- Остаточный риск: portable-копия в каталоге, доступном пользователю на запись, — подмена `urfin.exe` или DLL рядом с ним до согласия в UAC. UAC показывает путь и «неизвестный издатель»; закрывается подписью дистрибутива, если она появится.
- В снимок попадают итоги недоступной папки (размер, файлы, каталоги, суммы по типам), имён внутри нет — ни в памяти обычного процесса, ни в кэше.
