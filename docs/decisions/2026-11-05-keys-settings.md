# Раздел «Клавиатура»: список клавиш и правка из интерфейса

(владелец, 2026-11-05) Дословно: «конечно Б. и описание как их поменять. из интерфейса было бы максимально удобно, со внесением в файл». Вариант Б — таблица всех привязок вместо одного переключателя пресета. Макет `screen-settings-keys.png` — правда.

- Таблица: команды реестра и действующая раскладка (пресет + `keymaps/user.toml`), поиск по команде или клавише, колонка «Где», команды без клавиши тоже видны. Без строки остаются только команды, которые клавишей не вызвать (обязательный аргумент) и служебные.
- Правка из интерфейса: захват сочетания, добавить, заменить, снять, сброс строки и всего файла к пресету. Запись — в `keymaps/user.toml` атомарно, через `toml_edit`: комментарии и порядок остаются; затем `keymap.reload`. Рядом — короткое описание и «Открыть user.toml» для ручной правки; при входе в раздел файл перечитывается.
- Конфликт — только в пересекающихся контекстах (клавиша панелей не мешает просмотру); по макету: строка `header` и пояснение `context_remote` под командой, перед заменой — подтверждение.

## Поправка владельца: ничего не запрещать

(владелец, 2026-11-05, в ходе волны; отменяет запрет из постановки) Дословно: «не надо ничего запрещать, надо пояснение сделать!».

- Сочетания `Ctrl+Alt+буква` и AltGr назначаются из интерфейса свободно: при назначении — пояснение (на некоторых раскладках AltGr = Ctrl+Alt, символ может перестать набираться). Запись не блокируется, отдельного подтверждения не требует. То же для сочетаний, которые может перехватить Windows: пояснение «до Urfin может не дойти».
- `key_risk` (бывший запрет) — только повод для пояснения. Загрузка `user.toml` такую привязку принимает и не отбрасывает; она срабатывает как обычная. Предупреждение остаётся в `Keymap::warnings` и журнале, но баннера для пользовательского слоя нет: человек уже видел пояснение.
- Для встроенных пресетов проверка остаётся: это контроль разработчика (тест `known_commands`), исключения — №88.
