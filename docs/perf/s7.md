# S7 — замеры вьювера и редактора

## S7-16: размер для редактора (`EditorState` gpui-kit)

Стенд владельца, 2026-10-31/11-01. Замер — `urfin.exe --bench-editor <файл>` (флаг приложения, лимит снят только в памяти): файл открывается в редакторе, фича `Editor` меряет передачу текста в `EditorState`, пиковую private-память, 120 кадров прокрутки страницей, 300 нажатий (правка `insert` через API `EditorState`, не синтетический ввод) и 40 прыжков в случайное место. Текст — строки кода по 40 символов (25,5 тыс. строк на МБ), LF.

Сборка — **dev** (`opt-level = 2` у зависимостей: gpui, gpui-kit, ropey — как в release; свой код без оптимизаций). Release-замер не сделан: на диске C: 3 ГБ свободно (нужно ≥ 15 ГБ) — повторить командой ниже, когда место будет.

«Кадр» — CPU UI-потока между кадрами (правка + сборка дерева + раскладка + отрисовка). Разброс 1,2–5 мс между прогонами — от нагрузки стенда (рядом шли сборки), не от размера: кадр от размера файла не зависит.

**Итог:** `editor.max_size_mb = 16`.

- `set_value` gpui-kit линеен: ≈ 15 мс на МБ на UI-потоке (строка → Rope, второй Rope в карте отображения, карта строк). 16 МБ — ≈ 0,25 с без отклика, 64 МБ — ≈ 1 с, 256 МБ — 4 с. Перевод Rope → строка — в фоне.
- Память — ≈ 9 МБ на мебибайт текста (бюджет §5.5 — 1,3×): 16 МБ — ≈ 140 МБ, 64 МБ — ≈ 600 МБ.
- Нажатие и прокрутка — в бюджете кадра на любом размере (p99 ≤ 6 мс в прогонах с тихим стендом); размер их не ограничивает.
- Поднять лимит можно только изменением в gpui-kit: приём готового `Rope` без строки и построение карты строк вне UI-потока (вопрос к pets / gpui-kit, не к Урфину).

Повторить (release, по одному файлу на запуск):

```
cargo build --release -p urfin-app
target\release\urfin.exe --bench-editor <файл>
```
