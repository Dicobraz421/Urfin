### #345: F3 и F6

Первый замер S8-13 (тот же стенд, бенч в одном процессе): F3 272 мс против 87,5 мс у `rg` — 3,1×, без регистра 3,8×, кириллица 3,3–3,8×; F6 страница p50 3,23–3,98, строка 2,94–3,51, прыжок 2,89–4,10.

**Методика.** Разница «в 1,7× при равных 4 потоках» оказалась не в работе на файл. Windows через 10–20 с понижает приоритет (QoS) фоновому процессу без окна: тот же поиск в процессе, проспавшем 25 с, — 117–127 мс, в свежем — 74–80 мс; `rg` запускается заново на каждый прогон и понижения не получает. Чтение файлов, привязанное к одному ядру (`start /affinity`), — вровень с `rg`: P-ядро 631 против 628 мс, E-ядро 1335 против 1245 мс (1 поток, весь `src`). Поэтому `search_bench run` теперь зовёт себя (`part`) на каждый сценарий и каждый запрос F3/F4. Окно Урфина на переднем плане такого понижения не получает; в свёрнутом окне поиск, по всей видимости, замедлится так же — это поведение ОС.

**F3.** Поиск по содержимому на локальном SSD читает в min(ядра, 12) потоков вместо 4 (`walk.rs`, `CONTENT_THREADS`; столько же по умолчанию у `rg`). HDD (1 поток), сеть, `[search] threads` и поиск по имени — как у обхода (`volume::walk_threads`, решение №6): du и листинг не тронуты. Голова файла (BOM UTF-16) читается только в режиме «все кодировки» — минус одно чтение на файл. При равных 4 потоках (`--threads 4`) Урфин — 137–168 мс, `rg -j4` — 149 мс в S8-13 (207–232 мс со временем запуска процесса из bash).

**F6.** Профиль `URFIN_PROF` (release thin LTO с символами) и выключение частей кадра по одной: строки списка — 0,6–1,3 мс кадра, форма — 0,3–0,6, предпросмотр — до 0,35, заголовок, низ, итог — по ~0,1; без всего этого кадр — 1,0–1,2 мс. Правки:

- кэш строк списка: строка стора не меняется (стор только дописывается), поэтому строка, что была на экране в прошлом кадре, не шейпится и не обрезается заново; обе раскраски (с курсором и без) — в одной записи;
- номера `:N` — свой кэш до 1024 штук (на новой странице они повторяются);
- фрагмент моноширинным шрифтом сначала обрезается, затем шейпится: один вызов DirectWrite вместо двух;
- форма — своя view: в списке кадр берёт её из кэша gpui, как части панели; с фокусом в поле — рисует заново. Высота места — с прошлого кадра формы.

Снимки сцен поиска (`--screens`, dev) совпадают с main попиксельно. A/B вперемежку, 4 пары, fat LTO; A — main с правкой поиска, B — с правками кадра; UI-поток на кадр p50 / p99, мс:

| Фаза | A | B |
|---|---|---|
| Строка | 3,41–3,59 / 4,67–4,96 | **2,80–3,01 / 3,86–4,07** |
| Страница | 3,79–4,05 / 4,87–5,46 | 3,45–3,54 / 4,79–5,32 |
| Прыжок | 3,95–4,16 / 5,31–5,74 | 3,52–3,64 / 4,26–5,06 |

Страница и прыжок меняют весь экран: все строки новые, их шейпинг (DirectWrite) и отрисовка глифов gpui — основное время, кэшу тут нечего взять. По [решению 2026-11-05](../decisions/2026-11-05-fullscreen-frame-budget.md) смена всего экрана — p99 ≤ 12 мс, и это выполнено; p50 ≤ 3 мс по нему остаётся для построчной прокрутки, нажатия и стационарного кадра — строка в бюджете. Сжать p50 страницы до 3 мс без правки gpui (её решение 2026-11-05 пока запрещает) не видно; нужен ли p50 ≤ 3 и для смены экрана — вопрос владельцу в #345.

### Не мерилось

Far 3.0 и Проводник через GUI не гоняются (синтетический ввод запрещён) — ручной замер владельца:

1. Корпус: `cargo run -p urfin-search --example search_bench --release -- gen <каталог>`.
2. Far: панель на `<каталог>`, Alt+F7, маска `*.rs`, текст пусто, «Искать в подкаталогах»; секундомер от Enter до «Поиск завершён». Затем текст `XyzzyNeedle` на `<каталог>\src`. Первый прогон — прогрев, записать медиану трёх.
3. Проводник: открыть `<каталог>`, в поле поиска `*.rs`; от Enter до остановки зелёной полосы в адресной строке. Без индекса (папка вне индексируемых) — это и есть базлайн.
4. Урфин: Alt+F7 с тем же запросом, время — «готово за X с» в статусе экрана.

### Как повторить

```
cargo build --release -p urfin-search -p urfin-app --example search_bench --bin urfin
target\release\examples\search_bench.exe gen <каталог>
target\release\examples\search_bench.exe run <каталог> --runs 5 --rg <rg.exe> [--fd <fd.exe>] [--threads N] --json run.json
urfin.exe --bench-search            # F6, в переносной копии (urfin.portable)
set URFIN_PROF=prof.txt& set URFIN_PROF_PHASE=line& urfin.exe --bench-search   # профиль фазы строки
```
