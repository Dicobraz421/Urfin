# Бенч файловых операций (S5 §7, S5-25)

Харнесс — игнорируемый тест `bench_ops` (`crates/ops/src/ops/bench_ops.rs`): сценарии §7 на
датасетах с фиксированными сидами против Проводника (Shell `IFileOperation`, тот же движок),
robocopy и `rd /s /q`; прогоны чередуют инструменты. Вместо `xtask` и hyperfine — тест на
движке напрямую (без Cargo-воркспейса и внешних утилит). Таблица дописывается в файл
`URFIN_BENCH_OUT`; переменные — в шапке модуля.

```
cargo nextest run --release -p urfin-ops bench_ops --run-ignored only --no-capture
```

## Стенд

Ноутбук владельца: Intel Core Ultra 5 225H, 15,2 ГБ RAM, NVMe WD PC SN5000S 512 ГБ (QLC,
свободно ~60 ГБ), NTFS, Windows 11 Pro 26300; Defender — защита в реальном времени, штатный
режим. Один том: сценарии «между томами», ReFS / Dev Drive, HDD, SMB на стенде не воспроизводятся.
Кэш горячий: сброс (`RAMMap -Et`) требует прав администратора.

Разброс (CV) — 10–30 % (у Explorer на B2 — 4 %): Defender сканирует новые файлы, SLC-кэш
QLC-накопителя то есть, то нет, ноутбук троттлит. Приёмка «разброс <5 %» на этом стенде не
выполняется; медиана устойчивее среднего, для A/B брать один сеанс.

Что видно:

- **#9 нашёл дефект:** удаление шло через крейт `remove_dir_all` — 20 с на 2000 файлов против
  0,4 с у `rd`. Заменено на `std::fs::remove_dir_all` (POSIX-удаление, read-only снимается
  флагом): теперь быстрее `rd`, но не в 1,5 раза — следующий шаг S5-09, параллель по каталогам.
- **#5:** Explorer быстрее на 2 ГиБ, потому что не ждёт сброса на диск: 2 ГиБ ложатся в кэш ОС.
  Urfin (как robocopy /J) завершается после `FlushFileBuffers`. Скорость Urfin — потолок
  записи QLC без SLC-кэша (~100 МиБ/с, см. `s5-16-large-files.md`).
- **#3, Explorer:** 53 файла/с — `IFileOperation` из потока теста (STA без UI). Ручной
  контроль секундомером — `docs/manual-tests/S5-25.md`.
- **#7:** ~70 мс и у Urfin (job, обход, rename корня), и у `cmd /c move` (запуск процесса);
  один `MoveFileExW` — доли миллисекунды. Порог 50 мс — к старту job (S5-04).

Не измерено на стенде: #1–#2 (ReFS, Dev Drive — создание тома меняет систему), #4 (HDD),
#8 (второй том), #10 (корзина владельца — его данные), #11 (SMB), #15 (сравнение в Urfin —
по листингу панели, рекурсивного нет), FAR (ручной ×3, `docs/manual-tests/S5-25.md`).
