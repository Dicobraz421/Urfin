# Терминал: перф и e2e (S6-22)

Сводка замеров терминала. Подробности по этапам — `s6-04-pipeline.md` (разбор
вывода), `s6-06-grid.md` (рендер сетки).

Стенд владельца: Intel Core Ultra 5 225H (гибрид P/E/LP E), Windows 11, release.
Бенчи — exe с affinity на P-ядра (`ProcessorAffinity = 0x3`, `AboveNormal`).
2026-10-26.

## criterion

`cargo bench -p urfin-term --bench pipeline`

| Бенч | Результат | Бюджет |
|---|---:|---|
| `parse/yes_16mb_bare_alacritty` (голый эмулятор) | 99–102 МиБ/с | — (потолок) |
| `parse/yes_16mb` (pipeline Urfin) | 92–93 МиБ/с | ≥ 100 МБ/с (S6-04) |
| `parse/ls_color_16mb` | 80–84 МиБ/с | — |
| `grid/snapshot_200x60` | 0,096 мс | доля кадра ≤ 2 мс (S6 §2) |
| `cmdline/history_filter_5000` | 0,046 мс | < 1 мс (S6-16) |
| `cmdline/complete_10k_files` | 0,25 мс | < 30 мс (S6-17) |

Pipeline упирается в эмулятор (`Term`: перевод строки и скролл), накладные
расходы — 6–9 % при разбросе стенда ±5 %. Найдено в S6-22: автомат
win32-input-mode (S6-20) и пре-сканер OSC шли по выводу байт за байтом — это
стоило ~12 %. Теперь оба прыгают к следующему `ESC`: было 89, стало 92–93 МиБ/с.

Рендер сетки (полная пересборка 200×60 каждый кадр) — `s6-06-grid.md`:
p50 1,63 мс, p99 2,47 мс при бюджете ≤ 4 мс.

## e2e

`cargo run --release -p urfin-term --example term_e2e` — настоящий `cmd.exe` в
системном ConPTY, сетка 200×60, скроллбэк 10 000.

| Сценарий | Результат | Бюджет |
|---|---:|---|
| Память Urfin на сеанс до вывода (private bytes, 3 сеанса) | 7,45 МиБ | ≤ 10 МБ |
| CPU Urfin в простое, 3 сеанса, 10 с | 0 мс (0 %) | 0 % |
| `type` 100 МиБ | 89,7 с (1,1 МиБ/с), CPU Urfin 6,3 с | — |
| `dir /s C:\Windows` | 167 с, CPU Urfin 4,8 с | — |
| `dir /s C:\Windows > NUL` без терминала | 51 с | — |

Поток упирается в системный ConPTY (conhost), а не в Urfin. Голый ConPTY без
эмулятора и сетки (тот же `type`, 20 МиБ, только чтение pipe) даёт 1,26 МиБ/с —
столько же, сколько с pipeline Urfin. Urfin при этом занят 5–7 % времени.
Ускорение — свой ConPTY рядом с exe (S6-02b, решение S6 §12 №3): OpenConsole
быстрее отдаёт вывод.

hyperfine на стенде нет: время сценариев меряет сам пример (`Instant` от
запуска до `Exited`).

## Память и CPU

- Сеанс до вывода: сетка 200×60, потоки reader и writer, каналы — 7,45 МиБ.
  Скроллбэк растёт с выводом (10 000 строк × 200 колонок — до ~50 МиБ на
  сеанс при полном буфере).
- Простой: reader спит в `ReadFile`, writer — в `recv` без таймаута, сервер
  комплита pwsh (S6-18) — в `recv_timeout` 10 мин, потом закрывается.
