# Urfin — архитектура (ведёт S0 «Джарвис»)

Обновлено 2026-10-30 (по факту в `main`).

## Решения (ADR-0)
- Rust stable (edition 2024). UI — **GPUI** через gpui-kit (снимок Zed `gpui-pre`, версия зафиксирована; [ADR-0018](adr/0018-ui-gpui.md)). Оконная платформа Windows — свой патченный `gpui-pre-windows` из репозитория pets: кадры по запросу (0 % CPU в простое), живой ресайз, шейдеры байткодом в exe, `GPUI_FORCE_WARP=1`. egui/eframe/wgpu удалены (G-06).
- Платформа: **только Windows 10/11** (S0-decisions №57). Linux и macOS не собираются и не проверяются.
- Лицензия: **MIT OR Apache-2.0** (стандарт Rust-экосистемы).
- Ноль модальных окон. Все «диалоги» — inline-строки над cmdline или в панели. UI-поток не делает I/O.
- «Перекрыть системные» = свои алгоритмически быстрые реализации операций (каталог — S5). Системные хоткеи ОС не перехватываем.
- Хоткеи: пресеты DN и Far, пользовательский keymap; хоткеи с буквой — на любой раскладке (S0-contracts-v4 №5).
- Офлайн: никаких сетевых запросов в рантайме, телеметрии, CDN. Ресурсы вшиты (кроме системных шрифтов Segoe).

## Крейты (`crates/*`, пакеты `urfin-*`)
| Крейт | Ответственность | Зависит |
|---|---|---|
| core | AppState (панели, табы, выделение, история), Command bus, события, job registry, Runtime (полосы Interactive/Bulk), политики организации `PolicySet` (F-00) | — |
| vfs | trait Vfs, локальный бэкенд с быстрыми путями Windows, watcher, сортировка, тома; модель анализа места `du` (F-01) | core |
| ops | движок операций, очередь, прогресс, конфликты, журнал, Корзина | vfs |
| term | ConPTY, VT-эмуляция (`alacritty_terminal`), shells и их интеграция, сеансы, строка ввода | core |
| keymap | реестр команд → сочетания, пресеты, конфиг, хук клавиш Windows | core |
| i18n | Fluent EN/RU | — |
| ui | окно и виджеты GPUI, темы, сцены `--screens`, `--bench` | все выше |
| net | SSH и SFTP (F-03): tokio current-thread на выделенном потоке, профили, импорт `~/.ssh/config` и PuTTY | core |
| pkg | менеджеры пакетов winget / scoop / choco (F-02) | core |
| view | вьювер/hex/редактор (M4) | vfs |
| search, arc | поиск и архивы (M5) | vfs |
| app | бинарь `urfin.exe`, старт, сессия, один экземпляр | все |
| testdata | генераторы датасетов для тестов и бенчей (только dev) | — |

## Потоки
- UI: GPUI, события Core — через `MsgSink`/`poke`, кадр только по событию или анимации.
- Runtime core: полосы Interactive (листинг, запуск shell) и Bulk (операции, запись на диск), rayon — сортировка, хэши, поиск; `spawn_dedicated` — долгие задачи.
- term: поток-читатель и поток-писатель на каждый сеанс ConPTY.
- Любое действие пользователя → `Command` → bus → handler. UI только рисует снапшот состояния.
- Отмена: токен в каждой задаче. Прогресс: атомики + троттлинг событий ≤30/с.

## Бюджеты (S0-decisions №80; кадр — решение 2026-10-29)
- Первый кадр < 250 мс (своё время старта < 20 мс); каталог 100k записей < 200 мс (первые строки < 16 мс, стриминг).
- Кадр p50 ≤ 3 мс, p99 ≤ 6 мс при 100k строк (виртуализация; решение 2026-10-29 — цена кадра GPUI), ввод ≤ 1 кадр; сетка терминала 200×60 — полная пересборка ≤ 4 мс.
- Простой: 0 % CPU, своя память < 50 МБ, процесс ≤ 200 МБ private. Бинарь ≤ 30 МБ (растёт вместе с функциями, №80).

## Платформенный слой
Модули `sys` внутри vfs, ops, term, ui, view, app (Win32 через `windows-sys`). `unsafe` — только в `sys`.

## Конвенции
- Ошибки: thiserror в либах, anyhow в app. Логи: tracing.
- Тесты: cargo-nextest; бенчи: criterion, `urfin --bench` (кадр), `bench_ops` (операции, [perf/ops.md](perf/ops.md)).
- Clippy pedantic = warn (в CI `-D warnings`), rustfmt по умолчанию.
- Процесс pets-dev ([решение 2026-10-24](decisions/2026-10-24-pets-dev.md)): полосы — `lanes.toml`, одна волна = одна полоса = один PR; межполосные правки — ветка `x/*`; мерж — очередь GitHub на зелёном `gate`.
- Документы в репо: `docs/specs/Sx.md`, `docs/adr/NNNN-*.md`, решения `docs/decisions/`, контракты `docs/CONTRACTS.md`, карточки задач `docs/tasks/<ID>.md`, ручные проверки `docs/manual-tests/<ID>.md`.

## Стенд
Windows 11 владельца, сборка нативно (MSVC). Проверка лестницей: L0 на стенде (fmt, clippy, nextest, release) → L1 CI (только windows) → L2 ручная приёмка владельцем (метка `win-manual`). Перф-бюджеты меряются на стенде в release. WSL Ubuntu — только для проверки интеграции shell в WSL.
