# F03-21 — Слежение за файлом по SFTP (`viewer.follow`)

Статус: ⏳ (2026-11-12, PR w/net-tails)

Стенд Windows 11 и настоящий SSH-сервер (OpenSSH, SFTP; Linux) с профилем в Урфине; второй сеанс к серверу (PuTTY или `ssh`) — писать в файл «со стороны». В панели — `sftp://<профиль>/tmp`. Автотест `follow_sees_append_and_truncate` (`crates/net/tests/sftp.rs`) проверяет то же на `testsrv`; здесь — живая сеть и настоящий сервер.

| № | Действие | Ожидание |
|---|---|---|
| F0321.1 | Во втором сеансе: `seq 1 1000 > /tmp/follow.log`. В Урфине F3 на `follow.log`, Shift+F | В шапке чип «Слежение»; вьювер в конце файла (строка 1000) |
| F0321.2 | Во втором сеансе: `for i in $(seq 1001 1100); do echo $i >> /tmp/follow.log; sleep 0.2; done` | Новые строки появляются по ходу записи, без заметной задержки (≤ 0,5 с после записи), вид прилипает к концу; кадры не дёргаются |
| F0321.3 | Прокрутить вверх (PgUp) во время записи, затем End | Вверху вид не прыгает к концу; End — снова в конце и прилипает |
| F0321.4 | Во втором сеансе: `: > /tmp/follow.log; echo after-truncate >> /tmp/follow.log` | Вьювер показывает одну строку `after-truncate` (файл усечён); старые строки не остаются |
| F0321.5 | Во втором сеансе: длинная запись `head -c 5M /dev/urandom \| base64 >> /tmp/follow.log` | Хвост дочитывается, статус размера растёт до ≈6,8 МБ; Урфин отвечает на клавиши во время дочитки |
| F0321.6 | Оставить слежение открытым на 1 мин без записи; на сервере `sudo tcpdump -i any port 22 -c 1000 -w /tmp/f.pcap` (или журнал sftp-server `-l DEBUG3`) | В простое — только запросы опроса, около 4 в секунду (один `STAT` на шаг); CPU Урфина ≈ 0 % в Диспетчере задач |
| F0321.7 | Во втором сеансе: `sudo systemctl restart sshd` во время слежения, затем дописать строку | Связь — «ждёт связи» и переподключение по F03-06; после него новая строка видна (если нет — записать, что слежение не возобновилось) |
| F0321.8 | Shift+F ещё раз | Чип «Слежение» пропал; дозапись во втором сеансе больше не видна до повторного Shift+F |
