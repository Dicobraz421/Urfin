# F03-09 — SSH-терминал и пара «панель + терминал»

Статус: ⏳ (2026-11-03, PR x/term-ssh)

Стенд Windows 11 с OpenSSH-клиентом ≥ 8.9 (`ssh -V`) и тестовым сервером (bash). Снимок `screen-sshpair` (`--screens`) сверен с макетом; здесь — живое поведение.

| № | Действие | Ожидание |
|---|---|---|
| F0309.1 | «Подключения», профиль с паролем, Shift+Enter | Пароль спрашивается один раз (строка `screen-sshpass`); справа — панель `sftp://`, под ней терминал «ssh srv1 ▾», фокус в терминале, вопросов в самом терминале нет |
| F0309.2 | Профиль с ключом из менеджера паролей (команда отдаёт PEM), Shift+Enter | Терминал входит без вопросов; статус «ssh.exe · ключ ed25519 из агента»; ключ не появляется на диске |
| F0309.3 | Новый сервер («Только в этот раз»), затем Shift+Enter | `ssh.exe` не спрашивает о ключе сервера |
| F0309.4 | В терминале `cd /var/log` (bash с OSC 7: `PROMPT_COMMAND='printf "\e]7;file://%s%s\a" "$HOSTNAME" "$PWD"'`) | Панель переходит в `/var/log`; статус «папка: /var/log ↔ панель» |
| F0309.5 | Сервер без OSC 7 | Через ~5 с в статусе «папка: сервер не сообщает» |
| F0309.6 | Ctrl+Tab несколько раз | Фокус панель ↔ терминал; в keybar «Ctrl+Tab Панель ↔ терминал»; в панели Ctrl+Tab не листает табы; во вкладке анализа места Ctrl+Tab — по-прежнему карта |
| F0309.7 | Панель пары в другую папку, «ssh srv1 ▾» → «Перейти в терминале сюда» | В терминале `cd -- '<папка>'`, набранная строка стёрта |
| F0309.8 | В терминале `exit 3` | «[соединение закрыто, код 3]», «Enter — переподключить»; Enter — новый вход без вопроса пароля |
| F0309.9 | «ssh srv1 ▾» → «Новый сеанс», затем выбрать сеанс 1 | Второй `ssh.exe`; меню — «ssh srv1 · 1/2», выбранный показан в паре |
| F0309.10 | В терминале `htop`/`vim` | TUI внутри пары, панели не прячутся; размер — по области пары |
| F0309.11 | Ctrl+O в терминале пары и обратно | Терминал на всё окно; Ctrl+O — пара на месте, фокус в терминале |
| F0309.12 | OpenSSH < 8.9 (или переименовать ssh.exe) | Тост «обновите OpenSSH» / «Не найден ssh.exe»; пароль — в самом терминале |
